状态：2026-11-02 用户已确认 Q1–Q3 均按推荐执行，并要求更新规格、重新拆票及清理旧票。本文替换原四组菜单和 R1–R8 草案，是当前实施依据。规格发布不代表代码、部署或真实业务验收已完成。

GitHub：[规格 #150](https://github.com/brycezhang/timenook/issues/150)；实施票及清理结果见[实施清单](admin-vben-refactor-tickets.md)。

## 问题与结果

现有后台以配置、运行状态及独立工单为入口，通过按钮变量切页，缺少便于日常人工处理的订单和用户列表。运营需要先找到具体的人或单，再完成退款、资料服务及生产履约；本轮把后台精简为三个一级菜单，登录默认进入订单管理。

| 菜单 | 查询与详情 | 人工操作 |
| --- | --- | --- |
| 订单管理 | 订单号、购买人、讲述者/项目、价格与实付、付款/退款状态、待处理事项、关联生产单 | 添加内部备注；处理已有退款/质量售后申请；进入关联生产单 |
| 用户管理 | 产品账号、关联讲述者、项目、订单及服务申请；无支付订单的内部验收项目也可查到 | 添加内部备注；核验处理换绑、资料导出、主动撤回/删除及必要纠正申请 |
| 生产单管理 | 原订单、讲述者/书名、确定 PDF、生产进度、地址/物流及异常 | 审核制作条件、获授权下载 PDF/地址、线下交接、登记完成印制/发货/交付、处理取消及原单重印 |

三个列表均有搜索、适用筛选、稳定分页和待处理筛选；复杂详情有独立 URL，可刷新、前进后退并返回原查询位置。独立客服工单菜单取消，实际申请通过关联详情处理。申请没有购买订单时，仍能从用户/项目进入，列表待处理结果不能遗漏它。

## 实现决策

### 应用组织与查询

参考 wutong-admin 的 Vben web-antd 路线，实际使用认证布局、主布局、菜单、面包屑、多标签页和通用页面/表单/弹层，统一 Ant Design 表格适配；不为名称强制更换整套表格。保留框架来源和许可证。旧配置/运维/工单导航退出当前应用；只有订单、用户、生产单三个一级入口，详情不额外生成一级菜单。

飞书登录沿用服务端保密客户端、白名单、独立管理员权限、HttpOnly/Secure Cookie、CSRF、限流与审计。回跳只接受本应用允许的路径；嵌套 URL、静态服务回退、同源 API 及 Cookie 路径一起验证。无权限入口按可访问业务页回退；直接 URL/请求仍由服务端鉴权。

管理员列表由受保护的管理查询提供，覆盖历史记录，服务端执行搜索/过滤、稳定排序、页长上限及分页。支持实际已取得的账号编号、订单号、项目/讲述者信息；不假设账号已有昵称或手机号。不得用“最近 50/100 条”替代全量检索。备注采用最小追加记录，保留操作人/时间并审计。

产品账号、讲述者与项目内参与身份分别表达。无个人账号的讲述者通过项目查询；无支付订单的项目显示其实际内测来源，不伪造付款或生产权益。实施前核对最新已合入主分支与实际装配，消费已有登录、普通商户、固定套餐和内部验收契约，避免在过时 checkout 重建已交付能力。

多标签仅保存必要路由元数据；私人资料和授权不持久化到浏览器。私密详情退出、切换或授权失效后停止活动访问并清理，晚到响应不能填回已失效页面。服务器仍需重验当下权限和确定版本。

### 订单与服务申请

订单指购买记录，生产单指确定书稿的制作与履约记录。价格、实付、退款、首本权益及生产进度分别表达，受控 1 分验收订单明确标识；不得把 999 元标价当成实收或退款金额。已合入的真实支付/退款能力及适用证据复用，不因本次整理追认其他订单、设备或售后通过。

退款/质量首版只处理已存在申请，使用当前状态允许的审批、拒绝、核实、执行和查单动作。未知资金或印厂结果保持待核实；原单重印不生成新购买或首本权益，改稿仍需重新确认。用户资料申请及换绑等继续使用原核验和受控用例；必要纠正仍经本人确认。待处理查询按实际用户/项目/申请关联，不要求每项都存在支付订单，也不新建通用工单工作台。

### 人工生产

主流程为“PDF 书稿完成 → 已生产 → 已发货/物流”。PDF 及适用确认来自确定版本；已生产必须有运营核实完成印制的独立事实，不能把印厂接单直接改名。沿用必要的交接编号、负责人、接单/取消核实及各次制作记录；日常表单不要求手填内部工单 ID 或文件 hash。

人工取得当次获授权的 PDF/地址并线下联系印厂；登记完成印制、物流及实际交付。物流事实与适用微信发货处理结果独立记录。审核、权限、唯一权益、重复提交及退款/撤回冻结继续有效；不开发印厂下单或物流查询接口。

### 长期服务及硬更新

长期业务语义按 [ADR 0017](../../adr/0017-lifetime-service-and-retention.md)，共用实施归既有 #105。制作、回听、下载、导出申请及必要原声/转录/故事/照片/书稿 PDF/完成资料包长期有效，停止 API、Worker 及对象生命周期按服务期限清理必要资料。移除计时、期限配置和到期审核；日期确实必填时固定 2099-12-31，仅作占位，超过该日也不失权或删除。有效长期包不能被孤儿清理误删。

安全会话、上传/下载能力和客服私人访问继续限时；主动撤回/删除、迟到结果拒绝、当前模型重启和逐层清理仍验证。首本数量、资金、实际售后窗口和人工处理时限独立适用。开发直接硬更新并按需重建夹具，不安排旧数据迁移、旧期限/旧台账兼容、备份准备、旧库恢复或回滚演练。

## 测试决策

沿用已确认的最高公开入口：HTTPS 后台浏览器联通实际管理 HTTP，唯一性、锁、重复提交和重启使用真实 PostgreSQL/Redis。复用既有飞书、退款、生产交接、资料导出和删除的 HTTP/浏览器范例，只替换外部供应商网络；不以组件内部实现或重复断言充当验收。

| 入口 | 必验结果 |
| --- | --- |
| 登录与导航 | 飞书回跳/失效/退出；权限菜单与直达 URL；刷新/前进后退/多标签及 403/404；旧功能无入口 |
| 列表与关联 | 超过旧最近记录上限仍可搜索翻页；待处理不漏无订单项目；详情跳转和返回定位；备注准确关联且不重复 |
| 订单与服务 | 实付/标价/退款准确；状态允许的处理、重复/冲突及未知结果；换绑、导出、撤回/删除和原单重印仍执行原约束 |
| 生产与用户端 | 同一确定 PDF/地址；接单与完成印制分别记录；人工发货/取消/交付与两端进度一致；微信结果独立 |
| 长期访问与清理 | 时间超过旧期限及占位日期仍可使用；API/Worker/有效包/对象清理不误删；安全授权失效和主动权利仍立即生效 |

各票完成相关回归、类型和构建，固定最终提交后独立 Standards/Spec 审查及最终 PR CI；串行合并并等待 main CI 全绿。新后台公开配置下的路由和业务装配必须实测，不能把仅测试环境注册的能力写成正式可用。实际飞书、真实支付/退款、双端设备、OSS 生命周期、印厂与实物分别留证；既有证据只有在版本/配置适用时复用。本轮需求更新不执行部署。

## 范围外

- 独立客服工单、商品/关系配置、服务期限、运行信息、任务管理、全局审计、经营看板、模板或角色配置页面。固定套餐和关系由项目配置维护，审计/后台任务继续执行；必要故障处置使用已有受控维护工具。
- 人工开单、改价、直接标记付款、代客新建退款/质量申请；账号封禁、合并、批量营销和无需本人确认的内容代改。
- 新支付通道、印厂/物流自动接口、额外首本权益、无限内容额度、自动批准售后或永久安全凭证。
- 旧开发数据/备份迁移、兼容及恢复/回滚演练。
