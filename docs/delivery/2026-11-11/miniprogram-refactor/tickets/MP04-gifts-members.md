# MP04 · 礼物三分类、切换故事书与家人邀请

状态：ready-for-agent；GitHub [#170](https://github.com/brycezhang/timenook/issues/170)，父规格 [#166](https://github.com/brycezhang/timenook/issues/166)。父规格：[小程序全量重构](../spec.md)。

## 交付结果

用户从送出、收到、参与找到正确的故事书；购买者邀请家人，家人填写相对主讲人的关系后加入。

对应差异：F06、F07。主责画板：`MyProjects`、`MyGiftsReceived`、`MyGiftsParticipating`、`SwitchProject`、`InviteShare`、`InviteJoin`。详见[画板对照表](../DESIGN-MAP.md)。

## 验收条件

- [ ] 分类来自真实赠礼/领取/成员事实，不把普通 invited 改名当收到。自购同一本在送出和收到均显示并标记送给自己。
- [ ] 送出类恢复待付款；切换故事书使用相同分类，展示送礼人昵称与购买时赠礼关系。
- [ ] 仅购买者可邀请；接受邀请必填「你是主讲人的谁」，支持自定义，关系不改变成员功能权限。
- [ ] 未登录接受后返回原邀请；失效提示在现有流程内处理，不恢复已删除独立失效页。
- [ ] 切换、旧订单和邀请操作保持账号/项目隔离；网页与后台消费同一新身份契约。
- [ ] 本票全部主责画板完成设计与原生 UI、交互对照，记录 390px/320px、真实入口、截图与差异处理；不留死入口或用样例数据冒充业务。
- [ ] 实现、相关检查、原生验证及外部待验分别记录，改动与测试只覆盖本票实际边界。

## 数据与契约边界

本票按新方案直接修改相关前后端、共享契约和数据库。开发数据可破坏性重建，不做旧模型兼容、双写或旧接口别名。影响现有网页/后台消费者时同步适配，不扩展视觉范围。

## 测试决策

成员权限与分类 API 集成测试；开发者工具多角色、同一自购书双入口、待付款和切换路径。

复用现有测试入口，优先验证公开行为；数据库约束使用真实 PostgreSQL/Redis。外部待验不视为功能缺失，已实现能力与未验环境分别说明。
