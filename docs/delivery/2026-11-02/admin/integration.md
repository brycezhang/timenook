## 已接通的操作

- **订单**：真实 Vben 登录/主布局、路由菜单、面包屑、多标签；全量历史查询/分页，标价、实收/退款及验收订单分别显示；关联用户/项目/生产单、追加备注及本单历史。
- **用户**：账号及无账号讲述者可检索，关联项目和已有订单；无支付订单项目可处理本人资料申请，核验、换绑、撤回/删除和必要纠正嵌入项目详情。内部本人导出采用人工受理，不编造 D06 SLA/日历；未明确的无账号替代接收验证渠道显示不可用。
- **生产单**：全量分页检索、独立详情、当次授权 PDF/地址取得、人工交接/取消核实、完成印制事实、人工物流/交付及独立微信结果；用户端读取同一事实。候选 PDF、未付款及 physicalProduction:false 不获得实物资格。
- **订单售后**：已有退款/质量申请在原订单内处理，核实/批准/拒绝/执行/查询或原单重印有标准确认；私人材料按当下限时授权取得，切换/失权/退出后清理。生产跳转返回同一订单申请，审计按原订单关联。
- **长期服务**：复用已合入的 #108，补齐剩余期限文案；时间推进到 2100 年、Worker 重启/孤儿扫描仍保留有效 ready/delivered ZIP 与相同摘要，主动删除和安全授权仍生效。

商品配置、运行/任务、独立工单和全局审计页面退出本次应用，后台任务、审计和已有受控维护继续执行。旧 #8/#9 的 not_planned 状态表示被替代，不表示未完成验收通过。

## 发布输入

正式构建补验发现 Vben 与应用通过不同 peer 解析实例取得路由注入键，开发服务器未暴露该差异，构建页面出现 router 注入失败。Vite 现显式去重 Vue、Vue Router、Pinia；订单 HTTPS 套件改为先构建再用 preview 提供实际产物。未修复时真实登录/主布局无法出现，修复后原两条订单、标签、备注、权限/退出路径 2/2 通过且无 pageerror，后台类型检查通过。实际线上恢复与最终 CI 仍在 #150 分别留证。

新增权限仅 `orders:read`、`orders:write`；用户服务沿用 `care:write`，生产沿用 `fulfillment:write`。实际原管理员的配置更新须作为部署运维记录，不通过兼容映射或虚构管理员会话完成。

新增结构为订单备注、用户备注、审计资源关联及完成印制事实，使用本次审定 Prisma 变更应用到当前结构；不安排旧开发数据迁移、兼容、备份或旧库恢复/回滚演练。API/Worker、后台静态页和产品网页使用同一验证候选，保留服务器受限 env、文件资料和真实付款事实。

部署前已只读核实：线上 `timenook` Bucket 生命周期 HTTP 200、规则为空；现存 21 个项目的服务政策均为长期、待定为 0。现网 Node 为 22.23.4，项目内 pnpm 为 10.34.7，API/Worker 独立运行，后台/产品网页具有既有 history fallback。发布时重新读取实际 current/服务状态，最终候选、CI、表结构应用、权限、正常飞书及公网路由结果单独记录。
