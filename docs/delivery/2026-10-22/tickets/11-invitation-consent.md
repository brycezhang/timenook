# T11 · 实现讲述者邀请绑定与分用途授权

GitHub：[#12](https://github.com/brycezhang/timenook/issues/12) · 状态以 GitHub 为准。
阶段：S1

## 交付结果

讲述者申请参与，经发起人核验绑定后，分别决定采集、AI 处理和共享权限。

## 验收条件

- [ ] 邀请令牌仅保存摘要和有效期；申请不授予内容权限，陌生人页面不泄露私人标题/素材。
- [ ] 发起人确认后事务锁定项目与 subject；并发审批只绑定一人，旧邀请失效，禁止将付款账号伪装成另一讲述者。
- [ ] 记录主体、操作人、用途、告知版本、方式及证据；拒绝授权保留订单与客服入口但禁止采集/AI。
- [ ] 建立按项目、用途及 access_epoch 校验的访问边界与基础撤回命令；旧会话/幂等结果也重新鉴权。
- [ ] 客服换绑须有 D08 本人核验、工单、操作人及绑定版本；原 subject 与历史故事/确认记录不变，原子更新绑定并递增 access_epoch。旧账号本项目访问及旧幂等敏感结果失效，新账号重新授权，其他项目合法身份不受误伤。
- [ ] 公开 HTTP 验证无工单/证据/权限拒绝、换绑并发只生效一次、重放不重复迁移、旧会话立即拒绝和新账号未授权前不可读取；工单/来源版本与审计可追溯。
- [ ] 本人首次参与事实按 T10 契约写入并幂等传递；再次登录、换绑或重新邀请不重置制作或资料期限。

## 实现边界

复用 T06/T07 的身份、权限和审计；换绑由客服在共享工单内核验本人后执行原子命令，不建自动身份裁决或多级审批。T24 负责跨生产/活动流联动。
