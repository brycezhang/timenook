# MP03 · 指定手机号发卡与领取礼物

状态：已确认，待发布 GitHub Issue。父规格：[小程序全量重构](../spec.md)。

## 交付结果

送礼人指定号码并分享礼物卡；指定收礼人验证手机号、明确领取后进入原故事书。

对应差异：F04。主责画板：`GiftRecipient`、`GiftShare`、`GiftOpen`、`GiftVerify`、`GiftMismatch`、`GiftAccept`、`GiftInvalid`、`GiftClaimed`。详见[画板对照表](../DESIGN-MAP.md)。

## 验收条件

- [ ] 记录礼物、指定手机号、卡片当前版本、领取账号和状态；专属领礼与普通项目邀请分开。
- [ ] 服务端以已验证账号手机号判断匹配，不能信任客户端传入号码；匹配后仍需明确领取。
- [ ] 领取前更正号码并重发使旧卡失效；领取后不允许改号码，原领取者重开有效卡进入同一本书。
- [ ] 并发/重复领取只建立一次主讲人与成员关系，不复制项目、订单或权益；非指定账号无权领取。
- [ ] 领取后保留购买者在领取前准备的录音、照片与稿件，不复用旧重新绑定操作使素材授权失效。
- [ ] 微信分享可从真实入口到达；不匹配、失效、未登录、已领取、返回路径与画板一致，领取后不增加首讲中间页。
- [ ] 本票全部主责画板完成设计与原生 UI、交互对照，记录 390px/320px、真实入口、截图与差异处理；不留死入口或用样例数据冒充业务。
- [ ] 实现、相关检查、原生验证及外部待验分别记录，改动与测试只覆盖本票实际边界。
