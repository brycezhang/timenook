# 采用可靠保存后的文件转写

2026-11-05 更新：按 [ADR 0018](0018-project-members-and-simple-printing.md)，用户端改为录音结束自动上传，仅显示上传中、成功、失败重试；不再展示下文本机/封存/转写等技术阶段或本人确认门槛。可靠保存、后台任务和恢复仍是内部实现要求，新界面尚待代码重构。

采访链路为“录音 → 可靠保存 → 文件转写 → 可选追问 → 故事确认”。小程序持久保存录音并上传封存，数据库任务与Outbox驱动Worker调用豆包文件ASR，转录就绪后由DeepSeek按需生成一条可选追问。

用户可继续补录、跳过或离开；全部已选片段转写完成后才整理故事。失败重用封存原声恢复，未知提交结果先查询原任务；迟到结果须复核授权及输入版本。

录音中显示当前问题与计时。停录后存在上传和转写等待，界面区分本机保存、云端保存与文字处理状态；处理时延由实际短片段验证，未终态任务允许离开后恢复。

详见[技术架构](../architecture/技术架构.md)与[MVP PRD](../时光里_岁月成书_MVP_PRD.md)。
