# MVP 采用固定首版政策、探针复用与受控人工运营

用户确认在保留 MVP 功能与 T01–T30 拆分的前提下，收敛实现方式。一套首版套餐使用一份经确认的政策版本，历史订单继续执行其快照；商业值仍由对应 D 项负责人冻结，现有配置枚举不要求全量实现。

S0 探针输出可复用能力和真实风险证据；生产票复用已验证的 adapter、处理和渲染模块，补齐生产身份、授权、版本和共享任务机制。探针身份与数据保持隔离，不建立第二套运营产品。

首版使用共享工单与必要操作表单。客服承担身份核验、异常判断、交接和售后决策；权限撤销、资金执行、资料清理和确定版本交付仍由受控业务用例保证。人工流程保留负责人、时限、状态和证据。

2026-10-29 进一步明确成书与线下履约边界：系统自动产物止于生产 PDF，运营人工导出并在线下对接印厂。主流程以“PDF 书稿完成 → 已生产 → 已发货/物流”表达；PDF 完成由确定文件及适用确认事实形成，已生产和已发货由运营核实后手动登记。印厂接单不等于完成印制，物流事实与微信平台发货处理结果分别表达。系统保存相应版本、操作人与时间，不承担印厂下单、印刷调度或物流自动查询；既有权限、权益、撤回/取消和实际交付事实仍按原规则处理。系统功能验收与线下实物/经营验收分别记录，不以本次边界澄清追认任何验收通过。

[实施规格](../delivery/2026-10-22/spec.md)中的“首版固定政策”“探针复用与生产集成”“人工运营边界”“验收复用与唯一归属”为详细执行依据。沿用 ADR 0001/0002/0003 的单体、版本与授权底线，以及 ADR 0008 的单套模板。此决定不代表代码、真实条件或上线验收已完成。

2026-10-29：其中有限制作/访问/必要资料保留期的选择由 [ADR0017](0017-lifetime-service-and-retention.md) 替代，直接采用长期有效；D06人工时限、D07售后窗口与安全授权有效期继续独立执行。
