# 资料删除与恢复前重放（T26）

2026-10-29 当前目标按 [ADR 0017](adr/0017-lifetime-service-and-retention.md) 更新：必要资料长期保留，主动撤回/删除优先执行。下文区分新目标与既有恢复机制；代码对齐和新验收尚待完成。历史到期清理测试保留为当时结果，不能证明长期方案已通过。

本票 [#27](https://github.com/brycezhang/timenook/issues/27) 消费 T24 撤回与 T25 完整导出，并覆盖 T27 退款及 T28 质量售后的组合。工程决策见 [ADR 0014](adr/0014-independent-privacy-ledger.md)。本文描述本地机制和复现入口；独立审查、PR/main CI 及实际运行结果单独见 [T26 证据](delivery/2026-10-22/evidence/T26.md)，本地结果不代表正式恢复验收。

## 删除申请与逐层结果

沿既有 `POST /v1/projects/:id/care-requests` 申请 `kind: delete`，由具有 `care:write` 权限、飞书管理会话和 CSRF 的运营人员沿原核验入口处理。核验先持久化独立拒绝依据，再投影永久项目墓碑和逐项清单；核验会尝试一次活动清理，单项失败持久为 pending/RETRY_REQUIRED；核验201只确认拒绝与清单已提交，不能据此宣称物理擦除完成。活动清理失败不能撤销已经生效的拒绝。重新同意不能恢复永久删除的项目。

| 入口                                                               | 用途                                                  |
| ------------------------------------------------------------------ | ----------------------------------------------------- |
| `GET /v1/projects/:id/deletion-status`                             | 当前发起人/绑定讲述者查询最少状态，内容拒绝后仍可访问 |
| `GET /v1/admin/care-requests/:id/deletion-status`                  | 删除工单的运营逐层状态                                |
| `POST /v1/admin/care-requests/:id/deletion/reconcile`              | 重试系统负责的活动清理                                |
| `POST /v1/admin/care-requests/:id/deletion/items/:itemId/evidence` | 为历史对象、备份或供应商的一个项目记录受限核验引用    |

清单区分活动数据库、活动文件、缓存、对象历史版本、备份和供应商副本。一个项目完成只证明其对应层完成，没有人工总 `deleted` 开关。主动删除处理时限未冻结时保持空值和待处理原因；回执不能虚构执行结果或延长既定处理时限。当前运营证据接口只接受明确隔离的 `record:synthetic-…` 引用，真实接入仍须 D03/D08 准入。

用户页分别呈现在线访问停止、活动清理、备份待到期/核验和外部待确认，不返回姓名、正文或地址。客户端复用 T24 的页面权限重验和临时音频/照片清理；首次读取与成功轮询走同一状态应用及受控缓存清理路径，隐藏页面、切换项目后的迟到响应不能应用旧结果。设备原始录音、主动另存的 PDF/导出及纸书不由平台远程取回；新权利请求的输入也不作为旧资料缓存清除。

## 清理范围与不变量

`care/erasure-registry.ts` 与迁移中的登记表列明私有 payload 的类别、字段及行键。范围包含个人计划/实际问题、转录及各处内嵌副本、故事/追问输入输出、照片、书稿快照/检查文本、原声关联、导出清单、地址和运营私人证据。数据库触发器将擦除限制到已经登记的删除项，保留原有 FK、版本、金额、首本/生产及退款事实；不提供忽略全部 immutable 约束的开关。最少身份/哈希/权利/财务事实仍可能可关联，其依据、访问人和独立保留期限需要负责人确认。

各表的行键保留原类型，书中原声入口使用随机稳定短码，不能按 UUID 解析。逐包删除的 UUID 转换须隔离在 `care_exports` 的 PL/pgSQL 分支内，不能仅依赖 SQL CASE：PostgreSQL 在计划阶段可能提前计算常量表达式。该约束由真实 PG 的 custom/generic plan、精确删除项及实际擦除回归验证，修复与最终运行证据见 [#83](https://github.com/brycezhang/timenook/issues/83)。

随机输出和临时运行先登记持久所有权，再执行 I/O；已经有持久编号的录音、照片、书稿和导出复用其原标识。事件捕获当时的精确存储目标和任务范围，恢复时与旧库可发现目标合并，清理不扫描删除整个 Bucket 或其他项目的临时目录。活动文件会重复清理，以覆盖已经签发的上传或迟到写入；旧任务依 T24 拒绝，不因新 lease 或新授权重获资格。

照片裁剪运行中的输入及 `output/original.bin` 仍是原图副本，首次 I/O 前逐文件登记 originalPhotos；预览、印刷图和输出描述另登记 derivedPhotos。混合目录不能整体归入一个类别。照片读取只检查所选原图或衍生图自己的类别；同时要求两类的门闩保留在真正制作、裁剪和封存入口。

Redis 的录音/照片上传能力按应用命名空间及实际 projectId 清理，不清空 Redis。主动撤回/删除只处理所涉上传通道与精确资产，不能因清理孤儿包误清仍有效的上传能力。已完成的缓存项继续补扫迟到 SET。付款能力缓存按登记的 PG 列清理；BullMQ 中的最少任务 ID 不等于正文缓存。照片新制作和后续处理仍核对原图、衍生图的当前授权及删除状态。

D03 支撑制作、回听、下载的资料长期保留。取消按服务/保留期限扫描并产生删除事件的规则，时间推进、日期占位、交付和退款均不成为自动删除原因。本人主动撤回或核验删除仍沿独立台账处理；类别与副本层分别报告，技术残留清理不得误删有效资产。

固定 PDF、冻结 snapshot 与其必要来源长期保留，读取继续核对当前身份、授权、epoch、来源及确定版本。真实编辑或配置改变仍使受影响旧版 obsolete；主动撤回/删除不得被快照读取绕过，也不能通过新授权恢复永久删除的项目。

清理归属继续登记到实际类别：个人计划、问题、偏好、地址和质量证据归 activeData；正式转录及内嵌 sourceManifest 归 transcripts；确认稿归 confirmedStories；冻结 snapshot、检查文本及最终 PDF 归 bookPdf。处理过程的混合副本登记全部实际来源，原图与衍生图分别处理。主动删除必须覆盖相关嵌入副本及 ZIP；长期服务不改变逐层、逐文件定位与单向擦除要求。

ZIP 的 source 捕获、行清单和文件目标共用实际 manifest 的类别判定。有效 ZIP 不因经过时间被撤销；主动撤回/删除按其实际包含资料判断范围。未知 manifest/照片归属不能静默假定无目标。

有效导出包长期保留，不再按 readyAt/expiresAt 产生自动到期删除事件。技术孤儿文件与主动核验删除仍使用精确包标识，不能误扩大为其他项目或其他有效包。derivedAudio 没有本平台产物时明确记录无目标。主动删除后的历史对象、备份轮换和供应商回执按实际处理流程与时限逐层核验，不能将长期服务解释为无限保留已请求删除的副本。

恢复只接受原独立源中可认证的撤回、版本否决、核验删除及其他已发布的不可逆删除事实，保留实际 ID、时间及当时捕获的清理范围。无法确认范围或授权依据时保持待核实并停止相关私人能力，不圈选后来新任务或假报各层完成；任何恢复结果都不能制造新的肯定授权。

2026-10-29 本次开发重构按 ADR 0017 直接硬更新：不以旧开发备份/旧台账格式、历史到期删除事件的恢复兼容为实施要求，不安排备份或回滚演练。下述既有机制记录不构成本次旧版本兼容承诺；新模型的主动删除、权限和迟到结果拒绝仍验证。

## 独立源与恢复门闩

独立源包含受限的事件目录、固定锁文件和认证 head；32 字节密钥在业务备份和发布包之外托管。发布通过原生非阻塞 flock 串行化，在事件文件及目录同步后发布 head。缺失、截断、损坏、分叉、错误权限或数据库 authority 不符都拒绝私有能力；半写临时文件与完整认证后继按固定协议恢复。单事件上限 16 MiB，超限失败而不截断删除目标。

同进程按 `realpath(root)` 排队并直接FIFO交接，避免持续短snapshot重取让10毫秒轮询的旧等待者一直错过空隙。入口原有单一单调5秒预算包含目录准备、本地等待、打开与原生flock重试；排队超时移除自身，不释放持有者或阻塞后继，handoff时还会跳过已过期等待者。当前owner先处理原生unlock及自己的FD close，再交给本地后继；已取得锁后的完整认证work不被该获取预算中断。内核EX锁、固定inode检查、跨进程排他、源认证和运行失败后的显式重启规则保持。

独立源是拒绝依据，业务库中的 `privacy_events` 和清单是投影。恢复前校验来源及连续 checkpoint、重放拒绝/永久墓碑，再执行活动清理；无法解释的目标或不一致不能静默跳过并宣称 ready。API 门闩位于 `app.init()` 触发的定时任务前，Worker 在恢复扫描、领取和供应商交互边界复验；健康探测的存活不代表私有能力可用。

活动进程固定绑定规范化数据库位置、数据库安装 UUID 和 authority 代次。恢复切换使用显式命令，在目标库重放后提升独立源代次；旧 API/Worker 不能跟随新代次自行继续。全源及认证 head 一起退回合法旧版本的检测依赖正式独立介质与运维防回滚措施，不能用本地 HMAC 代替。

连续 checkpoint 校验 sourceId、generation 与该前缀 hash；业务库仍持有较高或不同前缀时拒绝合法旧 head。事件 receipt 与对应完整投影在同一事务提交，checkpoint 只沿已经提交的连续 receipt 推进。持有项目锁的业务操作验证全源认证与连续 checkpoint 前缀，再核对当前项目后缀事件的精确已提交 receipt（UUID按数据库等价语义规范化）；其它项目尚未提交的事件不撤销本项目权限。启动、恢复与请求入口仍要求全源重放，源身份、authority、认证或前缀矛盾仍关闭全部私人能力，不在另一连接重取已持有的项目锁。活动流在实际 scope 检查前后均复验 fence/source：scope 读即使等待了一个“独立源已发布但 PG 最终回滚”的事务，也不能再凭旧数据库授权发出下一块字节。换绑及工单核验先完成可能失败的 PG 准备写入，再发布独立源，最后 COMMIT；发布前准备失败可以完整回滚，发布成功后 COMMIT 失败或进程退出不能撤销拒绝。下一次启动先重放；相同核验重试复用源中的确定删除事实，不能重新捕获后来任务。

项目永久删除后仍可依法原 D07 申请、审批、执行、查询及入账退款，只新增最少资金事实，不重新保存私人描述或证据正文；unknown、资金预留和商业冻结约束保留。本人否定及必要权利事实可继续记录，不能重新肯定授权或绕过永久墓碑。

私人正文读写继续检查已持久化拒绝、当前用途授权和项目墓碑；拒绝一旦生效，即使物理清理尚未完成，也不能继续读取或新增被禁止的私人内容。稳定请求号、请求 hash 和最少资金/权利事实继续处理，重试只影响物理进度。

通用工单、首本、履约及质量详情不因服务经过时间隐藏仍合法的私人资料，但须按当前权限、主动撤回/删除范围限制展示。经核验删除的地址、物流、微信发货与私人回执不能重新写入或复制到新尝试；一份 PDF-only 授权不能扩大为地址授权。

公开写入按 registry 核对主动删除范围及当前授权：会话或专属授权过期仍拒绝肯定操作；本人否定、已核验换绑和退款/履约最少事实继续处理而不恢复被删除的私人内容。精确故事否决沿独立源保存主体/操作人/版本/hash/否决 flags，不能把此前否定的确认位变回 true。

履约 `shipped_at` 与私人 tracking 分离为最少实际时间。发货/签收保存实际时间与状态，不推测缺失事实；主动删除后省略所涉私人 tracking、WeChat、回执及 evidence。原输入重放仍通过稳定 requestHash 核对，更改原输入或实际时间仍冲突。质量案 D07 退款判定按原案、原窗口和原政策执行；长期服务不重开退款/质量窗口，新的私人材料访问和重印仍须当前授权。

## 本地入口与验证边界

仅使用回环 PostgreSQL/Redis、隔离 schema/前缀及合成资料。测试通过 `test/privacy-fixture.ts` 在迁移后显式创建独立源；重启复用同一个源，不在应用构造时自动创建。依赖安装须按仓库锁定的 Node/pnpm，`fs-ext` 是显式允许编译的原生依赖。

已编译 CLI 的入口如下，实际数据库身份须由配置位置和安装 UUID 派生；不要给一个随意 UUID 代替目标身份。密钥文件和源目录必须在 Git、业务数据和发布包之外。

```text
pnpm --filter @timenook/api privacy:journal bootstrap --root <独立绝对目录> --key-file <受限密钥绝对文件> --database-id <目标派生身份>
pnpm --filter @timenook/api privacy:journal inspect --root <独立绝对目录> --key-file <受限密钥绝对文件>
pnpm --filter @timenook/api privacy:recover activate
```

`bootstrap` 只允许明确的新源；`inspect` 只输出脱敏 head 元数据，不输出正文或密钥。恢复命令须先准备已经迁移的隔离目标库、原独立源及受限配置，不能在正在服务的业务库中试运行。测试专用配置文件入口额外要求 test 环境与回环数据库，不能用它接入正式环境。

真实 PostgreSQL/Redis、主动文件清理、独立进程恢复、故障窗口、长期保留及安全授权失效的公开 HTTP 结果在本票证据中另记。真实 D03/D06/D08、Linux/ECS 介质和权限、备份轮换、供应商回执及双端设备仍须各责任票验收；T29/T30 未由本轮实施。

长期资料不按服务期限补扫删除。主动核验删除仍清理已完成、失败与 packing 状态的实际目标；不能因 locator/manifest 已擦除而复活旧包，也不能因未成功产包就遗漏其迟到文件。ZIP 下载通过最后 guard 后才设置文件响应头，失败返回正常错误正文。

数据库载荷的逐项擦除由单向 SQL 约束保护；新尝试已完成后，旧失败不能把该 active_database receipt 或完成时间降回 pending，条件按数据库当前 layer/state 判断。文件和缓存可有迟到副本/SET，完成后仍重扫，真实重扫失败仍改为 pending；不能套用数据库终态例外。运行中重放错误已使进程关闭私人能力时，仅移除故障不会自动重开；须显式重启，沿原独立源与 authority 重放后再以原命令号继续。

固定 PDF 流沿服务端来源范围核验当前主体、许可、版本/hash 及前后 fence；长期服务不允许绕过任何主动撤回/删除、故事否决、hold 或 epoch 变化。完整 source、authority、连续前缀或 receipt 的认证矛盾继续拒绝私人能力，启动/恢复继续重放独立拒绝依据。原服务期限类别例外不作为新方案的兼容要求。

CI的book-fixture诊断只包裹原文件/native调用：失败候选可带目录准备、本地排队、native回调、认证work和unlock/close的最少时长/计数。本地slot的观测不等于跨进程native所有权；只有原成功回调后才记录native获取，错误归因仍为unknown。它不增加source/DB读取、重试或重置failed/5秒预算，成功不输出；路径、密钥、载荷和rawstack不进入记录。具体CI失败与未复现的本地测量见本票证据，不能将诊断提交视为根因修复。

每次完整源认证仍持有同一原生EX，event文件按最多4项读取，每项仍认证原字节的HMAC，批次全settled后依原顺序验证链/文件名/head前缀；错误不会令其它在途FD/I/O越过unlock。此有界读取缩短慢FS回调往返在本地FIFO内的累计等待，不缓存源或省略认证，也不延长获取锁的原单一5秒预算。真正超过预算仍拒绝并保留原进程闭锁/显式恢复要求。

打包沿固定Node22的原生CRC-32生成同字节ZIP STORE，避免逐位JavaScript计算长时间占用源I/O所在事件循环。解码/渲染的RSS监控使用非重叠异步ps，保留50ms采样、1秒查询上限、全后代RSS与原总时限/失败终止；worker结束仍须等待在途采样，不能把尚未返回的监控失败当成功。它们不放宽源认证或锁预算，具体可控负载与实际CI尚未证明的边界分别记录在本票证据中。

异步资源采样在总时限后返回时，先将已锁存的终止意图应用到新识别的真实后代，再完成采样drain和拒绝；不能只在本次RSS超限时重新终止。持续控制覆盖原ps行已捕获后代、deadline先结束worker、晚到结果后后代也须停止的窗口；僵尸与仍运行进程分别判断。
