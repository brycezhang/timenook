# 双端 UI 实施与发布

2026-10-30 用户已批准最新可点击原型并授权实现网页版、小程序版及线上部署。主规格为 [UI 提案](../../frontend/ui-review-2026-10-30.md)，视觉与布局以 `designs/timenook-ui-2026-10-30/index.html` / `app.js` / `style.css` 为准，后两轮反馈覆盖首版交互。实现基线为 `404a137`（#116）；已有录音、OSS、任务、版本和权限契约直接复用。

## 用户可见结果

- 纸色、宋体阅读、橄榄绿行动，手机底部导航、桌面左侧导航；项目页先显示当前行动、未完成讲述及待确认故事，任务历史折叠但保留故障恢复入口。
- 选题、准备、录制、回听、保存处理按已实现步骤呈现；选题主按钮独占一行，换题独立一行；照片、自拟、自由讲述、暂停继续和原片段恢复保留。
- 保存／转写只显示实际状态。上传完成与封存成功分开，未知结果不称已保存；排队、提交、供应商等待、成功、失败、无语音、人工核查、失权正确显示；无百分比、ETA 或定时模拟完成；测试存储不称云端。
- 资料用途开始页一句说明、「确认并开始」及折叠详情。访问不产生授权；本人点击一次记录现有采集、AI、共享用途并进入准备。用途管理、撤回、删除和同机协助身份规则保留。用户最新反馈取消单独入书用途说明，也不新增第四类用途记录。
- 故事阅读确认区只保留「确认」按钮，移除复选框、手写说明和单独入书用途说明。沿用确定故事版本的确认及入书决定，绑定版本、内容 hash、告知及真实点击操作证据，发起人不可替本人确认，修改后旧确认失效。
- 成书页突出确定书稿与真实 PDF，同版双方确认、变更提示、地址和生产准入保持；官网与内测登录、邀请、大纲、我的和服务沿用原型层级，保留动态关系和已有真实业务入口，不发明示例数据。

## 验证边界

沿用现有 Page/业务客户端公开交互、API/契约与浏览器端到端测试：点击记录真实请求，核对权限、确定版本、重复提交恢复、用途撤回后的入书行为；复用已有数据库及供应商链路验证，本次不重复无关全链路。样式通过 320/375/390/430 及桌面截图、键盘和无溢出检查，小程序执行官方编译。真实微信上传/提审/发布取决于已有可用账号及上传权限，实际设备结果和网页证据分别记录，不能用共源浏览器替代真机。

线上部署沿用实际主机和静态 release 原子切换；先核对服务、当前 release、环境与入口，保留服务端密钥和业务数据。只有本次实际需要的服务才更新，部署后核对公网内容与业务状态。方案、工程交付、运行验收分别记录。

## 审查修复与本地验证

- 换题使用录音上下文新增的 `plan.eligibleQuestions`，来自当前个人计划并沿用禁问主题及非 ready 状态过滤；页面轮换真实问题，开始时提交当前显示的 key。
- 本人开始确认后携带独立草稿与准备标记进入录音准备，不自动启动麦克风；旧活动讲述及本机原片段继续通过恢复入口访问。
- 故事确认按同一讲述者主体的最新决定保留入书拒绝，账号换绑不重置该选择；有效内容确认仍校验当前绑定，本人可明确调整决定。原声播放卡使用中性的“原声已保存”。

上述问题均在公共 Page／API 入口补充回归并先复现再修复。受影响前端 127 项、真实本地 PostgreSQL／Redis 下两个 API 套件 44 项通过，前端类型检查、contracts／API 测试编译、双端构建和官方 wcc／wcsc 26 页编译通过。此处仅为本地工程证据，发布、微信设备及真实供应商结果另记。
