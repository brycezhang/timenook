# 项目成员统一功能与简化制作流程

本决定来自用户对设计审阅的六项明确调整，是当前产品规则。原生小程序、API、数据库成员关系和条款已按本决定重构；本机定向验证通过，后端与成员迁移已部署，小程序 0.3.1 已于 2026-11-06 查询原任务确认上传成功、未提审。官方开发者工具真实登录及项目读取通过；小程序／API 旧流程测试已清理并按新规则补测，完整 `pnpm check` 及实际线上 15 步通过；网页单独的旧浏览器测试暂不对齐，见 [E2E 记录](../delivery/2026-11-05/online-e2e.md)、 [实现记录](../delivery/2026-11-05/final-design-implementation.md) 与 [部署记录](../delivery/2026-11-05/deployment.md)。

## 决定

- 品牌为“时光故事”，产品/首页 Tab 为“岁月成书”；另一个 Tab 为“我的”。
- 购买与参与统一在“项目”入口展示。内部保留支付记录、权益与成员关系，但不再以订单作为另一个用户菜单。
- 支付者可分享邀请给微信用户。接受邀请即加入；成员拥有记录、照片、编辑、成书、地址与印刷等完整项目功能。取消原身份申请审批、发起人核对绑定、同机协助及讲述者专属操作门槛。自购也使用同一成员模型。
- 资料用途与服务约定归使用条款。登录或接受邀请即接受条款，入口清楚展示同意说明和阅读链接，实施时记录对应条款版本与接受事实。后续不重复确认，不设用途选择或独立制作授权页。
- 2026-11-06 登录要求更新：先在协议弹窗中明确同意《使用条款》和微信《隐私保护指引》，再授权手机号快捷登录；首次昵称为「用户」加手机号后四位，后续可在「我的」修改，重新登录保留修改结果。开发数据清空，不增加旧账号兼容或补全流程。
- 登录与购买分别操作。首页与“我的”均可独立登录，登录本身不创建购买或发起支付；已有项目登录后直接可用。新购项目需要登录时，先完成独立登录页，再回到购买确认；只有点击购买才进入支付。
- 2026-11-06 首页新购顺序更新：未登录点击首页 999 元购买，先在首页弹出共用手机号快捷登录，成功后进入「新购一本书」；已登录直接进入。「我的」和独立登录承载页复用相同组件，取消不继续购买。此规则替代上一条新购前先进入独立登录页的导航。
- 录音结束自动上传，用户只需知道上传中、成功或失败重试。后台仍负责可靠保存、上传恢复和任务处理；不把封存/ASR等阶段转成用户需要完成的步骤。
- 新故事整理后可自动编入章节，由任一成员编辑或移出入书内容。取消“必须讲述者本人确认才能入书/印刷”的门槛。
- 项目中直接印刷：当前就绪书稿、有效地址、提交制作。无需双方确认、本人确认、逐页访问完成、勾选或手写核对说明。
- 退款、质量售后、资料与服务仅放在使用条款中说明，不单设小程序菜单。该导航决定不等于财务记录、履约事实或后台服务处理已经删除/完成。

## 保留的事实与技术约束

故事与书稿仍版本化；章节引用多个故事，编辑正文更新对应故事版本。封面/目录/故事变化后重生成；已提交或交付文件不被后续编辑覆盖。

首本权益、防重复支付/提交、未知结果查询、实际取消/生产/物流/交付记录继续保留。项目成员不自动获得运营后台权限，不代表项目内容公开。菜单简化不等于伪造退款到账、资料删除或实物完成。

## 对既有决定的影响

- ADR 0003 的分角色绑定、用途授权、同机协助与独立确认流程由本决定替代。
- ADR 0002 的不可变版本和确定文件继续有效；其中讲述者/发起人双方确认门槛由本决定替代。
- ADR 0006 的可靠上传与后台任务继续有效；用户端多阶段保存界面改为自动上传与结果。
- 既有 T22/T23 的本人/双方确认与限时制作交接门槛需在重构时移除或改为条款与项目成员规则，不能只删前端入口。
- ADR 0017 的长期服务继续有效。退款、质量和资料服务不设菜单，不增加业务到期倒计时。

开发阶段直接按本决定重构，不引入旧流程兼容层。现有代码验收记录继续描述当时实现；新规则的实现、设备/支付/资料处理/实物结果另行记录。
