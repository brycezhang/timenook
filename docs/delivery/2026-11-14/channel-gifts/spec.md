# 渠道礼物与第三方后台录单规格

2026-11-14。用户已确认业务方案及第三方后台增量。[父规格 #180](https://github.com/brycezhang/timenook/issues/180) 已发布。功能已在集成分支实现，工程证据见[实施索引](README.md)，设备、供应商与部署验收分别记录。

## Problem Statement

用户在第三方微信小店购买时光故事虚拟商品，填写购买者手机号后，需要在首次登录小程序或个人中心找到已购买的礼物，再选择送给谁。第三方运营销售需要能直接录入这些购买记录，平台运营需要管理录入账号和纠正录入错误。

## Solution

超级管理员通过现有飞书白名单登录后台，生成或撤销第三方用户名密码账号。第三方登录后进入唯一业务入口「录入订单」，填写购买者手机号即可提交。平台自动关联同号产品账号；尚未注册的订单在后续同号验证登录时关联。

购买者在「我的 → 我的礼物 → 我送出的」查看待送礼物，确认赠礼关系和书名后，开通同一本故事书及首本权益，再走现有送给自己或指定收礼人流程。待关联及待送礼物长期有效。新增礼物合并提醒一次，用户可查看或稍后处理。

## User Stories

1. 作为超级管理员，我希望通过已获准的飞书身份登录并管理第三方账号，以便将录单工作交给销售人员。
2. 作为超级管理员，我希望生成一个第三方账号及可交付的用户名密码，以便对方开始录单。
3. 作为超级管理员，我希望撤销账号后立即终止该账号的后台会话，以便结束其录单权限。
4. 作为第三方销售，我希望登录后只看到录入订单，以便直接处理购买记录。
5. 作为第三方销售，我希望只填写购买者手机号就能成功录入，以便处理缺少其他资料的购买记录。
6. 作为第三方销售，我希望可选补充原订单号、实付金额和付款时间，以便有资料时记录来源凭据。
7. 作为第三方销售，我希望重复点击或重试同一次提交时看到原结果，以便避免重复发放礼物。
8. 作为第三方销售，我希望明确录入新的一笔购买时能够使用相同手机号，以便同一用户多次购买。
9. 作为超级管理员，我希望查看全部渠道记录的录入账号、内部编号、手机号、可选购买信息及关联进度，以便追溯和核查；作为第三方销售，我希望在录入页面查看本人记录，以便更正和核对。
10. 作为已有账号的购买者，我希望后台录入后在小程序看到礼物，以便继续送礼。
11. 作为尚未注册的购买者，我希望用下单手机号首次验证登录后看到购买记录，以便开始使用。
12. 作为购买者，我希望每份新增礼物只提醒一次，多个新增礼物合并提示，以便稍后再决定送给谁。
13. 作为从家人邀请或礼物卡进入的用户，我希望先完成原来的接受操作，以便保持当前流程连贯。
14. 作为购买者，我希望选好赠礼关系和书名再创建故事书，以便付款时无需决定主人公。
15. 作为购买者，我希望送给自己后直接进入故事书，送给他人时填写收礼手机号并发卡，以便完成不同赠礼用途。
16. 作为购买者，我希望中断后继续同一份礼物，重复操作只得到原故事书，以便可靠恢复。
17. 作为超级管理员或原录入销售，我希望在权限范围内更正尚未建书记录的手机号，以便礼物归到正确账号。
18. 作为超级管理员或原录入销售，我希望在权限范围内因录入错误作废尚未建书的礼物并保留记录，以便停止错误发放。
19. 作为购买者，我希望礼物长期有效，销售账号撤销后仍能使用已录入礼物，以便自行安排送礼时间。

## Implementation Decisions

### 账号与权限

- 现有飞书白名单内的有效身份登录后具有超级管理员角色。现有企业、应用和白名单校验继续用于确认身份。超级管理员可访问现有后台业务以及第三方账号管理、渠道录入、查询、更正与作废。
- 后台登录页提供飞书登录和第三方用户名密码登录。第三方成功后进入「录入订单」，可以提交及查看本人录入记录，并更正／作废本人尚未建书的记录。访问全量订单、其他录入人的记录、用户、生产单、账号管理和其他用户资料均须由服务端拒绝。
- 超级管理员生成第三方用户名及随机初始密码，可通过弹窗查看密码。新生成或重置的密码加密保存，登录继续使用安全密码哈希。旧账号须重置后才能查看新密码。撤销或删除后，账号及活动会话立即失效。删除同时清除凭据并移出列表，保留历史操作人和已录入礼物。
- 复用后台受保护会话、Origin/CSRF、退出、限流及审计机制。超级管理员身份仍受私人资料访问授权约束。
- 本轮采用两个固定角色。第三方查询、更正与作废仅限本人录入的记录，操作在「录入订单」同一业务入口完成。超级管理员可处理全部渠道记录。

### 录入订单

| 信息 | 录入要求与含义 |
| --- | --- |
| 购买者手机号 | 唯一必填业务字段；使用现有账号手机号规范化规则 |
| 原订单号 | 可选参考信息，按字符串原样保存有效文本 |
| 实付金额 | 可选；未填写时记录并显示「未提供」 |
| 付款时间 | 可选；未填写时记录并显示「未提供」 |
| 套餐 | 服务端使用现有固定套餐及录入时快照，默认一份 |
| 内部编号、录入账号、录入时间 | 服务端生成并保存，用于追溯 |

表单没有店铺字段，补充信息可折叠。提交表示销售人员确认该笔购买事实，成功后礼物立即有效。第三方结果展示内部编号、脱敏购买者手机号及录入成功状态，超级管理员详情另可查看关联账号及使用状态。

手机号允许多笔独立录入，可选原订单号作为参考信息。每次明确的新录入生成一个稳定提交标识；双击、重试和丢响应恢复同一次提交复用原记录。原先讨论中的「店铺加订单号」去重方案由此更新。

### 关联、展示与开通

- 渠道记录可先于产品账号存在。已有同号已验证账号立即关联，尚无账号时等待后续同号验证登录。客户端提供的手机号文本不能代替账号验证结果。
- 小程序登录后、恢复账号及进入「我的／我的礼物」时读取真实服务端结果。已有登录会话也能看到后来录入的礼物。账号切换清除前一账号内容。
- 未建书礼物显示套餐名称、待送出状态和可用日期信息。有付款时间时标注购买时间，缺省时标注录入时间；金额缺省显示未提供。该记录只出现在购买者送出类。
- 去送礼进入赠礼关系及书名表单，明确确认后原子创建一个项目和一份首本权益，并锁定购买者归属。打开表单、登录或查看礼物均不提前建书。
- 送给自己时购买者同时为主讲人，同一本书在送出和收到两类显示；送给他人时进入现有收礼手机号及礼物卡流程。
- 建书后的同一礼物行继续显示原项目和送礼状态，避免渠道记录与项目形成两张重复礼物卡。详情和再次点击均恢复原项目或当前礼物卡。
- 原生购买、网页购买及渠道录入的身份、来源、金额和权益记录准确表达各自事实。共享契约变化同步现有消费者，渠道新用户界面范围为后台及小程序。

### 新增提醒

每个账号对每份新关联且有效的待送礼物提醒一次，多份合并为「你有 N 份新礼物待送出」。点击查看进入送出类，稍后返回原页；查看或稍后后持久保存已处理提醒，换设备和重登沿用。邀请、领礼、录音及其他进行中操作完成后，在首页或「我的」等合适入口展示。

「我的」展示真实待送出数量，包含尚未创建项目及已创建但未生成礼物卡的礼物；待领取、已领取、自购已开通和作废项不计入。用户在提醒前已完成送礼或记录被更正、作废时，按当前有效状态更新数量和提示。

### 更正与作废

超级管理员可处理全部渠道记录，第三方可处理本人录入记录。建书前可更正手机号或因录入错误作废，必须填写操作原因，并记录操作人及时间。更正后原账号失去这份待送礼物，新号码按相同规则立即关联或等待注册；新账号可得到一次新增提醒。作废记录保留，已关联购买者查看时显示已作废，停止开通与提醒。

确认创建故事书后锁定购买者归属，录入错误作废操作也限于未建书记录。建书、更正、作废必须在同一持久化记录上协调并发，成功结果只能有一个，失败操作读回真实状态。

### 长期有效

待关联账号和待送礼物均长期有效。第三方账号撤销只终止该账号后台访问，已录入礼物及买方账号归属继续有效。

## Testing Decisions

使用已有后台 HTTP／HTTPS 浏览器和小程序页面入口验证公开行为。数据库唯一性、注册关联、提交重试、建书与更正作废并发使用真实 PostgreSQL／Redis。沿用现有后台会话、账号同号解析、项目礼物分类、指定领取及支付单次交付的验证方式。

每票运行其受影响的定向测试、类型检查及必要构建。后台验证实际角色菜单和越权直连拒绝；小程序验证首次登录、已登录后新增、提醒处理、送礼／自购与中断恢复。真机手机号授权、分享及目标环境登录另记实际结果。已通过且未受影响的检查复用，遵守仓库必要 CI。

## Out of Scope

本轮边界排除第三方小店 API 自动拉单与支付接入、渠道退款登记及权益联动、小程序「找不到已购礼物」入口、批量导入、第三方跨录入人订单或用户查询、自助账号注册／找回密码、通用角色权限配置、按礼物有效期收费或续期。订单疑问通过原销售渠道人工核查。
