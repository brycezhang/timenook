# [后台 B01] Vben 入口与订单查询备注

GitHub：[#151](https://github.com/brycezhang/timenook/issues/151) · Parent：[#150](https://github.com/brycezhang/timenook/issues/150) · ready-for-agent

## What to build

运营使用飞书进入完整 Vben 应用，默认打开订单，通过搜索/分页找到记录，查看关联用户/项目/生产信息并追加备注。交付真实可用的订单流程，同时建立三个业务入口及详情路由；后续票补齐用户/生产操作，无权限或尚未交付页面须有明确反馈。

## Acceptance criteria

- [ ] 实际接入 Vben 认证/主布局、权限菜单、面包屑、多标签页及通用组件，只有订单、用户、生产单三个一级入口；移除配置、运维、任务和独立工单页面入口。
- [ ] 飞书白名单、Cookie/CSRF、会话及审计沿用；登录回跳只接受应用内允许目标；嵌套 URL 刷新、浏览器前进后退、403/404、退出及窄屏布局正常。
- [ ] 管理员可按订单号、购买账号/项目及适用状态搜索、稳定分页；超过旧最近记录上限仍能找到，服务端校验范围/页长/权限。
- [ ] 订单详情显示标价、实际收款、付款/退款事实、权益和关联资源，受控验收订单明确标识；不提供人工开单、改价或标记付款。
- [ ] 订单内部备注采用追加记录，保留操作人和时间；重复提交不重复记，越权与失效请求拒绝；显示本单操作历史。
- [ ] 搜索、详情、关联导航及返回位置有一致加载/空态/失败/冲突反馈；私人状态退出/失权后清理，晚到响应不能回填。
- [ ] 浏览器联通实际 API 验证上述行为和受限账号；不新建商品/运维/审计产品，既有受控任务与审计后台能力继续运行。

## 验证与交付

以 HTTPS 后台浏览器联通实际管理 HTTP 验证公开行为；锁、唯一性、重复操作和重启使用真实 PostgreSQL/Redis，仅外部供应商网络可隔离替换。复用既有相关范例，完成定向回归、类型、构建、独立 Standards/Spec、最终 PR CI 及合并后 main CI。读取最新主分支的已有业务/支付/内部验收交付证据，核实实际装配；代码存在或替身通过不代表正式可用。真实账号、资金、设备、供应商和实物结果单独记录。

开发直接硬更新，按需重建数据/夹具；不做旧开发数据迁移、历史兼容、备份准备、旧库恢复或回滚演练。禁止私密样本和凭据进入 Git。

## 工程依赖

无新增票阻塞；消费已交付飞书登录、固定套餐/普通商户及管理鉴权。
