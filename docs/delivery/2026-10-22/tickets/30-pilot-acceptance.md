# T30 · 完成内部实物闭环与付费试点验收

GitHub：[#31](https://github.com/brycezhang/timenook/issues/31) · 状态以 GitHub 为准。
阶段：S5

## 交付结果

以一份真实内部项目走完付款、讲述、确认、实体书、原声和资料权利，再按门槛开放 30–50 个付费项目。

## 验收条件

- [ ] A01–A24/X01–X06 逐项关联前序责任票证据，覆盖期限、换绑、文件标识及路径，区分模拟、真实供应商、真机与实物；按[证据复用规则](../spec.md#验收复用与唯一归属)只补缺口和不适用部分。
- [ ] 核实 D01–D10、平台审核、双端收退款/发货、授权渠道、费用/质量证据与 T29 正式环境齐全，采用一份冻结首版政策；证据缺失不开试点。
- [ ] 以同一内部项目验证付款至实体交付的衔接，印厂文件与双方确认 PDF hash 一致、实物全文/照片/原声码可用；复用资料权利和售后机制证据，确认导出/撤回/删除/退款/质量工单在整体流程中可执行。
- [ ] 试点分批开放，记录完成并生成一本书、购买/参与/保存/确认/交付漏斗及人工耗时；未通过门槛保持关闭销售。
- [ ] 按[质量目标](../spec.md#质量目标与证据归属)完成目标讲述者双端可读性与开始录音试用，记录设备/微信版本、协助方式、原始计时及未完成原因。
- [ ] 按[质量目标](../spec.md#质量目标与证据归属)预先记录样本规模/口音/设备/网络及排除规则，实测端到端出稿；报告原始分母、成功/失败/人工接管/未终态数量与耗时，不排除失败凑达标。
- [ ] 未达质量目标时记录差距、整改或经确认的目标调整再决定试点；内部目标不写成供应商 SLA 或销售承诺，实际售卖仍需明确授权。

## 实现边界

汇总前序适用证据，并以同一内部项目验证跨步骤衔接、真实用户与实体交付；缺口或变更补验，不要求全部票重跑。记录人工耗时与成本，质量目标按父规格统一口径执行。

## 测试决策

- 覆盖模块：完整业务链、目标用户与实物。
- 主入口：真实项目端到端 + 双端用户试用 + 纸书/资料核验；本票真实验收不使用供应商替身。既有自动测试用于准备及回归，不代替本票证据。
- 现有范例：[book.test.mjs](../../../../tests/print-probe/book.test.mjs)、[access.spec.mjs](../../../../tests/admin/access.spec.mjs)、[recorder.test.ts](../../../../tests/recorder.test.ts)；仅作测试方式参考。
