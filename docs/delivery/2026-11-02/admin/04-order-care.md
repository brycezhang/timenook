# [后台 B04] 在订单详情处理退款与质量售后

GitHub：[#154](https://github.com/brycezhang/timenook/issues/154) · Parent：[#150](https://github.com/brycezhang/timenook/issues/150) · ready-for-agent

## What to build

客服从订单待处理筛选发现已有退款/质量申请，在订单详情核对生产事实、执行适用退款或质量救济，进入关联生产单处理原单重印，再返回同一申请。

## Acceptance criteria

- [ ] 订单列表待处理筛选能发现已有退款/质量申请，详情显示关联申请、当前处理人/进度/证据和当前状态可做动作，无独立工单菜单。
- [ ] 退款审批/拒绝、生产核实、执行及查单复用现有用例；金额按实际收款及原政策，未知资金保持预留，不用手工改状态冒充退款成功。
- [ ] 生产未知交接及取消事实必须核实；退款冻结/取消与生产单完成印制、发货状态一致，重复动作和并发不重复退款或交接。
- [ ] 质量方案在原订单处理，原文件重印与改稿重新确认区分；只增加原单制作记录，不新增购买或首本权益，可跳转生产单并返回原申请。
- [ ] 私人 PDF/证据依当前限时授权取得，失权/退出停止访问；订单备注与处理历史准确关联，退款不自动删除资料。
- [ ] 适用原单售后窗口和人工时限继续执行；不新增代客退款/质量受理、自动批准或独立售后平台。
- [ ] HTTPS 浏览器联通实际 HTTP 完成退款和质量两条受控完整流程，验证重复/未知/拒绝边界；复用适用的既有真实 1 分退款证据，新增实际资金、重印实物结果分别记录。

## 验证与交付

以 HTTPS 后台浏览器联通实际管理 HTTP 验证公开行为；锁、唯一性、重复操作和重启使用真实 PostgreSQL/Redis，仅外部供应商网络可隔离替换。复用既有相关范例，完成定向回归、类型、构建、独立 Standards/Spec、最终 PR CI 及合并后 main CI。读取最新主分支的已有业务/支付/内部验收交付证据，核实实际装配；代码存在或替身通过不代表正式可用。真实账号、资金、设备、供应商和实物结果单独记录。

开发直接硬更新，按需重建数据/夹具；不做旧开发数据迁移、历史兼容、备份准备、旧库恢复或回滚演练。禁止私密样本和凭据进入 Git。
