# 购买时不收集配送信息

2026-11-06 用户要求：购买流程删除「选择配送地区」，仅在成书发货阶段填写配送地址。

## 当前规则与实现

- 购买确认页移除地区选择、页面地区状态和按钮的地区必填条件；下单请求不再携带 `shippingRegionCode`，下单失败提示也不再要求核对地区。
- API 的创建订单契约移除该字段及付款前地区校验；订单模型删除地区列，迁移为 `20261106100000_defer_shipping_address`。相关支付、项目和后台测试夹具同步使用新契约，无旧开发版本兼容分支。
- 成书后沿用「我的书 → 印刷 → 填写地址 → 提交印刷」流程。地址仍核验收件人、手机号、详细地址及套餐支持地区；没有有效地址不能提交印刷，订单付款及首本权益校验继续保留。
- 小程序使用条款、套餐配送文案、售卖条款草案及当前业务流程同步收集时点。支持的配送范围没有因此扩大。

## 工程验证

- 18 项前端定向回归通过，覆盖购买页无地区控件、可购买状态不依赖地区、下单不携带地区、付款取消后原单恢复、账号切换及未知订单恢复。
- 46 项 API 定向测试通过（真实本机 PostgreSQL/Redis，外部微信支付为合成供应商）：覆盖无配送信息的普通 999 元及受控 1 分下单、支付幂等与恢复、套餐条款、地址权限及不支持地区拒绝、无有效地址阻止印刷。
- 前端类型检查、共享契约构建、API 测试编译和正式构建、后台类型检查通过；29 页正式小程序构建和官方 WXML/WXSS 编译通过。
- 官方开发者工具加载正式构建后，实际进入「妈妈的一生」购买确认页；页面没有地区选择器（`picker` 查询为空），截图核对合计后直接展示使用条款与客服。当前套餐未开放，因此购买按钮仍按实际资格禁用。截图：`/Users/bryce/.codex/visualizations/2026/11/06/01a1af0d-8040-7520-a646-2de51d5416e7/purchase-without-shipping.png`。首次导航因刷新后已回首页、前置等待的 `.s-page` 不存在而超时；读取实际页面后正常导航通过。

## 运行与发布边界

本轮只修改和验证本地工程，没有执行云端数据库迁移、部署后端、上传小程序、手机预览推送或微信提审。手机旧包与现有后端不会因本地修改自动更新。更新运行环境时需同步部署 API/迁移及小程序新包；真实支付、真机填写地址与实物寄送不记为本轮已验收。

后续同日随[临时支付开放](open-one-fen-checkout.md)完成部署：`20261106100000_defer_shipping_address` 已应用到云端，实际无地区下单和微信 1 分预支付通过；594,315 字节新小程序预览已推送。原未付款核验单已关闭，无扣款或新项目。此项补记覆盖上段「尚未部署/预览」的历史状态；真机地址及实物寄送仍待实际验收。
