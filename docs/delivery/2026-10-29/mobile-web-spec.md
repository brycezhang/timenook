# 网页与小程序统一分步讲述：内部功能验收规格

日期：2026-10-29。状态：用户已确认两端统一分步流程、保留现有业务规则及内部验收范围；按六票推进，工程与实际运行结果分别记录。

## Problem Statement

独立微信小程序尚未申请完成，现有浏览器演示无法让发起人与讲述者在同一个真实后端项目中连续验收录音、保存、转写、整理和成书。现有工程测试、独立供应商探针与可人工使用的产品入口需要接通。

用户要求开发手机优先网页端，与营销落地页同域名 `sgl.wootoon.cn`；网页登录与小程序共用账号和项目；录制体验参考 Remento 的网页分步流程，小程序与网页同步采用该交互。用户已确认首版用于内部功能验收，账号可简化，暂不要求网页真实收款。

## Solution

保留根路径营销落地页，新增 `/app/` 产品入口。内测参与者通过预建账号的内部验收登录链接进入自己的项目，发起人与讲述者分别操作，运营沿用既有后台。网页登录映射到与小程序相同的内部用户；小程序取得真实 AppID 后，通过经验证的显式绑定读取同一份项目资料。

录制以单题分步呈现：选题或照片 → 准备与授权 → 录制／暂停／继续 → 回听、重录或提交 → 保存和处理进度 → 可选追问或整理故事。真实内容链路推进到故事确认和确定 PDF 下载；公开销售、小程序真机验证和线下实物验收分别处理。

## User Stories

1. 作为内测参与者，我希望手机链接直接打开网页，以便无需安装或等待小程序。
2. 作为访客，我希望原有落地页继续可用，以便了解产品后进入明确标注的内测入口。
3. 作为参与者，我希望通过验收期间不按时间到期的登录链接进入固定账号，以便不需要新建密码或等待短信／邮箱服务接入。
4. 作为参与者，我希望链接使用过或被撤销时得到清楚提示，以便重新取得有效入口。
5. 作为参与者，我希望恢复会话、退出和切换账号时保持资料隔离，以便不会看到上一位参与者的内容。
6. 作为参与者，我希望网页与小程序绑定同一产品账号，以便项目、故事、原声和确认状态互通。
7. 作为参与者，我希望绑定前明确核对目标账号，以便不误绑定或合并别人的资料。
8. 作为发起人，我希望进入明确标注的内测项目，以便验收业务而不产生真实付款或印制义务。
9. 作为发起人，我希望发送项目邀请链接，以便讲述者使用自己的账号参与。
10. 作为讲述者，我希望分别理解并决定采集、AI 处理、共享和入书用途，以便保留本人选择权。
11. 作为双方参与者，我希望编辑项目大纲及未来问题，以便安排合适的讲述顺序。
12. 作为讲述者，我希望从一个问题、照片或自己的回忆开始，以便不用填写完整问卷才开讲。
13. 作为讲述者，我希望录制前看清当前问题及设备权限提示，以便知道将记录什么。
14. 作为讲述者，我希望在单题页面录音、暂停和继续，以便从容组织语言。
15. 作为讲述者，我希望停录后先回听、选择重录或提交，以便控制提交内容。
16. 作为讲述者，我希望重录前明确确认并保留尚未替换的录音，以便避免误操作丢失素材。
17. 作为讲述者，我希望看到本机保存、上传、云端封存和转写分别处于什么状态，以便知道是否可以离开。
18. 作为讲述者，我希望网络失败后继续上传原录音，以便无需重录或重复创建故事。
19. 作为讲述者，我希望重进页面后恢复可恢复的录音与任务，以便继续完成讲述；无法恢复时得到真实说明。
20. 作为讲述者，我希望获得一条可选追问并能跳过，以便自行决定补充深度。
21. 作为讲述者，我希望所有已选片段转写完成后再整理故事，以便文稿不会漏掉还在处理的录音。
22. 作为讲述者，我希望核对原声、转录和整理稿，修改后确认确定版本，以便纠正识别和整理错误。
23. 作为讲述者，我希望内容确认与允许入书分别表达，以便事实核对不自动变成印刷授权。
24. 作为双方参与者，我希望生成、浏览和下载同一版本的 PDF，以便检查目录、文字和照片。
25. 作为双方参与者，我希望改稿使受影响的旧确认失效，以便不会误用旧稿制作。
26. 作为运营，我希望在既有权限与授权范围内查看项目进度和取得确定 PDF，以便衔接人工处理。
27. 作为参与者，我希望网页继续遵守撤回、删除及失权后的访问停止，以便增加新入口不扩大资料权限。
28. 作为验收负责人，我希望每项结果注明真实服务、模拟条件及未验部分，以便知道系统真正验证到了哪里。

## Implementation Decisions

- 两端共用分步讲述状态与用户可见规则：选择起点、录前准备、录制（暂停／继续）、回听与提交、保存／处理／可选追问、故事核对确认。仅平台权限、文件和登录适配不同。小程序现有 live 采访页同步改造，不能仅改网页；demo 模式继续明确显示示例内容。
- 现有可选追问仍由用户按需发起，不改成自动强制追问；故事仍在所有选定片段正式转写就绪后按需整理，录制时不提供实时字幕。
- 网页为独立构建和部署的手机优先应用，位于既有 Monorepo，与营销站、管理端分别组织。复用现有页面设计、业务状态和契约；浏览器与微信的登录、录音、文件、导航能力在明确适配层实现。
- 根路径保留营销站，产品使用 `/app/`。网页 API 使用同源代理到现有 TimeNook 服务；管理端、支付通知与小程序既有 API 入口保持各自用途。网页深链刷新及静态资源缓存分别配置。
- 内测账号由受控命令创建并签发一次性登录链接，服务端保存凭据摘要和用途。2026-10-30 用户确认验收期间不要过期；显式内部验收模式下，链接在消费或撤销前持续有效，以 URL fragment 携带票据，经用户明确操作 POST 兑换，避免预取消耗；兑换后清除地址栏票据，建立可撤销会话。登录凭据不进入请求日志、分析、引用来源或公开截图。链接不是项目邀请，也不替代讲述者授权。
- 网页会话使用同源 HttpOnly、Secure、SameSite Cookie，内部验收模式下不按时间过期，已有有效会话恢复时升级，Cookie 随恢复刷新；状态变更检查来源及 CSRF。小程序保留独立 Bearer 会话，两种会话解析至同一内部用户和业务授权。链接续发与退出遵循独立撤销规则，不形成公开换取任意用户会话的接口。
- 内部用户是账号互通的稳定主体。微信身份经服务端验证后显式绑定；并发兑换、重复绑定、身份已属于其他用户时保持唯一归属并拒绝错误绑定。首版不自动合并两个已有账号或按昵称匹配。
- 内测账号只承担受控参与者身份，不向公众开放自选任意用户的登录入口。AppID 未配置时明确显示绑定暂不可用；本地协议测试与将来真实双端验证分别留证。
- 内测项目需要可审计的创建来源与明确标识，不伪造真实支付事实；项目准备仍建立真实业务所需的大纲、主体、参与关系、条款和测试额度。公共购买路径继续遵循现有售卖门槛。
- 当前订单具有微信身份外键，内测项目不得通过伪造微信身份适配该约束。实现须明确无付款项目的服务权限来源；网页本人参与记录其实际登录渠道与主体、操作人和证据，不冒记为微信本人操作。
- 现有产品模块含隔离合成配置限制。增加显式受控内测装配，接通真实私有存储、ASR、整理、Worker 和 PDF；保留确定性的隔离测试入口。不能通过把公开服务标成测试环境或删除原有保护来装配。
- 录制沿用保存后文件转写的顺序。暂停与继续保留同一录制意图和实际问题；停止后进入回听提交步骤；重录的删除／替换边界显式确认。浏览器实际生成的音频按真实类型检查、解码和适配，不通过改扩展名伪装格式。
- 本机草稿按账号、项目和实际问题隔离并尽早持久化；上传完成以服务端封存结果为准。退出、失权、录音中切页及恢复失败均有明确处理。不能承诺系统强杀后的全部内存片段必然恢复。
- 任务与版本复用现有后端约束：同一输入重试、迟到结果隔离、所有片段就绪才整理、原声不随改稿覆盖、双方确认同一书稿。
- Remento 仅作为流程参考。本项目保留音频为主、可选追问、讲述者本人授权与确定版本确认；不因此增加视频、周邮件推送、多人评论或自动入书。
- 采用已确认的长期服务方案，网页不显示制作／回听／下载到期倒计时；相关后端门槛也须按最新方案对齐。验收账号与会话按上述内部模式持续有效，私人文件访问授权仍保持独立限时。
- 既有后台重构及长期服务计划属于同时进行的工作，实施须复核最新工程依赖，避免重复实现或混入其未提交改动。

## Testing Decisions

- 以两个隔离浏览器上下文经公开网页／HTTP 接口操作同一项目作为主验收路径；无关账号作为拒绝访问对照。覆盖登录、邀请、授权、录制、保存、整理、确认和 PDF。
- 数据唯一性、登录链接并发兑换、身份绑定、任务重复提交与恢复使用真实 PostgreSQL／Redis 验证；测试只替换外部微信、AI 网络与可控媒体输入。
- 验证常规模式的登录链接过期、内部模式持续登录、重放／撤销和会话退出、跨账号缓存清理、绑定冲突、CSRF 与同源行为；不通过直接写浏览器凭据跳过待验登录路径。
- 用真实浏览器录制接口和明确标注的合成音频验证暂停、回听、重录、持久化、上传和转写；人工手机录音与锁屏／切后台另留设备证据。
- 对真实服务做单独受控合成样本验收，记录存储对象、原声摘要、任务状态、转录、整理稿与最终 PDF；不把替身返回文字当作实际 AI 效果。
- 重点故障点包括：停录后刷新、上传中断、封存成功响应丢失、Worker 重启、处理结果迟到、改稿后旧确认、撤权后的原声和 PDF 访问。
- 两端共享录制状态转换和保存门槛测试；小程序使用官方编译器和页面行为测试验证，真实微信设备、账号及邀请验证保持未完成直至条件具备。网页人工验收不替代原生设备结果。
- 手机覆盖窄屏、标准屏、较大屏，检查触控、键盘遮挡、滚动、权限错误及无横向溢出；桌面验证可用性。Safari／Chrome 的实际设备差异按设备记录，不用桌面模拟追认真机结果。
- PDF 检查实际文件的全文、照片、目录、页数和确定版本；内测 PDF 不被标为已通过印厂实物验收。
- 按最新 [AGENTS.md](../../../AGENTS.md) 执行功能优先、相关定向检查和必要合并 CI；不额外强制逐条 RED/GREEN、双轴/多轮审查或等待 main CI 后再开发下游。真实微信、资金及实物结果继续由对应责任票记录。

## Out of Scope

- 公开注册、网页真实收退款、开放销售和真实生产交接。
- 小程序申请、平台认证、在无 AppID 时声称已完成微信真实互通。
- 视频录制、多人家庭空间、Remento 的邮件／短信提醒系统。
- 将现有后台整体重构纳入本规格，或重写已经交付的业务规则。

## Further Notes

- 本规格的“账号互通”是同一个内部用户与同一项目资料，不是网页与微信共享浏览器 Cookie，也不是复制两份项目。
- 本规格的“分页录制”是按步骤呈现单题录制与提交，不是长问卷分页后整批上传。
