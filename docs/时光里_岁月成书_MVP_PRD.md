## 1 产品定位与目标

### 1.1 用户问题

用户希望记录自己或亲友的经历、了解家人的故事，并制作一份有个人意义的礼物。主讲人未必习惯打字或写长文，因此语音是主要输入；家人可以提供文字问题、协助录音、编辑和安排制作。

一个项目围绕一位主讲人的第一人称经历。实际操作设备的人可以是其他成员，不因此成为书中主人公。内容属于项目成员私密协作范围，不是公共阅读或社交平台。

### 1.2 主要场景

| 场景 | 产品路径 |
| --- | --- |
| 送给爸爸、妈妈、爷爷、奶奶或其他亲友 | 购买后指定手机号，收礼人验证并明确领取，同一本书内持续记录 |
| 送给自己 | 统一送礼入口选“自己”，付款后直入故事书 |
| 家人共同回忆 | 购买者邀请家人，家人文字提问，语音回答形成故事 |
| 看照片讲往事 | 项目中先添加照片或录音时关联照片，讲述后继续补充 |

赠礼关系可自定义，关系不改变价格、权限或默认大纲。本人自购属于本版范围；未成年人、逝者纪念、多主人公合著仍不因增加称呼而自动开放。

### 1.3 MVP 目标

验证 999 元付费意愿、低门槛首次与持续讲述，以及从真实素材到可制作书稿和实体交付的完整路径。北极星指标为完成实体交付且用户确认满意的付费项目数；满意度反馈不作为产品中的逐篇内容确认门槛。

### 2.1 范围边界

不增加语音祝福、赠礼留言、付款后可选准备、独立首讲引导或独立“给自己做一本”入口。家人提问仅文字输入，回答以语音为主；不新增语音提问及问题朗读。

不增加公共评论点赞、共同家庭史、多主人公、实时字幕、实时语音通话、视频、声音克隆、多文风／多模板、自由排版、独立电子书阅读器、加印购买、订阅提醒、自动供应商与物流接口。现有可选 AI 追问与逐段原声选择不作为新版主流程必经步骤，也不因画布未单列而删除已有后台数据能力。

## 3 角色与权限

| 角色／身份 | 权限与入口 |
| --- | --- |
| 购买者／送礼人 | 购买及查询本人订单，领取前设置收礼号码与重发卡片，邀请普通家人；同时是项目成员 |
| 收礼人／主讲人 | 匹配已验证手机号并明确领取后成为成员；是书中主人公 |
| 送给自己 | 当前账号同时是购买者与主讲人，付款后直接加入；送出与收到两类打开同一本书 |
| 已加入家人 | 接受普通邀请后成为成员；从“我参与的”进入，不视为指定收礼人 |
| 所有项目成员 | 记录、回听、照片、编辑、问题、大纲、书稿、地址及提交制作；实际权益和项目状态继续校验 |
| 未加入用户 | 可查看公开介绍或邀请／礼物公开信息，不能读取私人故事、照片及原声 |
| 平台运营 | 既有后台处理权限，与用户项目成员权限分开；私密资料按必要授权处理 |

只有购买者发起家人邀请。普通家人填写“你是主讲人的谁”，购买者首次提问缺关系时补填；关系不决定权限，也不从购买时的“爸爸／爷爷”等赠礼关系反推。已回答或被他人编辑的问题仍保留原提问人。

登录与邀请接受保留当前条款版本及接受事实；取消原双角色审批、同机协助授权页、用途选择、逐篇本人确认、逐页核对和双方印刷确认门槛。资料权利处理及私密访问约束按现行条款与 ADR 0018 执行。

## 4 用户流程

完整流程图、异常状态与返回规则以[业务流程](../designs/timenook-modern-2026-11-10/project/BUSINESS-FLOW.md)为准。

### 4.1 购买、送礼与自购

首页／我的“送出一份礼物” → 原地登录（如需） → 必选赠礼关系并填写书名 → 确认购买 → 微信付款。

送给他人：支付经服务端确认 → 建立项目和首本权益 → 指定收礼人微信绑定手机号 → 分享电子礼物卡 → 收礼人验证匹配 → 明确领取 → 已领取 → 进入故事书首页。验证本身不自动领取；领取前改号码重发使旧卡失效，领取后不能修改；原领取者重开有效卡进入原书。

送给自己：关系选“自己” → 服务端确认支付 → 绑定当前账号为主讲人 → 直接进入故事书。无需填写收礼号码、分享或领取。

付款未知先查原单，不重复创建。待付款从“我送出的”恢复；普通家人邀请与专属礼物领取分别记录，不能相互替代。

### 4.2 进入故事书与开始讲述

首页问题卡展示家人题或大纲题，“开始讲述”与问题同卡滚动 → 讲述准备 → 点击麦克风开始录音。首次与后续讲述共用此路径，不新增首讲页，也不要求先设置大纲或再次确认选题。

首页故事数进入故事列表，照片数进入照片列表，书名／赠礼副标题／封面整块进入书稿；零数量仍可进入空态。家人提问独立入口保留；“换一个”混合换题，“从大纲目录选题”主动选题。

### 4.3 家人提问到回答

家人文字填写问题 → 可选章节 → 发布 → 主讲人或协助记录的成员选择问题 → 语音回答 → 保存并整理故事 → 问题显示已回答并关联故事。未选章节的回答先保存为普通故事，可随时归入任一章节；不设成书前必须全部归章的门槛。

### 4.4 成书与收书

故事归章及排序 → 编辑封面 → 生成 PDF → 系统查看器预览 → 填写地址 → 确认使用首本权益制作 → 查看制作与物流。只收录章节引用的故事；空章、未答问题和未归章故事不印。已提交制作使用固定版本，不随以后改稿变化。

## 5 页面与交互

### 5.1 信息架构

顶层只保留“时光故事”“我的”。已有项目默认回到当前故事书；“我的礼物”与切换故事书统一为我送出的／我收到的／我参与的。送给自己的书显示于送出和收到两类，不复制内容。书名副标题使用送礼人昵称与购买时赠礼关系。

“我的”保留昵称修改、我的礼物、送礼入口、当前条款和退出。退款、质量、资料申请继续通过条款内服务方式处理，不恢复独立小程序菜单。

### 5.2 页面组织

[画布索引](../designs/timenook-modern-2026-11-10/project/canvas.json)覆盖首页购买、礼物设置、领取、故事书／礼物、家人问题、语音、故事、大纲、书稿、制作、我的共 11 组。准备／录制／暂停／上传等为可复用页面状态，PDF 画板表示系统文档内容，非自建阅读器。

登录为共用底部弹窗，关闭留在原页；查看条款返回仍能继续原操作。协议未勾选时登录按钮可点击，点击后提示“继续登录表示同意协议”；点击“继续”即确认同意并直接继续微信手机号登录，无需返回勾选或再次点击登录。取消提示不提交同意或登录，已勾选则直接继续登录。礼物验证和接受必须分开。标题说明角色只用于画布，手机导航保留简洁功能标题。

### 5.3 手机交互

- 白色页面、卡片、导航、返回按钮及底部操作区；橄榄绿 `#46563C`、局部浅绿 `#EDF0E7`，系统中文无衬线。
- 基准 390×844，同时覆盖 320px 窄屏、长内容、键盘与安全区。主按钮约 52px，图标按钮至少 44px；不靠缩小字号塞入说明。
- 导航标题不在正文重复；删除无必要的二级说明和重复返回，必要状态、错误、协议与字段标签保留。
- 首页开讲随问题卡滚动。封面、已回答故事、麦克风与开始录音文字均为完整可点击区域。
- 故事／书中原声统一播放暂停、拖动进度条、已播放／总时长；首页总原声分钟四舍五入，非零不足一分钟显示“<1 分钟原声”。
- 首次加载结构化骨架、局部加载反馈；刷新保留已有内容。媒体失败说明实际保存状态与下一步。
- 样例照片与书图标注示意，不能当作真实用户经历或实物品质证据。

## 6 大纲、提问与语音

### 6.1 通用大纲就是目录

一套与赠礼关系无关的模板，初始六章，每章十题：

1. 我的童年
2. 求学与成长
3. 初入社会
4. 亲密关系与家庭
5. 时光转折与重要经历
6. 现在的我与想留下的话

[60 题正文](../designs/timenook-modern-2026-11-10/project/OUTLINE-QUESTION-BANK.md)仍为内容初稿。创建项目复制确定模板，用户可增删、改名、排序章节及调整问题，模板升级不覆盖个人内容。不要求答完或按顺序回答。

大纲与书稿使用同一套章节身份、名称和顺序，章内区分问题与故事；不继续维护两套可独立改名排序的目录。历史实际问法和生成 PDF 保留快照。

### 6.2 家人问题与推荐

家人提问仅手动输入文字，章节可选，从章内发起默认带入并允许取消。首页、问题列表、详情和讲述页统一显示“女儿 · 小雨的提问”，跟随原作者；大纲题显示大纲来源与章节。

首次进入优先待回答家人题；两类足量时约 2 道家人题穿插 1 道大纲题，每类随机、本轮不重复，一类不足由另一类补足。已回答与已跳过不推荐；稍后回答本次略过、再次进入可出现，列表始终能主动回答。全部浏览后可开启新一轮。

问题支持编辑、删除、跳过与恢复。已回答问题可以直接打开关联故事继续讲述；改变已回答问题所属章节时同步移动故事。删除问题不删除回答；删除章节保留故事，家人问题转为未选章节。

### 6.3 录音与保存

语音为主，问题、照片或自由讲述均可开始。准备页可添加、浏览和逐张移除本次照片；录音中添加照片先暂停、保留时长，继续后接着录制。补录沿用同一故事及问题，不展示换题。

单段最长 10 分钟，到时自动保存，同一故事可续录多段；项目累计 6 小时。体验项目照片 40 张、首次整理 30 次、主动重整 30 次、追问 90 次；自拟问题 2,000 字、故事标题 200 字。正式权益仍以生效套餐快照为准，不根据原型样例扩大额度。

结束后自动保存、上传、转写与整理，不要求用户分别封存或提交 ASR。原始录音、转录、正文分开保存；重试不重复新增素材或扣额度。等待可离开，回来恢复；迟到结果或切换项目不能覆盖其他故事。未保存不能虚报云端成功。

### 6.4 故事输出

整理为主讲人第一人称自然叙事，保留模糊时间与不确定事实，不编造人物、年份、地点、对白或经历。照片未知信息允许留空。生成稿保留 AI 整理标识，成员可校对；编辑文字不改动原声。

整理失败仍可回听已经保存的原声并重试；未识别到语音与已识别但未成稿分别处理。现有可选追问不成为录音保存或成稿的必经门槛。

## 7 故事、照片与归章

### 7.1 编辑与回听

故事详情完整展示原声、正文、照片、章节和“继续讲述”；文字校对页只编辑并保存，补录从详情进入。正文、照片或原声清单变化生成新版本；不再要求讲述者本人逐篇确认后才能编辑或入书。

### 7.2 归章与暂不入书

有有效章节的问题回答后归对应章；没有章节、自由讲述或原章已删除时保存为未归章故事。详情、未归章清单和任一章节的“本章故事”均可归章，同一故事同时只属于一章。

“加入本章”用于未入章故事，“移到本章”从原章移出；章内故事可拖动排序。移出引用或删除章节不删除录音和故事。未归章与明确暂不入书是不同状态，均可后续归章；不默认放入第一章，不因仍有未归章故事阻塞已有内容成书。

### 7.3 项目照片与补图

照片数进入项目照片列表；没有故事也能先添加照片，再以照片开始讲述。录音前后均可关联照片和说明，无照片也可完成故事。移除本次照片关联不影响其他故事引用及冻结版本；照片原图、预览与印刷图沿用私有素材访问规则。

## 8 书稿与原声交付

### 8.1 章节与封面

章节名称、顺序和故事归属与大纲共用。书稿按当前章节和章内故事顺序生成；空章与未答题不印。没有任何入章故事时显示空稿，引导讲述或归章，不生成空白 PDF。

点击封面卡片编辑书名、寄语和照片；点击保存才生效，选图返回仍在同次草稿中，直接返回放弃未保存修改。维持一套固定封面和内页模板，不增加自由排版。

### 8.2 PDF 与版本

生成真实 PDF 后展示版本与页数，用微信文档查看器打开完整文件。PDF 目录只读，章节管理是唯一目录编辑功能；不设计小程序自定义翻页或 PDF 内音频播放。

封面、入书正文、图片或顺序修改后重新生成。只改未来问题文字不改历史正文；已生成及已提交制作的版本不会被后续编辑覆盖。取消逐页勾选、手写核对、双方确认要求。

### 8.3 提交制作

当前就绪 PDF、有效地址、实际首本权益和可制作状态满足后，任一项目成员可确认制作。提交后固定 PDF 与地址；未知结果先查询，重复提交不重复生产；已取消需核实后才能修改重提。退款、冻结、内部验收及不具实体权益项目的真实限制继续有效。

### 8.4 原声二维码

每篇有原声的入书故事使用二维码关联所印版本的录音。扫码进入小程序 → 登录（如需）→ 校验项目访问权限 → 回听固定版本，后续改稿不替换原纸书录音。二维码是扫码入口，PDF 不提供直接播放；原声页可独立进入，不依赖返回书稿。

原声是真实录音，文字编辑不生成或篡改声音。未授权访问不展示私人内容；撤回或删除按现行资料规则停止相应访问。设计中的二维码仅为示意，不是上线验收。

### 8.5 数字资料与长期服务

PDF 可预览及按现行服务下载。完整资料包括原声、转录、故事稿、照片、PDF 及关联清单，客服核验后交付，沿用已公示服务范围与时限。

制作、回听、导出申请、下载及支撑资料按 [ADR 0017](adr/0017-lifetime-service-and-retention.md) 长期有效，不增加服务倒计时。会话和临时访问凭证仍限时，授权有效可重新获取；主动撤回、删除与实际外部副本处理分别记录。

## 9 套餐、订单与售后

### 9.1 R01及R02 套餐规则

首版每项政策选择一个已确认规则并形成套餐快照；D02 制作权益与 D03 资料服务统一长期有效，开发阶段按最新方案更新，不保留旧有限服务期规则。其他未确定数值保持待定，人工售后处理遵守已公示政策。后台不提供服务期限配置、暂停计时、恢复计时或到期审核。

**999元一次性套餐**包含一位主讲人的故事书项目、约定额度内录音与整理、固定模板书稿、PDF、原声二维码、完整资料导出服务及一本实体书。

售卖前展示：

- 书籍尺寸、装帧、页数范围和配送地区。
- 制作、回听、下载长期有效及必要资料长期保留，说明本人授权、主动撤回和删除方式。
- 录音、照片与整理额度。
- 生产交付预计、退款及质量售后规则。

约定配送范围内的首本书费与运费已含在999元内，提交印刷不重复收取。不支持地区在付款前告知，套餐外没有额外份数或超页购买入口。

支付以服务端核验为准。取消或失败不授予权益；成功后退出可恢复同一订单、权益和项目，重复回调不重复创建。

### 9.2 R11 生产及物流

使用一种公示尺寸、装帧和页数范围。运营检查生产文件，人工交给供应商并登记阶段和物流单号；供应商只获得生产与配送所需资料。

状态为：提交制作 → 待处理／制作中 → 已完成印制 → 已寄出 → 已交付；取消核实中与已取消分别显示。用户凭物流单号查询快递，生产异常由客服告知处理方式。

预计生产周期从书稿锁定并经运营审核通过后起算，具体工作日数在供应商打样和履约核定后公示。内容积累时间由讲述者节奏决定，不从初次付款日承诺固定一个月成书。

投产前可申请撤回，由客服核实实际生产状态；投产后不直接变更文件或地址。因质量问题返工重印属于原订单售后。

### 9.3 退款与质量售后

首批通过客服受理，运营按付款前公示的政策执行。

| 情形                           | 处理要求                                 |
| ------------------------------ | ---------------------------------------- |
| 未参与或讲述者不愿开始         | 核实订单和使用记录，受理退款             |
| 已使用但未生产                 | 按已公示的服务和实体部分规则处理         |
| 平台故障导致无法交付           | 恢复、补做或退款，不重复收费             |
| 破损、漏页、错版、平台排版错误 | 核对提交制作的版本与生产记录，补寄、重印或退款 |
| 提交制作后发现事实错误             | 受理资料更正，解释已生产实物的处理边界   |

退款金额、申请和处理时限必须明确。退款不静默删除讲述者资料，重复操作不重复退钱，退款与权益及生产状态保持一致。

## 10 状态与一致性规则

| 对象 | 用户可见状态／语义 |
| --- | --- |
| 交易 | 待付款、已付款、结果待查询、已关闭及实际退款状态 |
| 礼物 | 待指定收礼人、待领取、已领取；旧卡失效／手机号不匹配为领取结果 |
| 问题 | 待回答、稍后回答、已跳过、已回答并关联故事 |
| 素材与故事 | 正在保存、上传失败、整理中、整理失败、可阅读故事；保留实际未识别或未成稿状态 |
| 故事归属 | 已归章、未归章、明确暂不入书；不与处理状态混用 |
| 书稿 | 尚未生成、生成中、就绪、内容已变化、生成失败 |
| 制作 | 待处理、制作中、已完成印制、已寄出、已交付、取消核实中／已取消 |

1. 一个付款套餐只创建一个项目和一份首本权益；自购显示两类不复制数据。
2. 专属领礼需匹配已验证手机号并明确接受；普通邀请不授予收礼身份。
3. 主讲人、提问人、录音操作人分别记录；成员关系与赠礼关系独立。
4. 一个项目只有一位主人公，素材、问题和任务不能串项目。
5. 同一故事最多属于一个章节；未归章故事不自动加入第一章，PDF 只收录目录引用。
6. 原声、转录与稿件分别保存；文字编辑不改变录音，已提交制作版本固定。
7. 私人阅读、回听和下载校验当前访问权限；删除／撤回按现行处理规则执行。
8. 保存、支付、生成与制作结果不明先查询原操作，不靠重复创建表示成功。

## 11 隐私、标识与服务准入

通过现行条款及实际采集入口告知用途、服务商、项目成员共享范围、长期保留和资料权利处理方式。内容默认私有，不用于公共模型训练；服务商配置和合同支持该约定。

讲述者可申请更正、导出、撤回和删除。涉及敏感个人信息时按适用规则取得单独同意。删除后停止在线访问，活动数据与备份处理时限公示，交易记录与故事资料分别处理。相关方案按[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)核验。

整理稿注明“根据本人讲述经AI整理”，下载与导出文件带适用标识，真实原声不误标为合成音频。方案按[生成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)及[生成式AI服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)核验。

基础云服务使用阿里云，包括数据库及私有对象存储；文件ASR首选豆包（火山引擎），文本模型首选DeepSeek，用于可选追问和故事整理。按实际使用的服务、用途、地域、数据保留及第三方副本能力进行隐私告知，并核对训练使用、保存和删除条款。

对外服务前检查微信主体、类目、支付路径、iOS与Android适用情况、隐私与录音授权、印刷供应商及实际业务准入。产品交付为私人时光故事书制作，不承诺正式出版发行；制作、回听、下载和必要资料保留按已确认的长期服务方案提供。

## 12 运营与质量要求

### 12.1 R13 运营能力

2026-11-02 MVP 范围收敛：支付无权益、Outbox 滞留、任务费用、错版/访问及工单超时的自动告警，以及跨业务全链路日志串联，不列入 MVP 必需交付，也不作为 #30 的关闭条件。MVP 使用已有健康检查、进程日志、业务状态及必要审计支持人工核查和受控维护；支付幂等/权益一致性、Outbox 恢复、授权检查、确定版本与错版阻止、额度约束和服务时限继续执行。此调整移除运维增强要求，不宣称已实现自动告警或完整追踪。

管理端仅设订单、用户、生产单三个一级菜单，登录默认进入订单；采用 Vben 完整登录/主布局、路由、多标签页、搜索/筛选/分页及详情表单。实际客服申请通过对应订单或用户关联项目处理，待处理筛选覆盖无支付订单项目；不保留独立工单、商品配置、运行/任务或全局审计页面。审计和受控维护能力保留，D06 办理时限继续执行。当前规格见[精简后台 #150](https://github.com/brycezhang/timenook/issues/150)。 固定套餐/关系及默认大纲文案由项目配置和代码版本维护，不提供后台编辑平台；个人计划不随默认文案更新覆盖。人工核验/判断/交接，系统保证权限、资金和版本约束；私人内容处理须有本次明确授权。

处理记录包含操作人、时间、原因与版本。查看用户私密资料须有明确授权，仅供本次必要处理。

### 12.2 质量目标

| 项目       | 验证口径                                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 开始录音   | 讲述者已作为项目成员登录，从项目主页到开始录音目标不超过60秒                                                                                              |
| 素材可靠性 | 弱网、来电、切后台与重试中，已提示云端保存的素材不丢失或串项目                                                                                      |
| 整理时延   | 从录音结束触发自动整理且全部输入已云端保存起，含排队及依赖转写；5分钟以内输入95%在3分钟内成功出稿为内部试点目标；失败/人工接管单列，尚未结束的任务显示处理中 |

| 纸书与原声 | 实物与提交制作的 PDF 一致，纸面二维码可扫且播放正确片段                                                                                                      |

该时延目标须经阿里云实际短片段验证，不作为供应商SLA；等待超出页面预算时允许离开，不能伪写失败或重复提交。字号、耗时和口音效果通过目标讲述者真机验证；方言宣传以实际覆盖和识别效果为依据。
