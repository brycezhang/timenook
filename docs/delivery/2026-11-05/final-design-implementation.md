# 最终设计的小程序实现

2026-11-05，代码已由 `203dbaa` 提交并推送 main；后端与成员迁移已部署，小程序 0.3.0 已上传、未提审，见 [部署记录](deployment.md)。本次以 ADR 0018 和最终设计为准。

## 已实现的用户路径

- 时光故事，底部仅“岁月成书 / 我的”。首页区分未购买和当前项目，支持切换项目；我的提供项目、新购和使用条款。未购买首页保留大图与三个产品介绍，图片容器为 760rpx、最高 54vh，图片等比铺满容器，允许裁剪；购买栏固定在底部 Tab 上方。
- 支付者邀请微信用户，一次接受即成为成员。成员共同记录、修改、生成书稿、填写地址与提交印刷；服务端仍隔离无关用户。登录和接受邀请记录当前条款版本。
- 录音完成本机可靠保存后自动上传，向用户展示上传结果。封存与故事整理任务在同一数据库事务中提交；保留失败恢复、可选追问、未成稿文字、原声播放与入书原声选择。
- 章节列表直接拖动排序，触控区与正文入口分开。点击章节即可编辑正文；本章故事分为已加入和可加入，支持移入、移出与排序。修改保留来源、照片和原声引用。
- 独立书封编辑与照片选择，展示真实封面照片；照片自动上传、说明与顺序可修改。话题管理支持改名、排序、添加和状态恢复。
- 我的书 → 完整 PDF 预览 → 地址 → 提交印刷 → 实际制作进度。沿用 PDF 下载、哈希和大小校验、原生文档查看。取消双方确认与独立制作授权；版本、权益预留、幂等和未知结果查询保留。
- 使用条款内提供微信原生客服按钮。退款、质量、导出和删除不再作为独立用户菜单；后台处理事实保留。生产资料由当前交接负责人读取，无需用户限时授权。

## 验证证据

- 小程序、API 与管理端类型检查通过；28 页正式构建通过。正式构建不会临时复制含开发页的 app.json。
- 139 项定向前端测试通过，覆盖自动上传、故事/照片/原声、章节排序与选择、PDF 文件校验、失效会话清理、无二次确认的提交和未知结果恢复。
- `project-members-simple-flow.test.ts` 使用真实 PostgreSQL/Redis、隔离数据库 schema 和合成供应商：两名受邀成员共同编辑，自动整理与生成真实 PDF，双成员并发提交仅产生一份首本记录；交接负责人直接取得固定 PDF/地址，其他运营人员被拒绝。
- 原生模拟器脚本 `scripts/test-native-design.cjs` 使用可识别的合成 HTTP 数据，检查首页布局、已购首页、章节编辑/故事选择、封面选择、微信客服按钮与原生双 Tab。不能据此宣称真实登录、支付或客服接待通过。

## 验证边界与待处理项

完整旧前端套件首次执行 454 项中 314 通过、140 失败。大量用例仍调用已删除的用途授权、同机协助、双方确认与旧页面方法，另有旧导航断言；不能将本轮定向通过等同于整个 `pnpm check` 已通过。旧流程测试尚需按现行方案更新后才能作为合并门禁使用，本轮没有跳过或删除这些测试。

部署阶段已执行线上成员迁移，上传小程序 0.3.0，并在官方开发者工具通过真实微信登录、项目读取与退出撤销检查。本轮未执行真实微信支付、真人录音、双真机协作、客服后台接待、实际印制或物流。客服按钮已接入；实际客服人员配置与消息接待需要在微信后台/真机验证。上传成功不等于已选为体验版或已正式发布，本轮未提审。
