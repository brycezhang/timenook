# 固定 999 元套餐发布、真实下单与 1 分 E2E

2026-11-02。用户明确授权按 MVP 已定 999 元固定套餐补齐正式发布、展示、下单支付闭环，并使用已连接 Pixel 7 完整验收；随后明确 E2E 实际费用固定 0.01 元，展示仍为 999 元。基线 main `d0a6131`。

## 结果与约定

- 首版只用一套 99900 分/CNY、一位成年讲述者及一位发起人、一个人生项目和一本实体书的不可变套餐，制作/回听/下载/必要资料长期有效。复用既有目录、发布、支付、参与、素材、书稿和退款用例，不新建商城或政策组合系统。
- 商品发布后能读取确定版本、999 元标价与实际条款；生产环境不再无条件禁止发布或固定空版本。普通正式售卖仍须填写真实未定规格/政策，不能将合成材料伪装审批。已确定价格/权益无需再次确认。
- 用户授权的 E2E 为真实微信普通商户支付，实付只能 1 分。它是独立、明确标识的受控支付验收，不是 local-verification/mock payment。服务器开关与验收账号 allowlist 决定资格，不接受客户端金额/任意优惠参数。非验收用户不能取得 1 分价格。
- 套餐标价 99900 与订单实际金额 1 分分开持久化/返回；普通订单实付 99900。微信下单、回调、查单、对账与退款核对实际 amount。退款不得超过实际收到的金额。
- 正式未定商业细项不阻塞受控 1 分工程验收：提供明确 e2e 用途的固定套餐版本和当前验收运行政策；不声称印刷/退款/渠道已获得真实审核。普通正式发布路径支持完整真实参数后发布，不自动向非验收用户开售。
- 支付成功只以经过微信验签/解密且应用、商户、订单、金额一致的服务端事实为准；通知与主动查单复用既有幂等激活。已付验收订单通过真实 PaymentOrder 创建唯一项目、subject、计划、首本权益与长期服务，不伪造 paid，也不在 InternalProjectAdmission 双重挂靠。
- 该付款项目必须能继续本人授权、录音/照片、真实转写/整理、当前版确认、同版 PDF/原声；操作人与本人分别留证。未知生产规格和实物不冒充通过。
- 原生套餐页显示 999 元；具备服务端资格的验收操作走实付 0.01 元，微信确认金额及订单实付须如实表达。订单可恢复、取消/未知结果查原单、成功恢复同一项目，不重复扣款或创建。
- 默认正式包继续不携带网页/探针/模拟付款页面。开发演示仅显式 development 构建。
- 真机使用已连接 Pixel 7。支付密码/生物认证由用户完成，不索取或记录秘密；用户已授权本次 0.01 元验收，不为同范围扣款重复询问。

## 取消恢复修复（工程验证）

创建订单后、首次准备支付前退出或断网的原单，可通过既有 `POST /orders/:id/close` 取消。在与支付准备共用的订单行锁内，只有当前仍为 pending 且从未持久化支付提交记录的订单直接关闭；后续准备支付返回 409，不调用微信或产生项目权益。有提交记录（包括外发中的未知结果）继续查验、关闭微信原单，未查明时保持 pending；既有支付竞争和延迟验签付款事实仍按原逻辑恢复。

真实本机 PostgreSQL/Redis、公开 HTTP 与隔离微信协议替身验证：新增取消用例先复现返回 pending（RED），修复后取消/恢复为 closed、后续准备 409 且零微信调用（GREEN）；确定性并发用例在支付已预留、微信尚未接收时发起取消，确认查原单并保持 pending，微信接收后可再次取消。payments 与 fixed-package 定向 21/21 通过，固定外部请求时点后的并发用例单独 1/1 通过；API 类型检查与测试编译通过。本节没有部署或真实收付款结论。
