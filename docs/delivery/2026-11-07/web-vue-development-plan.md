# Vue 正式网页版开发计划

状态：计划草案；已确定 Vue、新设计、排除「状态预览」、短信验证码登录与小程序同手机号账号，以及网页首版支付宝 Page/WAP。支付由 TimeNook 后端调用现有 payment-service，暂不接支付宝系统退款，不修改或移植 payment-service。用户要求保留草案、暂不发布执行票；尚未开始业务实现或部署。

[完整规格草案](web-vue-spec-draft.md)记录用户故事、实现与测试决定；下文给出开发顺序和依赖。

## 交付目标与边界

沿用 2026-11-07 的网页设计，实现手机优先的真实产品路径：公开首页/样书 → 手机号验证码登录 → 同一个产品账号的项目 → 讲述、照片与故事 → 书稿/PDF → 地址、印刷与制作进度。网页新购路径依据本轮支付调研确定，不用模拟付款补齐闭环。

范围为产品网页版，不改营销官网和飞书管理后台。小程序只调整同手机号账号解析及必要的共用业务契约，保留微信原生 UI 与支付。设计提供的侧栏、手机底栏、暖白/棕色 token、封面照片、故事阅读样式继续采用；正式页面中的名称、照片、计数、原声、书稿与进度均来自当前有权访问的真实项目。公共样书使用单独的公开示例资源。

资料用途、退款、质量售后、导出及删除继续由使用条款和客服承载，不恢复旧授权/本人或双方确认菜单，不新增服务期限。当前书稿、版本固定、项目成员、支付幂等与权益规则继续有效。

## 实现基线

- Vue 3 + TypeScript + Vite + Vue Router；与仓库已锁定的 Vue/Vite 版本对齐，按需使用 shadcn-vue 式基础组件，复用小程序颜色 token 和网页语义映射。网页不引入 Vben 后台布局。
- 独立网页视图，按账号、项目、故事、采访/媒体、书稿与制作组织模块；复用现有 NestJS/Fastify、Prisma/PostgreSQL、Redis、Worker、私有 OSS 和共享契约。
- 复用现有 Cookie/CSRF 传输、同源 `/api/v1` 及 `/app/` 部署入口。会话凭据不放进 localStorage/sessionStorage；录音本地恢复数据按账号与项目隔离。
- 从视觉稿提取组件和 token，业务逻辑按真实接口实现。原型的场景开关、示例私人数据和计时器模拟不作为正式业务代码的起点。

### 必须排除的原型内容

「状态预览」、`accountPreview` / `loginOutcome` 等演示账号控制、`?state=guest/empty/member` 账户种子、假登录成功、`mock-session`、`mock-purchases`、假项目/假订单、延时器生成“就绪书稿”等均不进入正式应用及发布包。原型可作为设计资料留在设计目录，不能被产品入口、构建导入或生产路由加载。

真实空态、错误态及加载态必须保留，由服务器会话、权限、实际列表和任务结果触发。测试可以在隔离环境替换供应商网络或设备输入，不向正式应用加入用于跳过认证、伪造项目或支付的开关。最终检查产品依赖图和发布包，并实际验证未登录请求受保护接口会被拒绝；仅删按钮或检查文案不足以验收。

## 手机号账号闭环

已确定的领域决定见 [ADR 0019](../../adr/0019-phone-unified-product-account.md)。

1. 网页输入手机号、明确同意当前条款后请求短信验证码；验证码发送不创建账号、订单或项目。
2. 服务端校验验证码并消费一次性证明，在同一账号解析逻辑中读取或创建规范化手机号对应的产品账号，再签发网页 Cookie 会话。
3. 小程序验证微信 code 和微信手机号授权后，调用同一账号解析逻辑；已有手机号账号直接复用并关联微信身份，不新建另一个账号。
4. 两端以账号 UUID 持有项目、成员、昵称和权益；同手机号登录后的项目由现有成员关系决定，不从手机号直接推断所有权。
5. 先网页、先小程序、同时首次登录必须收敛为同一账号。账号昵称沿用当前已修改值，新账号继续默认「用户」加手机号后四位。
6. 退出网页只撤销相应网页会话；当前页面、媒体引用与迟到请求清理后不能重新显示旧资料。跨标签页账号变化沿用已有会话重验。

首版网页短信按中国大陆 `+86` 规划，内部号码统一规范化，微信手机号证明须保留服务端返回的国家码信息，避免 `138…` / `86138…` / `+86138…` 产生不同归属。国际短信、自助换绑及账号合并不在本轮。开发库若有空号或重复号，应先核对再按新模型处理，不增加旧账号兼容流程；本计划不执行删除或迁移。

### 邀请与加入（已确认）

2026-11-08 用户确认：网页生成的邀请链接留在网页，即使从微信聊天打开，也在网页完成手机号验证码登录并接受邀请；小程序分享在小程序完成手机号授权并接受邀请。已登录时复用当前有效会话，未登录时完成登录后回到原邀请。两端以同一产品账号加入指定项目，不强制跳转到另一端，也不额外要求手动绑定微信。收到链接或仅完成登录不自动加入，仍按现行规则接受有效邀请与条款。

### 短信与登录契约草案

- `POST /api/v1/web/sms-codes`：手机号 → 验证码挑战标识、重发等待及有效期；不暴露账号是否存在。
- `POST /api/v1/web/session`：挑战标识、验证码、当前条款版本 → 既有结构的网页会话、账号资料及 CSRF；替换旧登录链接兑换为正式入口。
- `GET /api/v1/web/session`、`DELETE /api/v1/web/session`：恢复、重验与退出，继续使用受保护 Cookie。
- 项目列表采用现行项目成员/参与契约；不继续沿用旧网页仅“创建人或讲述者”的列表规则。

验证码初始采用 6 位、5 分钟有效、60 秒重发等待、最多 5 次错误、验证成功即失效；同一手机号和来源 IP 共同限制发送，日上限配置在服务端。验证码不进入响应、日志或前端包。供应商失败不得显示已发送或建立会话。

现有共享 auth-service 的短信登录会创建其自己的账号和 token，并无通用 TimeNook 手机号证明接口；不直接把该 token 当作本项目登录态。优先参考 deed 的 NestJS 阿里云 sender，复用短信提供商接入方式，由 TimeNook 自己管理验证码、用途、限流和账号。签名/模板、密钥、实际投递结果另行验收；本轮未发送短信。

## 已确定的首版支付方案

用户已确定网页首版采用 [deed 同方式的支付宝 Page/WAP](../../research/2026-11-08-web-alipay-reuse.md)，由 TimeNook API 调用现有 payment-service，不移植服务、不修改共享服务代码，暂不接支付宝系统退款。[此前微信调研](../../research/2026-11-07-web-wechat-pay-reuse.md)保留为研究依据，网页 Native/H5/公众号 JSAPI 不属于本轮首版交付。商户开通与运行配置仍待实际验收。

网页订单由短信登录的当前 User 持有，支付宝付款账户不改变项目归属。TimeNook 核对本地订单、远端业务关联、金额、币种和渠道；金额由服务端商品及验收配置决定，前端回跳或“支付成功”按钮不作为付款依据，重复确认仅交付一个项目和首本权益。

### 支付宝网页支付

电脑使用 `alipay_page`，手机外部浏览器使用 `alipay_wap`；Vue 提交经服务端校验的支付宝 POST 表单并查询本地订单。微信内不承诺直接调起支付宝，支付路径引导外部浏览器打开并恢复原购买入口；相关设备路径实际验收。

TimeNook 自己创建订单、固定金额并保存买方 User UUID，以独立业务类型和本地订单关联调用 Payment-Service，不接入 deed 的订阅商品、账号或全局登录 token。付款账户不改变项目归属。回跳仅触发服务端核验，重复确认仅创建一个项目和首本权益。已有微信临时 1 分配置不自动扩展到支付宝，支付宝验收实收须在实施时由服务端明确。

按用户后续约束，支付宝首版暂不接系统退款、不修改 payment-service。复用其创建/准备/查账本/关单及表单能力，开发 TimeNook 后端和 Vue：创建接口传自己的业务类型与订单号，prepare 逐单指定回跳地址，支付宝通知保留共享服务入口，无需修改全局回跳配置。内部令牌仅在后端。支付宝订单不进入现有微信退款适配器；已有微信退款和售后业务规则不由本轮改写。

共享服务 GET 读取其账本，不等于每次浏览器查询都实时查支付宝，通知和对账调度实际运行仍须验收。沿用既有服务验证边界，TimeNook 核对本地所有权、业务关联、金额、币种和渠道，本轮不修改共享服务校验。当前购买/确认/关单粗估 2–4 工程日，前提是账号与 Vue 基础就绪、现有支付宝应用和渠道可用；整站、审批等待和实际资金验收另计。退款能力后续另排，首版渠道已确定。

### 与小程序的关系

小程序保留原生微信支付；网页首版使用支付宝，两端按同一产品账号读取项目。登录不创建订单，地址在成书后提交印刷时填写。网页不新增微信收银台或跨端支付订单交接；同号项目共享不依赖把支付宝付款账户关联到微信。

## 验证与上线安排

主验收路径为：同手机号网页验证码登录与小程序授权 → 同 User 及项目 → 网页录音/照片 → 原声、故事编辑、书稿/PDF → 当前版本与地址提交印刷；支付另验支付宝 Page/WAP 付款后两端显示同一项目。身份与支付通过公开 HTTP 边界，页面使用新增的定向浏览器场景验证。

复用当前项目的测试边界：供应商网络和设备输入可在隔离测试替换，真实 PostgreSQL/Redis 继续执行。真机麦克风、iOS Safari 中断/返回、真实短信、实际付款、OSS/ASR 和实物结果分别记录。支付宝退款不列入首版验收，已有微信退款按受影响范围验证。局部检查、类型检查与构建通过后不重复全量。

沿用仓库已配置必要 CI。原退役网页/小程序浏览器模拟套件不恢复为验收门禁；本轮新网页场景使用独立定向命令，是否新增常驻浏览器 CI 不作为本次功能前置任务。保持管理后台和营销官网现有独立验证。

预计为数个独立交付阶段，不把整个网页版积压到最后一次验收：

1. 先交付 WV01–02：能短信登录，并实际看到同手机号小程序项目。
2. 交付 WV03–05：能在网页持续记录、补充照片、编辑真实故事；支付 WV07 可并行。
3. 交付 WV06、WV08：能生成并阅读真实书稿，提交制作与查看履约。
4. WV09 以发布候选补齐实际平台、设备与供应商验收；缺少外部条件时继续交付可实现部分。

不把商户审批时间计为确定开发工期；支付研究给出相对工作量估计。每票实施后记录实际提交、测试、部署与待验项，本文件目前不代表任何业务已实现。
