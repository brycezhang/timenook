## 已实现边界

- 发起人使用自己的真实登录账号操作，同一 project / subject 保持不变；subject 的 boundUserId 可为空。会话明确记录 subject、operator、单一用途、同意/拒绝、告知、当次证据、服务端期限、bindingVersion 和 access_epoch，不创建讲述者微信账号。
- 采集保存、AI 处理、向本项目发起人共享分别选择和留证。会话创建/拒绝校验身份及乐观版本；用途决定递增 access_epoch，已有会话因此失效。续期必须取得新证据；同幂等键重放返回原会话，异载荷冲突。缺失证据、错误用途、非操作人、到期（包括恰好到期）、绑定/epoch 改变和已拒绝的会话均不能授权操作。付款身份不构成单独许可。
- `ProjectServiceTerms.ensureSubjectParticipation` 是可信事务命令：持 project 锁，有首次参与事实就复用其原时间，没有才写 `subject-participation:<subjectId>`。T11 发起人审批、Care 首次绑定/换绑和 T12 同意会话共用此命令；没有放宽 T10 `recordFact` 对不同时间重放的严格冲突规则。
- `authorizeAssisted(tx, command)` 为后续业务所有者提供同事务鉴权。`recordAssistedVersionEvidence(tx, command)` 要求故事或书稿确认用途的有效会话、实际版本 ID/hash、独立当次证据和幂等键；录音许可不能确认故事，故事许可不能确认书稿，不能复用会话起始证据或前一次版本证据。版本/hash 改变不继承旧证据，业务事务回滚时证据一并回滚。
- 当前没有 T19 故事或 T22 书稿实体；本票没有建立产品版本表/注册系统，没有客户端自报版本的确认 HTTP，也没有独立预检 HTTP 授权。内容所有者必须先读取并验证自己的实际版本/hash，再在同一事务中记录证据及业务确认。测试使用明确 synthetic 内容所有者夹具；不能据此声称真实故事/书稿已确认。
- Care 沿用共享核验骨架支持无微信本人的撤回、完整资料导出、删除申请，以及 sourceBindingVersion=0 的首次本人微信绑定。产品端代录保留 requesterSubjectId 与真实 product operator；管理员代录保留 requesterSubjectId 与真实 admin operator，无微信本人 requesterId 为 null。本人不是付款用户或管理员账号。
- 客服代录、查询、核验继续要求既有 MFA、care:write、CSRF 和事务审计。核验验证来源绑定/访问版本与工单，重放不重复执行。撤回同事务写入三用途拒绝、真实 operatorAdminId、epoch 和核验证据；当前权限立即停止。撤回请求保持 `verified`，表示当前访问已撤销且后续联动待处理。导出/删除也仅 `verified`、`pending-consumer`，未冒充文件交付或删除执行；T24/T25/T26 继续负责后续联动和履约。
- Care 首次本人账号绑定复用 T11 受控 rebind 命令，保持同一 subject 与历史，撤销既有 epoch，新账号重新选择用途，服务起点不重置。已有 T11 账号绑定/换绑及其他项目权限回归保持通过。
- 小程序增加实际 `assisted` 页面，使用实际 SessionClient / wx.request，支持正常同意/拒绝、等待、错误、过期、重查与权利申请恢复。welcome 提供同机入口和首次本人绑定入口，并准确恢复各类工单及 `verified` 状态。管理端提供最小代录和核验表单；新申请清空前次证据输入。没有接入实际录音、导出包或删除任务。

## 公开入口

HTTP 前缀 `/v1`；协助状态只提供会话事实，不授予后续内容操作。

| 入口                                                  | 行为                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------- |
| `POST/GET /projects/:id/assisted-sessions`            | 登录发起人为同一真实 subject 记录当次单用途同意/拒绝及查询恢复              |
| `POST/GET /projects/:id/care-requests`                | 两角色代录或查询本人绑定、撤回、导出、删除申请；申请不等于核验              |
| `POST /admin/projects/:id/care-requests`              | 有权客服为实际 subject 代录最小申请，保留 admin actor                       |
| `POST /admin/care-requests/:id/verify`                | 工单、D08 合成证据、来源版本、MFA/CSRF/权限及原子审计核验；撤回停止当前权限 |
| 既有 `GET /admin/care-requests[/:id]`                 | 恢复申请主体、操作人、状态、绑定历史和核验证据                              |
| 既有 `POST /admin/projects/:id/rebind`                | 扩展无微信 source0 首次本人绑定；保持现有换绑边界                           |
| `authorizeAssisted` / `recordAssistedVersionEvidence` | 仅可信内容所有者的事务内公开模块；T14/T19/T22 后续补实际业务 HTTP/素材集成  |

新迁移 `202610230012_assisted_sessions` 增加会话及逐次版本证据，窄扩展 Care 主体、actor、来源 epoch、核验状态和 admin 同意记录。已有迁移未修改。
