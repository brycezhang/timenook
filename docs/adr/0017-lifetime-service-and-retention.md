# 制作、回听、下载及必要资料统一长期有效

用户决定将岁月成书的服务统一为长期有效：可随时发起制作、回听和下载，不设置服务到期限制。支撑这些能力的原声、转录、故事与版本、照片及必要衍生文件、书稿/PDF、已完成资料包和对应关系同步长期保留。此决定替代 D02/D03 中有限制作期、在线访问期、导出申请期、包下载期及按服务期限自动清理的规则，以支持用户按自己的节奏记录、制作和保管资料。

服务期限不再是运营配置：移除后台“服务期限”菜单、暂停计时、恢复计时、到期审核及其业务接口，套餐配置和用户端均不展示可编辑期限或倒计时。领域规则直接表达长期有效；仅在底层接口确实要求填写到期日期时固定使用 `2099-12-31`，该日期不是实际截止日，也不得在到达或超过该日期时拒绝服务、触发删除或要求续期。

长期有效不增加首本数量、内容额度或权限。付款及首本唯一权益、版本确认、本人授权、退款后权益处理、生产未知结果和争议处置继续适用；退款及质量售后的 D07 申请窗口和 D06 人工处理时限独立于服务有效期。客服工单处理退款、质量售后、资料申请、换绑及其他实际服务事项，不再处理服务到期例外。

用户主动撤回和删除按其意愿及核验范围处理，继续执行拒绝访问、终止活动流、停止适用处理、逐层清理及独立台账，拒绝迟到任务重新生成已删除资料。会话、OAuth state、上传/下载临时能力、客服访问私人资料的授权仍有安全有效期；临时能力到期后，仍具备当前权限的用户可重新取得访问能力，不失去长期业务资格。

取消应用、API/Worker 定时器和对象存储生命周期中按业务服务期限删除必要资料的规则。未封存上传、失败/未交付的临时产物、设备缓存和确认为无引用的技术残留仍按用途清理，须验证不会删掉长期服务所需的唯一资料。供应商临时副本及主动删除的执行时限按用途核实，不把长期保留解释为永久保留每一份技术副本。

本次开发重构直接按新模型硬更新，必要时重建相关开发数据和测试夹具；不做旧数据迁移、历史有限期兼容、旧备份/旧台账恢复、备份准备或回滚演练，也不为这些旧开发场景保留测试。新规则下的主动撤回、删除、权限校验及进程重启后的正确行为仍须验证。本文记录已确定方案；本轮方案文档更新不代表业务代码、定时清理、OSS 生命周期或线上环境已经切换。实施与验证计划见[#105 长期服务实施](https://github.com/brycezhang/timenook/issues/105)及[开发说明](../development-lifetime-service.md)。
