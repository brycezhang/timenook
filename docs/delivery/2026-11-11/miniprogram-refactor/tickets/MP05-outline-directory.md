# MP05 · 六章大纲目录与问题管理

状态：ready-for-agent；GitHub [#171](https://github.com/brycezhang/timenook/issues/171)，父规格 [#166](https://github.com/brycezhang/timenook/issues/166)。父规格：[小程序全量重构](../spec.md)。

## 交付结果

新故事书初始化六章六十题，用户在同一目录中编辑章节、问题和章内故事顺序，选题后回答归入对应章节。

对应差异：F09、F14、F17。主责画板：`BookDirectory`、`ChapterOutline`、`QuestionDetail`、`QuestionEdit`、`ChapterEdit`、`ChapterStories`。详见[画板对照表](../DESIGN-MAP.md)。

## 验收条件

- [ ] 使用已确认六章与当前六十题内容初稿，关系不改变模板；项目保留个人修改，不被模板更新覆盖。
- [ ] 大纲与书稿目录共用稳定章节身份、名称和顺序；增删改、整章排序和章内问题/故事均真实持久化。
- [ ] 将当前计划与目录的双份结构直接改为统一模型，同步全部读写及共享消费者；不双写、不回填旧开发数据、不保留旧接口别名。
- [ ] 有有效问题章节时新故事归该章，无章/自由讲述/原章已删除则未归章；删除章或题不删除故事及原声。
- [ ] 同一故事只属一章，章内拖动与跨章移动保持顺序；已回答问题移章时同步故事，故事移动后问题关联展示一致。
- [ ] 同时移除自动第一章归属和 PDF 空目录全收录回退；仅已有入章故事可生成书稿，未答题和空章不生成空白正文。
- [ ] 本票全部主责画板完成设计与原生 UI、交互对照，记录 390px/320px、真实入口、截图与差异处理；不留死入口或用样例数据冒充业务。
- [ ] 实现、相关检查、原生验证及外部待验分别记录，改动与测试只覆盖本票实际边界。

## 数据与契约边界

本票按新方案直接修改相关前后端、共享契约和数据库。开发数据可破坏性重建，不做旧模型兼容、双写或旧接口别名。影响现有网页/后台消费者时同步适配，不扩展视觉范围。

## 测试决策

真实数据库验证目录统一、题→故事归属、删章保留、并发版本校验；复用章节排序和 PDF 内容测试，原生拖动/改名/选题/返回。

复用现有测试入口，优先验证公开行为；数据库约束使用真实 PostgreSQL/Redis。外部待验不视为功能缺失，已实现能力与未验环境分别说明。
