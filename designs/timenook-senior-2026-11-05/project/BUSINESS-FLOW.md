“全部功能”在设计中按同等项目能力处理，受邀成员可使用记录、照片、编辑、成书、地址和印刷，也不再展示角色切换。为自己记录也使用同一项目路径，不再需要把自己申请绑定为另一个角色。

## 正常用户路径

- 新建：未购买首页或我的 → 新购一本书（书名与称呼同页）→ 微信登录（如需）→ 确认购买 → 当前项目。
- 独立登录：首页“已有项目？微信登录”或我的 → 微信登录 → 读取已有项目；不创建购买、不触发支付。新建路径中的登录使用独立页面，成功后继续购买确认。
- 加入：微信邀请 → 接受邀请（未登录时同一按钮完成微信登录）→ 当前项目。无独立登录中转、审核等待与本人核验页面。
- 记录：当前项目 → 录音/暂停继续 → 说完自动上传 → 上传结果。整理在后台完成；用户可继续记录或离开。
- 故事：当前项目 → 已记录的故事 → 正文、照片、原声。新整理故事默认编入章节，可选择不入书，不设置本人确认任务。
- 成书：我的书 → 章节/封面调整 → 生成新版 → 完整预览。章节与已选故事、照片统一使用右侧把手拖动排序；章节名称点击编辑，右侧不再叠加进入箭头。
- 印刷：项目 → 我的书 → 印刷 → 保存地址 → 提交印刷 → 制作/物流。已有地址可直接到提交页。

- 项目切换：首页当前项目 → 切换项目 → 返回新项目首页。我的 → 项目也能进入相同项目。
- 条款：我的/登录/邀请/购买 → 使用条款 → 返回原任务。

2026-11-06 配送信息收集时点：购买确认不选择配送地区、不填写收货地址，下单接口不接收配送地区。成书后提交印刷时再填写并核验收货地址，继续按购买套餐约定的配送范围办理。

## 仍保留的必要状态

2026-11-06 加载反馈：小程序首次读取使用与页面结构对应的动态骨架屏，照片与原声读取使用局部旋转指示，提交操作使用微信按钮内置 `loading`。不以“正在打开…”等纯文字或空白承担加载反馈；已有内容的刷新与后台整理保留当前视图，真实空状态和读取失败在请求结束后显示。实现与模拟器验证见[加载优化记录](../../../docs/delivery/2026-11-06/global-loading.md)。

- 未登录、登录失败、套餐暂未开放、待付款、支付结果待核实、取消购买。
- 邀请失效；正常接受不需要再次审批。
- 录音上传中、成功、失败重试；文字整理中、无可用内容、重试。
- 照片空状态、上传失败、说明与顺序；书封显示已选图片，独立封面选择页沿用可入书故事照片，封面可不用照片。
- 书稿待生成、生成中、失败、内容更新待重生成、就绪。
- 制作已提交、制作中、印好、已发货、已交付、实际取消、提交待核实。
- 未保存编辑离开提示；长文本与当前项目归属。
- 原声未登录/可播放/暂不可用；纸书版本与线上后续改稿分开。

这些是状态变体，不加 Tab，不增加正常操作中的确认步骤。服务端未得到确定结果时不能展示成功；不能通过“刷新”虚构扣款、印制或交付事实。
