# 人工生产交接与物流本地验证

T23 消费 T22 的同版双方确认、确定 PDF/hash、地址与首本权益预留，沿用 T10 的独立制作和资料服务期限。入口与 Book 一起限制在 `environment=test`、`books.mode=synthetic-local`；默认配置和生产不注册这些路由。真实供应商、实际微信发货和实物结果仍由本票验收，首次真实交接须明确授权。

## 操作路径

1. 用户在首本制作提交后打开「生产与物流」，双方读取同一生产单的实际阶段。
2. 具有 `fulfillment:write` 的独立管理员在 Vben「生产与物流」查看预留单并建立生产尝试。系统重新执行 T22 门禁，只允许原销售快照 D08 批准的印厂，固定文件、地址和交接编号，保留处理人、共享工单及期限。D06 的工作日日历尚未冻结，当前由运营按适用政策明确填写本次处理期限，系统不推算正式交付日期。
3. 讲述者或具有当次本人证据的协助操作人为当前尝试授予限时生产资料访问。授权绑定具体生产尝试、操作人和版本，资料限于生产 PDF 与收货地址。
4. 运营核对限时资料及 PDF 字节/hash，人工联系印厂并记录交接与回执。应用保存记录，不自动发送文件或创建印厂订单。
5. 印厂明确确认接单后才消费首本权益；运营继续记录物流、适用微信发货管理结果及交付证据。用户页面重新查询后显示实际阶段。

## 一致性与取消

首本始终保留同一业务生产单和权益，每个预留版本与生产尝试分别冻结书稿、快照、PDF、地址 hash。每次尝试具有独立交接编号；数据库限制同一生产单同时只有一个尚未确认取消的尝试。新建、资料读取及交接前检查当前确认、授权、权益、冻结与 D02 制作期限。PDF 读取前后都重新核验，拒绝在磁盘读取期间撤权的迟到结果。

用户接口为 `GET /v1/projects/:id/fulfillment` 与 `POST /v1/projects/:id/fulfillment/grants`；后者使用幂等键和独立本人证据。运营接口以 `/v1/admin/fulfillment` 为前缀，`:id` 为首本生产单 ID：列表/详情、`/:id/attempts`、`/:id/attempts/:attemptId/{materials,pdf,handoff,receipt,cancel,shipping,delivery}`。资料与 PDF 为 GET，其他动作是 POST；运营写入沿用飞书管理会话、CSRF、权限和事务审计。限时授权最多 30 分钟，并继续受当次授权和访问期限限制。

交接开始后，结果未知保持待核实，不能以超时或重试制造新交接，也不释放权益。交接前取消结束本次尝试；交接中请求取消只进入待取消，由运营核对供应商回执后记录明确取消，才允许新尝试。已经离开平台的纸书与文件副本按实际状态人工核实，页面不承诺远程自动撤销。

印厂明确取消未成功时，运营可记录核实证据并继续原来的实际制作/发货阶段，原物流及已消费权益保持，不能借此创建新尝试。明确取消后允许更正地址或书稿并重新确认；地址变化只使发起人确认失效，内容/PDF 变化使双方确认失效。重新提交沿用原业务单与权益，递增预留版本并立即重新锁定，历史尝试的文件与地址快照保持原样。

已交接后，即使制作时钟到期或当前授权变化，后续回执、取消及物流事实仍按已有尝试核实记录；这不重新授予私人文件读取或新的交接权限。质量重印与退款分别由 T28/T27 承担。

交付完成保存唯一事实，向 T10 `ProjectServiceTerms.recordFact` 写入稳定的 `delivery_completed` 事件及原始发生时间。重放或再次录入物流不能改变该时间，D03 回听及适用资料期限从同一事实起算。期限结束不等于资料已经删除，清理由 T26 负责。

## 验证范围

测试从审核、限时资料、交接、回执、取消、物流和交付 HTTP 观察结果；并发和恢复使用真实本地 PostgreSQL/Redis，可丢弃独立 schema。微信、支付、AI 等外部协议使用明确替身；合成印厂回执和物流编号不是真实履约证据。

先按[本地开发](development.md)准备依赖、固定字体和 Chromium，再生成 Prisma client、构建 contracts 及 API 测试。定向命令：

```bash
pnpm db:generate
pnpm --filter @timenook/contracts build
pnpm --filter @timenook/api exec tsc -p tsconfig.test.json
cd apps/api
node --env-file=../../.env --test dist-test/test/fulfillment.test.js
```

浏览器联通验证使用仓库 Playwright，目标为「运营建立尝试 → 本人限时授权 → 核对同一 PDF → 人工交接待核实 → 明确接单 → 物流与微信发货记录 → 唯一交付」。外部真实验收与本地结果分别记录，见 [T23 工程证据](delivery/2026-10-22/evidence/T23.md)。
