# T10 · 核验付款并唯一激活人生项目和首本权益

GitHub：[#11](https://github.com/brycezhang/timenook/issues/11) · 状态以 GitHub 为准。
阶段：S1

## 交付结果

发起人付款或退出后查询订单，都恢复同一个人生项目、讲述者、默认计划和首本权益。

## 验收条件

- [ ] 创建订单冻结价格、币种、套餐/关系/模板快照及稳定商户单号；下单结果未知先查询原单。
- [ ] 通知验签、解密、核对应用/商户/订单/金额/币种/状态后持久化 Inbox 再应答；通知与主动查单走同一入账用例。
- [ ] 真实 PostgreSQL 事务一次激活支付、默认项目/subject、计划及权益；同键重放、异载荷 409、不同键并发和漏通知恢复均验证。
- [ ] 小程序付款成功/取消/超时均查询服务端，失败不发权益；关单竞态保留真实支付事实；未填姓名或书名也可继续。
- [ ] 按订单冻结的首版 D02/D03 建立独立项目期限，只消费所选规则需要的付款/参与/交付事实；未发生事件保持未起算。暂停/恢复、上限和未开始处理执行已选政策，重放、并发、重启及套餐更新不延长旧期限。
- [ ] 为 T14/T21/T22/T23/T25/T26 提供同一服务期限判定，测试到期前、恰好到期、到期后及暂停上限；制作到期/退款不直接触发资料删除，未知商业规则保持待定。
- [ ] 支付通知内部 `/v1/webhooks/wechat-pay/payments`、公网 `/timenook/v1/webhooks/wechat-pay/payments`；生成/核验回调地址不漏或重复前缀，真实商户通知与查单证据分别记录。

## 实现边界

只执行 T05 选定的首版政策及已售历史快照，统一期限判定供下游复用；不要求实现校验器全部枚举组合。客服发起适用的暂停/例外处置，系统仍检查依据、权限、时钟与审计。
