# 撤回与删除以独立台账为恢复依据

旧业务数据库备份可能包含已经撤回的授权和已经删除的资料；只把墓碑或 outbox 放在同一备份中，恢复后仍可能重新开放访问。T26 选择在独立受限的本地文件系统中先持久化经过认证的撤回/删除事件，再在 PostgreSQL 投影。API 和 Worker 开放私有能力前先校验并重放；运行时持续检查。新建源和恢复切换分别由显式命令执行，服务不能因缺源自动初始化或自动取得写入权。

独立源使用固定锁文件的非阻塞原生 flock、不可覆盖的事件文件、链式认证及经过认证的 head，按文件和目录 fsync 发布。活动进程固定绑定数据库位置、安装身份及切换代次；恢复到另一安装须在完成重放后显式 promote，使旧进程失去权限。这引入 Node 原生依赖和运维介质要求，换取跨进程排他、崩溃后确定性恢复及与业务备份分离的拒绝依据。首版只支持同一主机上的本地 POSIX 文件系统；不提供 NFS 或多主机锁的隐式降级。

资料永久删除采用按项目、类别、行键和列登记的单向擦除；数据库仅允许匹配删除清单的清空，并保留原有版本、引用和资金约束。财务与最少权利事实继续按各自用途处理，不把全部历史记录作为内容整行删除，也不把退款当作删除触发。原声等某类到期与仍有效 PDF 的保留分别判断；类别重叠和副本期限由 D03 冻结。

完整合法旧源、head 和密钥一起回滚，无法只靠同一介质上的认证链自行识别。独立介质、账号权限、密钥托管、防整体回滚、正式恢复时限及外部副本证据仍由 T29 和对应负责人验收。本决定记录工程取舍，不代表正式政策、部署或真实删除验收通过。接口与运行约束见[开发说明](../development-deletion-ledger.md)。

故事否决恢复使用 `journal_denial` 来源，只能复制独立已认证事件中的实际主体、操作人、版本/hash 与否决选择，证据引用指向该事件 hash。它不冒充原来的 self/assisted 确认证据，不创建肯定授权；原 assisted evidence 不在旧备份时也不虚构补建。已有普通操作记录保持原来源，缺少真实主体/操作人时恢复继续拒绝开放。
