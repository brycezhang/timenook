# [后台 B02] 用户查询与关联项目服务处理

GitHub：[#152](https://github.com/brycezhang/timenook/issues/152) · Parent：[#150](https://github.com/brycezhang/timenook/issues/150) · ready-for-agent

## What to build

客服从用户列表或待处理筛选进入账号及关联项目，找到有订单或无订单的讲述者，添加备注，并核验处理现有资料、换绑、撤回/删除与必要纠正申请。

## Acceptance criteria

- [ ] 管理员按实际账号编号、订单/项目/讲述者信息搜索并稳定分页；账号、发起人/讲述者项目关系分别显示，不假设已有手机号/昵称。
- [ ] 用户详情能进入全部获准查询的关联项目、订单和服务申请；无账号讲述者与无支付订单的内测项目不丢入口，也不伪造付款或生产权益。
- [ ] 待处理筛选按实际用户/项目/申请关系发现资料、换绑、撤回/删除及纠正事项，包括未关联购买订单的请求；只显示摘要，无权限不能越权加载正文。
- [ ] 复用受控申请及核验动作处理换绑、完整导出、主动撤回/删除和必要纠正；核验事实、进度、结果和后续步骤清楚，改动内容仍经本人确认。
- [ ] 用户内部备注按账号正确关联并追加操作人/时间；业务详情显示自己的历史，服务动作不会误作用到另一个项目或讲述者。
- [ ] 长期服务与完成资料包持续可领取，安全授权仍限时；换绑撤旧权、主动撤回/删除终止活动访问及迟到输出拒绝继续有效。
- [ ] 浏览器/真实 HTTP 覆盖待处理发现→详情→核验/处理→结果与返回，以及重复提交、失权/退出清理；不增加独立工单工作台、封禁或账号合并。

## 验证与交付

以 HTTPS 后台浏览器联通实际管理 HTTP 验证公开行为；锁、唯一性、重复操作和重启使用真实 PostgreSQL/Redis，仅外部供应商网络可隔离替换。复用既有相关范例，完成定向回归、类型、构建、独立 Standards/Spec、最终 PR CI 及合并后 main CI。读取最新主分支的已有业务/支付/内部验收交付证据，核实实际装配；代码存在或替身通过不代表正式可用。真实账号、资金、设备、供应商和实物结果单独记录。

开发直接硬更新，按需重建数据/夹具；不做旧开发数据迁移、历史兼容、备份准备、旧库恢复或回滚演练。禁止私密样本和凭据进入 Git。
