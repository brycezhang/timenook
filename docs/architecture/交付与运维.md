## 1. 部署拓扑

云厂商已确定为阿里云，中国大陆单区域起步；具体区域/可用区、账号主体、规格与预算待冻结。参考[wutong交付方式](wutong技术栈对齐.md)，API/Worker采用ECS + Nginx + systemd与CI release包，数据库用RDS PostgreSQL，调度用Tair（兼容Redis），文件用私有OSS。PDF渲染可保留独立固定容器；首版不引入Kubernetes、跨区域双活、独立消息总线或自建GPU。

按 [ADR 0009](../adr/0009-shared-ecs-api-path.md) 和 [ADR 0015](../adr/0015-dedicated-domain-ingress.md)，首版计算使用 legal-agent 同一台 ECS，TimeNook API 为 `https://timenookapi.threeminreading.com/api/v1`，管理页面为同域 `/admin/`；下面的独立性指应用进程、数据、身份和配置隔离。开发阶段直接按当前方案实施。

| 环境/角色  | 方案                                                                               | 数据边界                                                                       |
| ---------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 本地       | Docker Compose运行API/Worker、PostgreSQL 16系、Redis 7及隔离测试存储，渲染固定环境 | 参考wutong本地开发组织；原生小程序纳入workspace构建；真实OSS联调使用测试身份 |
| 测试       | 独立阿里云资源/身份、测试小程序与供应商配置                                        | 不复制真实私人素材，不连接生产RDS/Tair/Bucket、商户或密钥                      |
| 生产API    | legal-agent 同一 ECS，独立 NestJS/Fastify systemd 服务；TimeNook 独立域名下 `/api` 转发回环端口 | 用户/管理API、任务查询、鉴权素材读取与微信通知；管理端强认证，同机 legal-agent 服务独立 |
| 生产Worker | 同一 ECS，独立systemd Worker；渲染容器/进程限制CPU、内存和临时目录                | 无业务公网入口，按任务角色扩容；依赖与API来自同一release                       |
| 数据服务   | RDS PostgreSQL（支持日志备份/PITR的高可用规格）、Tair（兼容Redis）、私有OSS        | 同区域VPC优先；最小权限账号、白名单、TLS；队列noeviction及Lua/锁兼容验收       |
| 调度与监控 | 数据库租约下的逻辑调度器；阿里云云监控/SLS                                         | Outbox/恢复扫描、到期、备份与队列告警，日志脱敏                                |

单台共用 ECS 是共同故障域：主机故障会影响两个应用。发布前核实 CPU、内存、磁盘、连接池与队列配额，使用真实录音和 PDF 压测验证对 legal-agent 的影响。若容量或可用性门槛不满足，再拆分 Worker/渲染节点或增加 API 副本与独立故障域；不以家庭数直接推算容量。

私密音频/PDF通过API媒体网关流式读取私有对象，需支持Range和背压，设置并发限制。流量增长后可单独部署同代码库的媒体网关进程，仍保留逐请求授权；不能为了CDN缓存改为公共桶。

Tair并非仅凭兼容名称即可通过验收。首版优先标准架构，确认noeviction、持久化、Lua/阻塞命令及故障切换；普通缓存若需要淘汰策略则独立资源。RDS连接池按API/Worker总副本数与实例上限预算，批处理/渲染不无限建连接。OSS与服务器同区优先用受支持的内网路径，小程序使用公网上传域名。

## 2. 发布与恢复

同一提交经CI类型/测试与分包构建，产出API/Worker、Vben静态文件、契约、迁移及release清单；渲染容器单独记录镜像摘要。参考releases/current/shared，Node/pnpm/Prisma二进制在与生产兼容的Linux验证；不直接复制参考项目的环境文件或开发登录开关。记录schema、模型/提示词、模板/字体版本。关键配置进入环境校验，缺少支付验签材料、私有存储或销售参数时对应能力关闭，不能用测试成功响应掩盖。

发布顺序：核对 RDS 可恢复点 → 上传不可变 release 目录 → 部署本次审查后的数据库结构 → 原子切换 current → systemd 重启 API/Worker → 健康检查和核心冒烟 → 管理端/小程序发布。开发阶段按当前 schema 和接口契约统一实现、构建与验证，直接更新文档和项目记忆。

发布前读取实际 `nginx -T`、端口与 systemd 归属，确认 TimeNook 独立域名下 `/api/` 剥离一次后转至内部路由；客户端、回调与素材 URL 使用同一公网基址。发布后复验 legal-agent `/v1/health` 与服务状态，以及 TimeNook `/api/health/live`、`/api/health/ready`、业务鉴权和 TLS。回滚只作用于 TimeNook 服务及其专属配置。

恢复时使用相互匹配的应用、数据库结构、配置及任务版本；切换 release 并不自动恢复数据库。任务输入保留 schema 版本，Worker 拒绝未知格式。开发阶段的客户端和服务端按当前方案配套更新，不承担旧开发版本的兼容或迁移要求；回滚和备份恢复的实际结果由 T29 留证。

健康检查分为存活、就绪和业务依赖探针；模型故障不应令订单查询全站失效。管理端提供暂停新AI任务、暂停投产和暂停售卖开关，已保存素材和服务申请仍可查询。

### 2.1 备份目标

工程建议目标：数据库RPO不超过5分钟，试点RTO不超过4小时；这是待演练的目标，不是当前能力或用户合同。RDS选用支持日志备份/PITR的规格并实际开启；OSS启用适当的冗余与恢复策略，并核对原声对象清单。备份保留期由D03决定，不能自行设成永久。

RPO内可能丢失的任务/关联用支付查单、任务恢复及对象清单核对修复；孤儿清理延迟必须覆盖恢复窗口，不能刚恢复数据库就删除“无引用”的最新原声。原声可靠性同时依赖对象保全和数据库关联恢复，单独备份数据库不够。

每次备份恢复演练验证一个完整项目：原声hash、转录、故事确认、书稿PDF、二维码对应关系、订单权益。先重放独立保存的撤回/删除台账，再开流量；从旧快照恢复不能重新开放已经撤销的访问。

正式环境验收由 T29 集中负责，T30 使用同一内部项目核对端到端与实物。未变能力引用原责任票适用证据，消费者只补新增集成和受影响回归；完整规则见[验收复用与唯一归属](../delivery/2026-10-22/spec.md#验收复用与唯一归属)。

## 3. 安全与个人资料处理

这些控制对应PRD的私人家庭内容和授权需求，不扩大为额外产品功能。

| 范围     | 设计要求                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 身份     | 微信服务端换身份，产品会话可撤销；运营飞书白名单身份（无密码/MFA，见 ADR 0016）；关键操作核验角色和资源                          |
| 文件     | 私有桶、暂存与最终前缀权限分离、上传体积/类型校验、最终对象不可覆盖、访问网关检查撤回                |
| 凭据     | 通过密钥管理或部署Secret注入，生产/测试分离；支付私钥、ASR/LLM密钥只在服务端                         |
| 数据库   | 私网、传输/存储加密；地址等敏感字段按需要应用加密，密钥与备份隔离                                    |
| 模型     | 仅发送当前故事所需素材；不发送支付信息或地址；服务商训练用途、保存/删除和区域需合同及配置核验        |
| 渲染     | 固定模板、正文转义、禁止任意HTML与脚本，禁止任意外网请求；资源由内部资产清单供应，避免SSRF与私网探测 |
| 日志     | 记录ID、状态、耗时、错误码与用量；不记录正文、录音、完整地址、登录code、签名URL或令牌                |
| 运维访问 | 查看私密内容必须有用途明确、限时的授权工单；生产文件下载和导出均审计                                 |
| 删除     | 活动数据、备份、对象历史版本、模型输出、临时目录及供应商副本纳入清单；与财务留存分开                 |

隐私告知、敏感个人信息同意、AI标识、微信支付和印刷准入以PRD D08为上线门槛。技术上保留告知/标识版本及来源元数据，具体法定义务与适用范围由上线前专项核验确定；不能由“部署国内”推导为已经合规。

## 4. 容量与成本

### 4.1 用于压测的假设

以下只是工程估算，不是销售额度、书籍规格或用户承诺：50个项目，每项目20篇故事，每篇3段×3分钟；按48kbps MP3采集估算，每篇2张5MB照片，每项目50MB PDF。原声MP3兼作回听来源；必要衍生文件按实测计入。

| 内容    | 算式                       | 原始体积估算                     |
| ------- | -------------------------- | -------------------------------- |
| MP3原声 | 50×20×3×180秒×48000bit/s÷8 | 3.24GB（单项目约64.8MB/180分钟） |
| 照片    | 50×20×2×5MB                | 10GB                             |
| PDF     | 50×50MB                    | 2.5GB                            |

原始文件合计约15.7GB；缩略图、必要转码、历史版本、暂存、导出包与备份另算，初次可留2–3倍空间。音频参数、原图尺寸和D03保留期变化都须重算；上传封存前不清理唯一的本地副本。这里使用十进制GB估算，不作为实际账单。

单段5分钟、48kbps MP3约1.8MB，重点测真实手机录制/保存、弱网上传、服务端解码/封存、ASR拉取、查询频率及任务排队。不需要按持续音频长连接预留并发，上传并发和供应商任务额度分别限制。

初始Worker并发建议ASR提交/查询4、故事整理4、PDF渲染1，均为待压测起点；供应商并发限制、平均耗时和事件循环占用决定上限。提高并发前确认供应商额度和本地CPU/内存，不让PDF渲染阻塞API或队列续租。

### 4.2 成本模型

单项目贡献 = 999元实收 − 支付费用 − 文件ASR分钟费 − 追问/整理模型token费 − 存储/鉴权下载与OSS流量 − 图片及必要音频处理 − 人工工时 − 印刷/物流 − 售后预留。固定云资源成本另按付费项目数分摊。系统重试和用户主动重生成分别计量，用户额度按销售快照兑现。

记录每次供应商调用的真实用量和费用归属，包含失败/重试；按项目与全局设告警预算。用户额度按销售快照兑现，系统技术重试不能再次扣用户额度。主动重生成和超额处理规则由D04公示后启用；不能用临时运维预算静默削减已售权益。

官方文件识别机制与费用来源见[微信媒体与支付核验](微信媒体与支付核验.md)，不作为本项目已取得的报价或毛利。试点前用真实音频、供应商账单、打样和人工计时校核成本；追问仅在正式转录就绪后按需执行，等待期间不重复请求。

## 5. 观测与故障接管

| 指标/信号                                       | 处理                                                                                            |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 付款成功但项目/权益缺失，Inbox滞留              | 立即告警，查单与事务补偿，阻止重复发放                                                          |
| 对象已封存但缺失/校验不符、跨项目访问、错版生产 | 上线阻断级事故；停止相应写入或生产，保全证据                                                    |
| 队列最老等待时间、Outbox滞留、过期租约          | 超过任务预算告警，先恢复调度，不要求用户重录                                                    |
| 5分钟以内输入的成功出稿时延P95                  | 内部目标≤3分钟；单列失败率/排队及人工接管；ASR任务未终态时继续显示处理中，该目标不冒充供应商SLA |
| 上传成功率、ASR失败率、无来源事实率             | 按设备/供应商/模型版本拆分；原声正文不进入分析事件                                              |
| 追问时延、跳过/重复/禁问与编辑冲突              | 转录就绪后追问响应建议P95≤5秒，另报停录到追问的实际总时延；禁问被主动重问时阻断发布并修正       |
| PDF渲染失败、分页不收敛、印刷规格不符           | 停止该版本确认/投产，运营介入，不提供残缺文件                                                   |
| 授权撤回后的资源访问                            | 新请求必须拒绝；验证活动流中止、缓存与衍生物处理                                                |
| 导出、删除、客服工单超期                        | 按公示时限升级给运营，保留实际未完成原因                                                        |

结构化日志串联 `request_id / project_id / task_id / revision_id / book_version_id / fulfillment_id`。经营事件只记录购买、参与、保存、确认和交付时间等最少字段，用于PRD漏斗；不建设超范围的经营看板。
