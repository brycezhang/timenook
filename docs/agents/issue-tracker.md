# Issue tracker: GitHub

仓库为 brycezhang/timenook。用 gh 读取/修改 GitHub Issues；多行正文写临时 UTF-8 文件，以 --body-file 传入。

规格为父 issue，每票为一个子 issue，使用 GitHub 原生父子与 blocked-by 关系。使用 gh api 返回的 numeric database id 建立关系；如果平台不支持原生关系，在正文保留明确 Parent / Blocked by 引用并报告降级。

## 领取与依赖

每次开始前读取票据正文、评论、依赖及上游交付证据，区分本地工程、真实联调和上线验收。现有 blocked-by 保留完整交付依赖，不以删除依赖或提前关闭上游来放行本地工作。

用户已授权先完成本地开发与测试。下游本地实施可以在上游 issue 仍 OPEN 时开始，但须逐项记录：本票所需的上游接口/数据契约已有合并 PR，相关 TDD、测试及审查有证据；剩余阻塞仅为真实账号、设备、供应商、商业参数或环境验收。参数未冻结时只能使用明确隔离的合成配置验证既定契约，未知业务规则保持待定。上游所需代码或契约未交付时，继续等待。

开始本地工作时在本票记录所消费的 PR/提交、验证结果、未满足的真实条件和允许范围。ready-for-agent 表示规格可执行；ready-for-human / needs-info 表示仍有人工或信息条件，均不能单独证明可领取、可关闭或可上线。

验收证据按[父规格的唯一归属](../delivery/2026-10-22/spec.md#验收复用与唯一归属)复用：引用适用提交、配置与环境的责任票记录，消费者补新增集成。缺失或受影响部分仍须验证，不以链接代替不适用的证据。

## 逐票验证与合并

2026-11-02 范围收敛：原 #85 已按用户要求删除。统一合并队列、分布式互斥及原子串行保护不列入 MVP 必需交付；不再单独建设或以此阻塞功能闭票。使用现有入口，避免同时发起合并，遵守当前必要 CI 检查并处理实际失败。

实施 subagent 按公开行为逐项 RED → GREEN，运行本票相关回归、类型检查和构建。代码稳定后固定提交并创建 PR，同时运行 PR CI 和独立 Standards / Spec 双轴审查；不等待一方完成才启动另一方。审查修复补针对性测试并提交，新的 PR CI 替换旧运行，仅最终提交的审查结论与 CI 成功可用于合并。ready frontier 中工程依赖已满足且彼此独立的票，可以使用独立 worktree/分支并行实施；每票分别执行 TDD、相关检查、独立 Standards / Spec 双轴审查和最终提交的 PR CI。合并串行进行，每次合并后须等待 main CI 全绿，才进行下一票合并并放行依赖该提交的下游；独立票的实施、PR CI 与审查仍可并行。保留现有 45 条依赖及工程交付、本票验收、环境上线的分别判断。

本地负责快速反馈与 CI 无法覆盖的 Mac 微信原生编译、真机及供应商证据。main 每次 push 完整回归；PR 按已声明的说明文档、官网独立或整仓范围验证，未知/混合路径和公共契约、依赖、迁移保持整仓。相关检查已通过且没有新增失败、变更或证据缺口时，不机械重复本地全量。最终提交的 PR 选中检查与独立双轴审查通过才合并，合并后仍等待 main 全绿。分流边界和复现命令以[开发说明](../development.md#持续集成)为准。

## 完成与关闭

2026-11-02 用户更新：逐票区分“功能仍缺失”和“功能已交付、待实际验收”。以下新口径覆盖旧的“缺少实际验收即保持 OPEN”要求；历史复选框和真实验收结果不追认通过。按本票已确认的公开范围判断功能交付，后来拟用方案的新增接入工作应另列，不混入已交付旧票。产品网页端后续对齐按本次决定暂停，相关票据以 not planned 关闭。

- 工程交付：本票范围的 PR 合并，相关测试与审查完成，附可复现证据；据此判断下游工程前提是否满足。
- 本票实际验收：真实平台、设备、内容审校、供应商及实物结果继续分别记录，使用适用的真实上游参数与服务。仅这些结果缺失时，不阻止已交付功能闭票；在关闭评论明确“功能已交付，待实际验收”、适用交付证据和未完成项，历史未验收框保持未勾选。功能仍缺失则保持 OPEN，并列出具体缺口，不能用“待验收”掩盖尚未实现的能力。
- 环境与上线：T29 集中验收正式部署、实际管理员飞书登录、云资源与恢复；T30 汇总全链路、目标用户、实物与售卖门槛。T01–T28 的本票关闭不反向等待 T29/T30；需公网联调时使用获授权的隔离联调环境，其证据不替代 T29。

新功能以 ticket 分支交付，PR 关联对应 issue。仅部分功能交付时用 Refs；本票功能全部交付且 PR 合并后可用 Closes 或关闭，尚未完成的实际验收须在关闭评论明确列出。T07 的正式环境项归 T29，不再作为 T07 的重复关闭条件。本次规则修订不自动关闭任何 issue，也不追认新增验收项通过。父规格存在未交付功能时保持 OPEN；全部功能交付后可按同一口径关闭并列出实际验收待项。真实资金、生产交接、采集和售卖继续遵守相应授权及准入条件。
