# 登录、首页与新增故事真机回归

2026-11-06，按用户报告在 iPhone Mirroring 连接的真实 iPhone / 微信开发版进行回归。使用实际微信身份与线上 API；本轮只改小程序，没有重新部署后端或网页，也没有发起付款。

## 问题与实现

- 原首页只突出购买入口，新购流程把登录放在购买确认页。新增独立登录页与首页登录入口；已有项目登录后回首页，只有明确选择新购时才继续购买确认。登录不创建订单或调用支付。书名与称呼跨登录保留；“我的”原有独立登录继续可用。
- 原首页 `onHide` 清空项目，`onShow` 再次清空并显示全页加载。现在同一会话、同一项目保留内容与滚动位置，返回时后台读取更新；切换项目、退出或权限拒绝会清除旧内容。账号或项目改变时回到页首。我的页面从本机会话立即显示已登录状态，再向服务端核实，避免先闪出登录按钮。
- 自定义底栏对合法 Tab 点击直接调用原生切换，不用可能滞后的底栏选中值拦截点击。
- 当前“我的时光手记”对应受控实付 1 分订单；数据库确认成功全额退款 1 分，`creationState=terminated`，现有故事 3 篇。不能新增是退款后的项目规则，与账号登录失败无关。未恢复该订单的制作权益，现有故事与资金事实未变更。
- 通过现有内部项目创建能力，为同一购买账号创建“真机回归测试（内部验收）”，项目 `19c79903-3e43-44c0-a8a5-18932d62f105`，固定验收键 `device-login-home-regression-20261106`。该项目未付款、没有实体书权益，独立用于正常记录入口回归。

## 真机结果

在已接受当前条款版本的同一真实微信账号上完成：

1. 冷启动恢复会话，读取原退款项目及已有 3 篇故事。
2. 切换至内部验收项目，首页显示“开始讲述”；实际读取采访问题，创建一份无录音的采访并进入麦克风录音准备页。没有创建或伪造新故事。
3. 首页滚动到开始讲述区域 → 我的 → 首页，原项目、页面内容与滚动位置保留，没有全页加载占位；从录音准备返回同样保留位置。
4. 我的 → 退出登录 → 首页，不再显示旧项目。首页独立登录入口 → 微信登录 → 直接回到已有项目，没有进入购买确认或微信支付。
5. 数据库复查：自本轮开始（北京时间 10:30）该账号新订单数为 0；原退款项目仍为 `terminated`；内部验收项目没有关联支付订单，留下 1 份无录音采访供直接手机继续验证。
6. 最终包补测退出后从已滚动的项目首页回到未登录首页，已回到页首，主视觉标题完整显示；退出清除旧内容与滚动重置均通过。

热推送后与镜像触控中曾出现点击无响应；通过微信原生菜单“重新进入小程序”后继续完成上述操作。最终使用可识别的实际界面结果判定，不把未响应的点击计作通过。镜像操作采用明确按下／抬起并在页面稳定后点击。

真实麦克风采集需要直接操作手机；iPhone Mirroring 不能代替手机麦克风验收。此轮登录／首页／新增入口结果不等于真人录音、支付或实体生产通过。
