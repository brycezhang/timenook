## 已实现的公开行为

- 新片段 seal 的同一个 Participation/PG 事务写 asset、clip、唯一 sealed input、生产任务、输入 hash/主体/绑定/epoch、额度关联意图和 Outbox。额度意图关联 T14 已结算的真实录音用量，不新增 ASR 用户收费；重放和逻辑重试不重复结算。复合 FK 约束精确的输入/素材/录音意图归属。
- 数据库保存事实和 due 时间；Outbox 用于持久投递意图，BullMQ 稳定 `jobId=taskId` 仅唤醒。任务完成即移除该 Redis job；DB due/过期 lease 扫描保证 active 期间同 ID 吞掉一次唤醒后仍可恢复。Queue producer 使用有限失败策略，Worker 使用 BullMQ 所需的无限请求重试连接，两者与 session Redis 分开。
- 领取租约 30 秒及递增 fence；首次取源前持久化请求 UUID、配置版本/hash、preparing 尝试及预算预留。取源后由当前授权/lease/fence 在事务中原子标记 submitting，再调用 provider。租约失效但仍为 preparing 的新 owner 安全沿同 UUID 首次提交；跨 submitting 标记后的不确定只 query，不能据进程是否实际发包猜测安全重提。每次 Worker 只进行一轮 submit/query，然后保存下次时间并释放。未知结果查原 UUID/配置，确认供应商失败才允许新的有限尝试。源读取/签名确定发生在 ASR transport 之前的错误退回可重试失败，删除未使用预留，保持同一 UUID、配置和原 queuedAt；输入 hash 或归属变化则失效。进入 transport 后的不确定不能当作安全重提。
- 发送前和结果入库前复验输入、当前用途授权、绑定/epoch、适用期限和当前 lease/fence；迟到内容不能生效。正式原始转录保留供应商原文及 hash，PG 唯一关系、hash 检查及禁止 UPDATE trigger 使其不可变。空语音单独为 `no_speech`，不创建空转录。
- 外部尝试和内容有效性分别记录。当前 fence 成功失效任务时，以及当前领取/结果前检查到达 deadline 时，仅释放仍 preparing 的未使用预留；已经 submitting/unknown 的保守负债保留，旧 owner 不能删除新 owner 的已提交预留。撤回或旧 fence 取得的已验证外部状态写入脱敏 observation（标记 superseded），不激活内容或改当前任务。未知尝试继续占用预算；协议没有提供实际费用时 `actualCostFen=null`，不从时长或预留金额推算实际账单。
- 复用 Participation 的项目→主体锁和实际本人/协助用途 owner。修正正向授权不增加全局 accessEpoch，仅拒绝/撤回递增；与架构“撤回、绑定调整和删除时递增”一致。先 collection seal 后 AI grant 可处理同一素材，ASR 期间新增 sharing grant 不取消任务；撤回后重授不能复活旧任务。首次处理固定实际协助 collection/AI session，结果前验证原 session 的到期，后续新 session 不能替代旧证据。
- 每项目供应商 submission、poll、retry、费用预留预算来自冻结订单的既有 D04 结构；合成配置明确提供本地预留和 deadline。截止或预算耗尽进入可见 `manual_review`，失败、完成、人工接管分别记录；HTTP 视图的 retryable 与实际重试共用同一有限判断。
- `GET /v1/projects/:id/tasks` 和 `/:taskId` 复用私人内容访问；`POST .../tasks/status` 用 interviewId/可选 assistedSessionId 提供当前采访最小状态，不含原始转录，支持 collection-only 协助。`POST .../:taskId/retry` 使用幂等键并支持适用协助身份。运营 `GET /v1/admin/tasks` 只返回脱敏元数据；`POST /v1/admin/projects/:id/tasks/:taskId/retry` 经 MFA session、CSRF、`tasks:retry`、命令事务和固定审计调用相同 `retryIn`，没有直写成功能力。
- 实际采访 Page 封存后查询，显示处理中/可离开、无语音重录、失败重试或接管。hide/unload 停轮询，返回立即刷新，带页面/session/序列 fence，2→10 秒退避；未知重试响应保留同幂等键。后台为 Vben 原有样式，支持刷新、错误恢复及审计重试，不把讲述者页面字号要求强加给后台。

## 计时和后续消费边界

`sealed_inputs.createdAt` 保留每段云端封存事实；任务用不可变 sealed input ID/clip ID 关联该时间。`ProductionTask.createdAt` 是首次排队时间，`submittedAt` 保留首次开始尝试的时间，`TaskAttempt.submittedAt`、observation 时间、正式转录创建和任务 completedAt 保留实际各轮结果关系。重试、Redis 重建、Worker 接管不会重写首次 queuedAt 或 deadline，历史 failedAt 不因排队清空。

本票尚无“用户提交整理”和“本次全部输入保存”的 T18 提交实体，不能伪造这两个时间或宣称已经测得端到端出稿时间；T18 按本票实际 sealed input/转录/任务 ID 关联自己的提交与依赖完成时间。T30 的 95% / 3 分钟目标和失败、接管、处理中总体口径仍需真实样本验收。

## 故障证据的实际层次

1. 实际 BullMQ Worker 实例验证重复唤醒、受理后释放、下一轮同 taskId poll；PG trigger 在供应商响应后的任务更新处抛错，事务回滚后原 UUID query 恢复（`faults-01.log`）。这是可捕获数据库错误，不称作进程崩溃。
2. 独立 producer 子进程使用实际 Queue.add，Redis 已接受后、PG delivered 标记之前被 SIGKILL；PG 保持未确认投递，真实 Worker 消费并仅产生一次供应商尝试（`producer-process-fault.log`）。
3. 独立子进程通过 `launchProductionWorker` 启动真实应用/Worker/DB due 扫描，供应商响应已解析、入库前被 PG advisory-lock trigger 阻塞时 SIGKILL。随后夹具受控过期 lease、删除本票 Redis prefix，第二独立进程仅 query 原 UUID 并完成（`process-fault.log`）。这是进程 crash + 受控 lease/Redis 修复组合证明，不声称无需 lease 到期或单凭正常 close 自动恢复。
4. 单独清掉本票隔离 queue prefix，由 PG due 恢复，不重置输入/首次排队（`faults-01.log`）。初始源操作超 lease 测试使用无状态 provider，对未提交 UUID 也返回成功，不能证明首次 submit 恢复；该恢复结论由下方审查修复的自然到期、有状态 provider 用例替代。
5. Outbox INSERT 故障回滚 clip/task/用量，原 seal 可重放（`atomicity.log`）；真实 PG 拒绝转录 UPDATE、跨项目素材和同项目错录音额度关联（`invariants.log`、`green-18.log`）。

子进程仅在外部对象源/供应商网络 seam 使用 IPC 受控替身，PG/Redis、任务 owner、真实 HTTP 和供应商 adapter 都实际运行。没有真实公网供应商请求、真实 OSS 或真实内容。
