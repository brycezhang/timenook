## 范围与证据边界

采用票据允许、用户已确认的项目创建模块公开契约；不注册项目 HTTP 路由。当前未交付微信身份/项目访问授权，调用方必须先完成认证和授权，`createdBy` 和项目 ID 不代表授权。后续 T10/T13 接入该模块。本票没有支付、运营模板 CRUD、多模板选择或个人计划 UI。

模板是本次工程实现自拟的原创合成内容，明确标记 `unreviewed-test-only`；未经过 D09 内容负责人审校或目标用户试用，不是正式售卖默认内容。模板/个人计划/偏好验证不等于 D09 商业内容验收。

测试使用真实 PostgreSQL 的每轮独立 schema，执行仓库迁移并在结束后删除该 schema。数据库仅用于测试生命周期准备与清理，所有业务结果均通过模块公开契约观察，无内部依赖替换。现有 HTTP 健康测试仍使用真实 PostgreSQL/Redis。

## 逐条 red → green

工具链：Node 22.23.4 / pnpm 10.34.7，执行前 `export PATH=/tmp/timenook-toolchain/node_modules/.bin:$PATH`。

单文件命令（工作目录 `apps/api`）：

```sh
pnpm exec tsc -p tsconfig.test.json
node --env-file-if-exists=../../.env --test dist-test/test/project-plans.test.js
```

1. **新项目默认起点**：先运行失败 `Project plan creation is not implemented`（0/1）；实现服务端固定模板与模板/项目/计划初始持久化后 1/1 通过。断言中性章节及题目目的、照片/自由讲述入口、稳定模板 ID/version、hash 形状、明确未审校标记与空禁问偏好。
2. **重复创建、并发与重启读取**：新增测试先失败 `Unique constraint failed on the fields: (id)`（1/2）；事务内通过唯一键去重，仅首次创建复制计划，八次并发重放及新模块实例读取全部一致，2/2 通过。
3. **同版本内容不可改写**：新增测试先失败 `Missing expected rejection`（2/3）；初始化先插入去重再校验已存 hash/审校标记，内容变更返回 `TEMPLATE_VERSION_CONFLICT`，不覆盖旧内容，3/3 通过。迁移同时对模板版本施加 UPDATE/DELETE 拒绝触发器。
4. **重放载荷冲突**：同项目 ID 改用另一个 createdBy 的测试先失败 `Missing expected rejection`（3/4）；核对原项目创建身份并返回 `IDEMPOTENCY_CONFLICT`，原计划保持不变，4/4 通过。
5. **调用方事务的原子性**：先让创建忽略调用方事务，模拟调用方失败后仍能读到项目，测试失败 `Missing expected rejection`（4/5）；改为使用传入的真实 Prisma transaction 后，外层回滚使项目查询返回 `PROJECT_NOT_FOUND`，外层提交后能完整读回初始计划，5/5 通过。
6. **代码版本升级保留个人修改与禁问**：先失败 `Interview preferences are not implemented`（5/6）；增加受 expectedVersion 约束的最小领域修订和偏好保存契约，计划按版本追加，偏好单独保存。升级代码版本后新项目采用新版，旧项目的个人章节/问题/禁问及邻近项目均保持不变；旧版重新初始化也不改新版项目，6/6 通过。
7. **并发编辑与项目内历史**：先失败 `Plan revision history is not implemented`（6/7）；增加按 projectId+revision 查询的历史契约。两个操作人以同一 expectedVersion 提交时只有一个成功，另一个 `VERSION_CONFLICT`；初始修订不变，其他项目不能取得这份修订，7/7 通过。此处操作人是合成审计标识，不是微信/讲述者授权验收。
8. **稳定内容 hash 和代码快照**：相同内容仅调整对象字段顺序时先触发 `TEMPLATE_VERSION_CONFLICT`（7/8）；改为按对象键排序、保留数组顺序的 canonical JSON SHA-256，构造时复制代码模板；等价内容与外部对象后续修改均不改变本实例版本，8/8 通过。
9. **个人计划结构边界**：重复问题 key 先未被拒绝，测试失败 `Missing expected rejection`（8/9）；增加结构/唯一 key 校验，重复章节或问题、空问题、夹带 projectId/preferences 元数据均返回 `INVALID_PLAN`，不消耗修订号；空白个人大纲仍保留照片/自由讲述入口，9/9 通过。
10. **单套模板范围**：其他模板 ID 先未被拒绝，测试失败 `Missing expected exception`（9/10）；构造时限制唯一模板标识及正整数版本，错误返回 `INVALID_TEMPLATE`，10/10 通过。替换代码发布定义只用于模拟版本升级，不是用户选模板或运营发布接口。
11. **禁问偏好命令校验与并发**：缺少操作人先未被拒绝，测试失败 `Missing expected rejection`（10/11）；校验操作人、项目 ID、版本和非空主题，拒绝无效命令且不消耗版本。并发的本人决定只有一个成功，另一个 `VERSION_CONFLICT`；偏好升级不改变计划修订，11/11 通过。

额外回归：生产应用的项目创建/读取/计划编辑与模板管理路径均为 404，原实现本就未注册这些路由，此项首次运行即可通过，不伪造 red。计划当前指针以 `(project_id, revision)` 的延迟复合外键约束，复制/追加事务同时更新，防止悬空或串项目指针。

## 公开契约与交接

服务端入口为 `apps/api/src/projects/project-plans.ts` 的 `ProjectPlans`，共享读取结果位于 `packages/contracts`。`createProject({ projectId, createdBy }, transaction?)` 以项目 ID 去重，异创建身份冲突；传入调用方 Prisma transaction 时参与该事务，不单独提交。调用方仍负责真实身份授权、支付核验及所选事务隔离级别下的重试。

`initializeDefaultTemplate()` 校验并持久化当前代码发布版本；`getProjectPlan()` 和 `getPlanRevision()` 返回当前个人计划与项目内历史。`revisePlan()` 追加修订；`setBlockedTopics()` 单独按偏好版本更新，不受普通计划编辑或模板更新复位。两个写入契约仅提供本票所需的最小领域能力，不表示 T13 的角色鉴权、本人核验、状态流转、实际提问关联或编辑 UI 已交付。

初始模板标识为 `timenook-default`，版本 1。章节/问题 key 在单项目计划内唯一；顺序以数组顺序保存。SHA-256 对对象键排序的 JSON 计算，数组顺序保留；模板版本为不可变数据库记录，个人计划复制为独立 JSON 快照及 hash。
