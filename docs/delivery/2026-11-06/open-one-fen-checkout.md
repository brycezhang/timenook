# 临时开放 1 分支付，页面正常显示 999 元

2026-11-06 用户要求：修复「套餐暂未开放」，开放支付；页面显示 999 元，实际仍支付 0.01 元，正式上线前再恢复实付 999 元；小程序不增加任何临时价或验收说明。

## 当前方案

- 服务端 `TIMENOOK_CHECKOUT_E2E_ENABLED=1` 时，所有账号都能购买当前临时套餐，不再按产品用户 UUID 白名单限制。匿名可读取正常套餐；创建订单和微信支付仍要求真实登录身份。
- 价格继续只由服务端决定：`listAmount=99900`、`amount=1`、`isE2e=true`。小程序显示标价 ¥999；订单结果页以「套餐金额」显示标价，不将标价写成实际已付。微信收银台使用服务端签名的真实 1 分参数，财务、通知验签和退款继续按实收。
- 购买页移除实付/验收提示。临时套餐的用户可见说明只有正常套餐内容、长期服务和记录额度，不展示内部验收、临时折扣或商业待定文字。内部套餐快照、实际金额和履约限制保留。
- 同步部署上一项配送信息后置：下单无需地区或地址，成书后提交印刷时填写；新订单模型移除付款时的地区字段。

## 正式上线前切回

发布正式 `purpose=production` 套餐，移除 `TIMENOOK_CHECKOUT_E2E_ENABLED=1` 并重启 API/Worker；确认当前套餐与新订单均为 `listAmount=amount=99900`、`isE2e=false` 后再正式发布小程序。已有真实付款事实不改金额，不自动补扣差价。回归已验证关闭临时开关后的普通 999 元下单。

## 实际部署

首版应用 `049f598` 已部署到共用 ECS `106.14.11.96` 的 `/data/server/timenook/releases/20261106-checkout-049f598`；API/Worker 正常运行，配送字段迁移已应用，公网套餐可购、标价 99900 分、实收 1 分。只移除了环境中的旧白名单键，保留支付开关与其余配置。管理端和网页静态文件沿用前一版本。

官方开发者工具以现有真实手机号会话进入购买页，`loggedIn=true`、`purchasable=true`、价格 `999.00`，无套餐加载错误。真实新建未付核验单并请求微信预支付成功，金额 1 分、返回签名支付参数；没有调用 `wx.requestPayment` 或完成扣款。

取消核验单时暴露既有问题：微信已关闭订单的签名查单响应缺少 `amount`，后端原绑定校验误报 400。仅对非成功查单允许省略金额；如响应有金额仍须匹配，成功付款及通知继续强制校验金额、币种、身份和签名。新增回归后，支付与固定套餐 21 项定向测试、测试编译和 API 构建通过。修复版部署、原核验单关闭状态及手机预览随后补记。

首次发布打包受到 `ops/.DS_Store` 与 macOS 扩展元数据影响，在服务切换前被清单校验拦截，清理后 478 文件验证通过。切换后管理页因发布根目录权限 700 暂时返回 500，已修复为 755 并核验 200；后续发布按此权限执行。无真实扣款或退款，不将预支付成功记为实际支付完成。
