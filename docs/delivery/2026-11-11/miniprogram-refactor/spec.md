# 时光故事小程序全量重构规格

状态：业务方案、12 张模块票及验收方式均已获用户确认，按依赖开始实施。实现基线 `149b1b6`；设计基线为当前原画布及用户后续已确认的登录协议备注。

## 问题

当前小程序已有支付、身份、录音、故事、PDF 和制作基础，但与新业务流程及现代手机设计存在 18 项差异。仅替换样式无法实现指定号码领礼、礼物三分类、六章共用目录、家人问题优先推荐、项目照片和随时归章；必须同时调整数据关系、接口、原生页面及交互。

## 解决方案

以最新版画布为小程序的界面和交互依据，按完整用户路径分模块重构。保留仍符合新规则的真实底层能力，删除被替换的旧业务分支。开发数据可以破坏性更新；不做旧版本适配、双写、双模型或兼容入口。

设计交付覆盖 71 张页面／状态，另补已确认但原画布尚未体现的登录同意提示状态。功能以真实会话、项目、接口与任务结果驱动，不把设计示例或验收场景带入正式包。

## 用户故事

1. 作为访客，我可以查看产品介绍与样书，再决定是否送礼。
2. 作为访客，我可从首页或我的原地登录，关闭后仍留在原页面。
3. 作为未勾选协议的用户，我点击登录可查看同意提示，点击继续直接授权登录。
4. 作为用户，我查看条款返回后仍能继续刚才的操作。
5. 作为购买者，我通过同一入口选择关系和书名，为亲友或自己购买。
6. 作为自购者，我付款后直接进入自己的故事书，无需发卡领取。
7. 作为购买者，我可恢复待付款或查询未知结果，不重复建单。
8. 作为送礼人，我付款后指定收礼手机号并分享电子礼物卡。
9. 作为送礼人，我可在领取前修改号码，旧卡随即失效。
10. 作为收礼人，我验证匹配手机号后明确领取并进入原故事书。
11. 作为非指定收礼人，我能理解号码不匹配的状态并切换账号或联系送礼人。
12. 作为原收礼人，我再次打开卡片仍进入原书，不重复领取。
13. 作为用户，我可在送出、收到和参与三类中找到我的故事书。
14. 作为自购者，我在送出与收到打开的是同一本书。
15. 作为购买者，我可以邀请家人参与；普通成员不能代发邀请。
16. 作为受邀家人，我填写自己相对主讲人的关系后加入。
17. 作为成员，我看到送礼人昵称与赠礼关系，不因查看者变化而改变称呼。
18. 作为主讲人，我从问题卡直接开始语音讲述，按钮与问题一起滚动。
19. 作为成员，我点击故事数、照片数和书名封面进入对应功能，零数量仍可进入。
20. 作为主讲人，我优先看到家人问题，也能混合浏览通用大纲问题。
21. 作为主讲人，我能区分问题是谁提出的，并看到其与我的关系。
22. 作为成员，我可在六章六十题基础上增删改章节、问题和顺序。
23. 作为成员，我维护一套大纲目录，改动同时用于采访与成书。
24. 作为家人，我仅用文字提出问题，章节可以不选。
25. 作为购买者，我缺少成员关系时可在首次提问补填，后续沿用。
26. 作为主讲人，我可以回答、稍后回答、跳过或恢复问题，并查看已回答故事。
27. 作为录音者，我可暂停、继续、加照片、结束并自动保存，单段最多十分钟。
28. 作为录音者，我上传失败能重试，保存后可离开等待整理。
29. 作为成员，我可在没有故事时先添加照片，再从照片讲述。
30. 作为成员，我可编辑故事文字、补录并通过进度条回听原声。
31. 作为成员，我的无章回答会保存为故事，随时可以归入任一章节。
32. 作为成员，我可跨章移动故事或暂不入书，素材仍保留。
33. 作为成员，我可按章节和章内故事顺序成书，不收录未回答问题。
34. 作为成员，我的未归章故事不阻断已归章内容生成 PDF。
35. 作为成员，我可以编辑封面草稿并明确保存，取消不改内容。
36. 作为成员，我可用系统查看器打开真实 PDF，扫码回听所印版本原声。
37. 作为成员，我完成书稿后再填写地址并提交制作，查看固定稿与物流。
38. 作为成员，我遇到制作结果未知可查原单，确认取消后可以修改重提。
39. 作为用户，我可以修改昵称、退出和阅读条款。
40. 作为手机用户，我在窄屏、键盘出现和安全区场景中均能看到并操作关键控件。

## 实施决定

- 采用现有原生 TypeScript / WXML / WXSS 技术栈，重做页面和组件组织；现有支付、微信身份、录音、存储、异步整理、PDF 与生产能力按新业务契约复用。
- 前后端与数据库在同一模块内调整。旧计划与书稿目录改为一套有序章节；问题与已完成故事建立真实关联，实际提问快照与生成版本继续保留。
- 专属礼物保存指定号码、卡片版本和领取事实；主讲人账号、自购身份、成员关系及赠礼关系分别记录。服务端核验身份、项目权限、单次权益与版本一致性。
- 家人问题与大纲题共用推荐规则；推荐轮次与本次进入周期分开，重开一轮不能使本次稍后回答的题提前回流。
- 照片归属项目，上传素材与采访、故事、封面引用分开；删除本次关联不删除其他引用或固定版本素材。
- 新故事按有效问题章节归章，无章不默认入第一章；PDF 只收录当前目录引用的故事，取消空目录全收录回退。
- 当前书稿可更新，已提交制作和书中原声保持固定版本；未归章不要求强制清零才能成书。
- 统一白底、橄榄绿、功能标题、精简文案和进度条。移除重复入口；首页问题与讲述按钮一起滚动。
- 数据结构破坏性更新使用 TimeNook 的开发环境与隔离夹具，可按需重建开发数据库。不为旧开发数据编写回填迁移或兼容层，不操作其他产品的数据。
- 共享契约变化时，同步现有网页及后台消费者，使其已有功能继续工作；不扩展为网页视觉重做，不依靠旧响应别名维持兼容。
- 正式包排除场景切换器、模拟个人数据和验收账号；样书清楚标记公共示例。
- 新增礼物号码、成员关系、问题作者及项目素材字段时同步现有资料删除登记；复用已有权限和删除能力，不另建治理流程。领取不使购买者已准备的素材失效。
- 模块分支汇入同一集成分支，按真实依赖推进；主干合并遵守仓库必要检查，不额外建立逐票多轮审核门槛。

## 验证决定

1. **用户可见路径**是验收主线。每票通过公开入口操作，验证可见结果、返回路径和持久化数据；不只测试内部函数或把测试直接设置页面数据当成集成通过。
2. **71 张画板逐项对照**：记录画板、原生路由/状态、角色与数据前提、进入路径、设计参考截图、原生截图、交互结果和缺陷结果。以 390px 和 320px 可用内容宽度检查，字体/字重、间距、尺寸、照片裁切、颜色、滚动、键盘、安全区和触控范围均纳入。
3. **平台界面分开记录**：微信授权、支付收银台、系统 PDF 查看器外壳不由应用控制。应用页面、系统调用与 PDF 内容必须分别核对，不能用浏览器原型截图替代开发者工具或真机证据。
4. **现有测试边界优先复用**：登录与页面控制器行为测试、支付和成员接口、项目大纲/故事/PDF 测试、原生编译及官方开发者工具自动化；数据库唯一性、并发领取、章节归属和权益使用真实 PostgreSQL/Redis。
5. **真实服务结果单独标明**：合成音频、硬件替身、支付替身仅证明对应开发路径；手机号授权、真机录音、实际资金、供应商及实物未完成时列待验，不冒充通过，也不阻断其他已具备契约的本地功能。
6. 每票执行相关检查并同步其 UI 证据；最后汇总跨模块走查和仓库配置的必要 CI。只有新增修改、失败或证据缺口才补验，不无依据重复全量。

## 不在本轮开发范围

- 新支付渠道、共享支付服务改造、运营模板管理、多模板或实时语音通话。
- 新增语音提问、语音祝福、独立首讲、可选准备、旧版兼容与历史开发数据迁移。
- 网页和营销官网的视觉重做。
- 微信提审、正式发布、真实扣款或印厂生产下单；这些外部动作与开发交付分别执行和记录。

## 交付

一个父规格、十二张模块/集成票和一份完整画板对照表。每票声明阻塞依赖、实际交付与剩余真实验收。仅功能已交付的票可以按仓库规则关闭；尚有功能缺口保持未完成。

当前设计走查记录不作为新小程序验收证据。六十题内容以当前初稿开发，内容审校另记。最新登录提示以已确认文字规则同步画布与小程序。
