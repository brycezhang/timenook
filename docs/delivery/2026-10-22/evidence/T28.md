## 用户与运营行为

- 当前买方或绑定讲述者从实际订单、书稿或生产记录选择已交付尝试并申请，不手填技术 ID。共享工单记录原单、PDF hash、物流、处理人、核验截止、进展及结果。
- 本人或本次合规同机证据明确授予当前客服限时 PDF/说明 scope。该授权不授予买方私人共享；其他客服、到期、结束协助与相关撤回拒绝读取。PDF 按实际页渲染，离页、切号和到期清理；主动另存的文件不能远程收回。
- 原文件重印重验原 PDF 内精确故事版本的当前入书许可；改稿须实际生成新 PDF 并取得双方 fresh 同版确认。普通 consumed 首本提交不能复活，原单最多一个活动交接，未知接单及取消待核实仍占位。
- 退款走原退款用例及稳定单号，不手填资金成功；后续交付不改首次交付/D03。撤回后仍可填写新的商业质量申请，持续不可读状态不会反复清空新输入。

## PR 候选复审后的定点修复

PR #65 候选 `e2413b4` 的独立 Standards 审查发现二次申请后高亮为新工单、实际操作对象仍为旧工单。公开 Page 用例先复现旧对象 `666…` 与新高亮 `777…` 不一致，再验证新申请成功时原子更新两者；切换工单同时清除旧 scope、确认、授权/退款重试意图与同机协助选择。迟到轮询不能恢复旧工单，同一当前操作网络未知时仍保留原 key/授权到期时间，跨工单后须重新确认。

实际 HTTP 浏览器在原有第三条流程中新增：旧工单选择 PDF/同意但不提交 → 提交另一质量问题 → 新待领取工单高亮且旧授权控件消失 → 运营实际领取 → 本次重新同机选择 → POST 精确新工单的 `/access`，返回新工单 ID。最终三场 **3/3**，`390×900` 与 `1280×900` 截图可见新工单选中及新授权截止，页面身份、非空、遮罩、console/pageerror 与溢出检查通过。两端同一原因/状态词表统一为无平台或 session 依赖的纯常量，不改变文案、权限或商业规则。该修复单独验证时前端/运营类型与构建、Mac wcc/wcsc **23 页**再次通过；随后合入 T25 的整票结果见上表，完整 CI 与最终集成头独立复审仍由 PR 记录。
