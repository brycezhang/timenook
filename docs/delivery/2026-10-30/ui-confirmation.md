# UI-2 开始与故事确认

消费 #116 / `404a137`、受控网页/原声增量 `dd2f197`，并合入双端 UI 集成分支 `f062510`。以本日最后一轮用户反馈为准：不增加入书用途类别或单独用途说明。

## 已实现

- 本人开始页保留一句保存、AI 整理及与发起人核对的介绍，资料详情默认折叠。访问和展开不写授权；「确认并开始」调用 `POST /projects/:id/consents/start`，在现有项目/本人锁与幂等命令内一次保存采集、AI、共享三项事实，再进入共源讲述流程。当前告知、讲述者、实际账号及本次点击标识保留。
- 用途调整、拒绝、撤回、删除、绑定与工单入口保留；服务页的 `welcome?projectId=...&manage=1` 直接展开管理。同机协助身份与独立当次核验保持原规则。
- 故事阅读区只保留「确认」，没有复选框或说明输入。实际点击提交确定版本、内容 hash、当前告知和 `click:story-confirm:<command>`；API 继续执行本人/当次协助、版本及核对项校验。没有既有否决时记录内容确认及允许入书；已有明确拒绝默认保留，修改文字不沿用旧内容确认，也不会自动扩大拒绝。
- 在既有「修改、照片与原声」→「回听已保存的原声」展开区保留「调整本版决定」，支持明确撤回或重新允许。原声暂停、续播、拖动与时长保持。
- 网页使用原生 WXML 共源渲染，新增接口同时加入 runtime 与开发代理白名单。无需数据库迁移。
