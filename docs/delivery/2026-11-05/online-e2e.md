## 过期场景与保留覆盖

本轮初始重跑前端为 471 项：331 通过、140 失败；较早部署记录的 454 项是当时的历史结果。API 初始为 634 项：278 通过、356 失败，其中大量失败由共用旧绑定／用途 fixture 引起，不能等同于 356 个独立产品缺陷。

- 删除已取消的身份审批、同机协助、逐项用途确认、故事本人确认、双方印刷确认及独立资料／售后菜单测试。改用当前项目成员、直接章节编辑、书封／照片选择、PDF 和直接印刷规则。API fixture 通过真实邀请接受加入，保留数据库与 HTTP 验证。
- 录音和照片按自动上传测试；旧的手动保存／提交步骤退出默认链路。新原生线上入口每次先构建正式包，替换旧登录、旧 MVP 脚本；设计检查和实际服务检查分别报告。
- 保留支付与首本权益、并发幂等、供应商结果未知、额度、确定版本、越权与临时文件清理回归。历史书中原声不随新稿改变、明确取消后更正地址／书稿并在原单重新提交的三项回归已按新规则恢复。
- API 测试执行前清理 `dist-test`，避免已删除的编译产物继续执行；并发限制为 2，避免测试进程耗尽 PostgreSQL 连接，不设置跳过项。

## 修复的问题

1. 登录／退出开始即使旧页面请求失效，避免迟到的旧会话覆盖新账号。
2. 照片自动上传串行处理，持续处理上传中追加的批次；返回前等待上传和说明保存，避免重复上传、版本冲突或漏图。
3. 私有下载写入小程序自身 `USER_DATA_PATH`，避免平台临时文件不可删除导致封面预览阻塞；音频保留正确扩展名。照片清理串行执行，批量预览互不删除；清理暂时失败后允许重试。当前登记使用自有文件格式，不为旧开发格式增加兼容层。
4. 导出、删除进度和质量服务按项目成员权限核验；受邀用户接受条款并保留首次参与事实，不恢复旧本人专属门槛。
5. 自动整理替换尚未发给供应商的旧任务时，不重复消耗用户额度；相同输入的待执行任务复用。已有供应商尝试及未知结果仍保留计费和查询约束。

## 线上证据与边界

使用官方开发者工具 `2.02.2609240`、稳定基础库 `3.17.5`，正式包开启合法域名检查。真实 `wx.login`、HTTPS API、OSS、ASR、追问、故事整理、PDF 和原生音频播放均实际执行。只替换麦克风和相册的输入，内容明确为虚构的纸船故事及合成配图。

15 步覆盖：正式构建／域名门禁、真实登录、内部未付款项目、微信邀请直接加入、暂停继续及自动上传、可选追问、自动整理、正文直接编辑并重开、章节故事选择、照片说明与书封选择、6 页完整 PDF 校验和打开、冻结原声 hash 及原生播放、内部项目不可实体印刷、退出撤销。匿名请求被拒绝；输入临时托管、两个会话和自动化窗口均完成清理。

部署前运行客户端为本轮修复代码，服务端仍为 `203dbaa`。脱敏结果见 [线上结果](native-online-before-deploy.json)。业务 HTTP 替身的原生页面检查见 [页面结果](native-design-regression.json)，该检查验证首页、两 Tab、编辑与选择入口、书封和微信客服按钮，不代表真实客服接待。

本轮没有创建真实付款，没有真人录音、双真机协作、客服接待或实物生产／物流验收。内部测试项目没有付款和实体书权益。部署后复测、小程序上传与测试成员清理另行追加实际结果。

对固定代码快照独立进行 Standards 与 Spec 审查。两轴最终均无新增可操作问题；已验证追加照片批次和清理失败恢复，并保留上述三项版本／履约不变量。
