# [后台 B03] 生产单人工交接、完成印制与发货

GitHub：[#153](https://github.com/brycezhang/timenook/issues/153) · Parent：[#150](https://github.com/brycezhang/timenook/issues/150) · ready-for-agent

## What to build

运营从生产列表找到确定书稿，核对条件并获授权下载 PDF/地址，线下对接印厂，随后登记完成印制、发货/物流及交付；异常和取消在同一详情处理，两端显示同一事实。

## Acceptance criteria

- [ ] 管理生产列表支持订单/生产/项目标识及适用进度、待处理/异常筛选、稳定分页和详情 URL，能从原订单及用户关联项目进入并返回查询位置。
- [ ] 审核重验同版 PDF、双方确认、地址、付款/首本权益及当前授权；领取本次确定文件时验证完整性和当前授权，不要求日常手填内部工单 ID/hash。
- [ ] PDF 完成、印厂接单与实际完成印制分别记录；新增完成印制的独立事实、操作人及时间，主进度为 PDF 书稿完成→已生产→已发货/物流，绝不只把接单改标签。
- [ ] 人工登记发货公司/单号/时间和实际交付；适用微信平台处理结果独立于物流事实，不要求运营用虚构成功值才能登记实际发货。
- [ ] 交接、未知结果核实、取消和取消失败在详情提供当前允许动作；退款/撤回冻结、唯一权益、固定版本与幂等保持，不自动重发未知交接。
- [ ] 各次制作/重印记录可追溯并供订单售后消费；两端生产进度与同一记录一致，长期服务不因等待时长变为到期审核。
- [ ] 通过公开 HTTP+浏览器及用户端行为验证全流程、并发/冲突/授权失效；核实当前公开运行配置确实装配这些能力，印厂/物流自动接口和实物验收分别在范围外/原责任票。

## 验证与交付

以 HTTPS 后台浏览器联通实际管理 HTTP 验证公开行为；锁、唯一性、重复操作和重启使用真实 PostgreSQL/Redis，仅外部供应商网络可隔离替换。复用既有相关范例，完成定向回归、类型、构建、独立 Standards/Spec、最终 PR CI 及合并后 main CI。读取最新主分支的已有业务/支付/内部验收交付证据，核实实际装配；代码存在或替身通过不代表正式可用。真实账号、资金、设备、供应商和实物结果单独记录。

开发直接硬更新，按需重建数据/夹具；不做旧开发数据迁移、历史兼容、备份准备、旧库恢复或回滚演练。禁止私密样本和凭据进入 Git。
