# 小程序全局加载反馈

用户要求：优化全局 loading，参考微信小程序惯例或内置能力，不用纯文字占位或空白等待。

## 实现

- 全局注册轻量 `app-loading`，沿用纸面米色和橄榄绿，不增加图片资源或第三方 UI 依赖。项目、书籍、故事、列表和表单各用相应结构的呼吸骨架屏。
- 首次读取与提交操作分开：`pageLoading` 只在读取必要数据时显示骨架，保存/生成继续保留已有内容，使用按钮原生 `loading`。首页同一项目返回和故事任务后台轮询保留当前内容。
- 照片下载、原声下载、录音保存/上传与追问准备加入局部旋转指示。照片列表缩略图读取失败结束动画并显示图片图标；保留已有错误说明和重试操作。
- 初次读取成功或失败均退出骨架，离页和失权清理同步关闭加载态；不改变权限、文件校验、业务请求或资金规则。

参考微信官方 [button loading](https://developers.weixin.qq.com/miniprogram/dev/component/button.html) 和腾讯 [WeUI 加载组件](https://github.com/Tencent/weui/blob/master/src/style/widget/weui-loading/weui-loading.less) 的按钮反馈与持续旋转形式。页面内读取使用局部组件，不引入全局弹窗和请求拦截状态。

## 验证

- 97 项相关页面定向回归通过，涵盖首页/账号、书稿与编辑、故事、录音、照片及纸书原声。补充首次成书读取等待完整数据、失败退出加载、生成过程中保留现有书籍的断言。
- `pnpm typecheck:frontend`、`pnpm build:miniprogram` 和 `node scripts/check-native.mjs --built` 通过；正式包 29 页 WXML/WXSS 原生编译通过。
- 官方微信开发者工具已观察首页书形骨架与照片读取转圈，页面使用受控数据进入加载态，观察后恢复真实项目内容；截图保留在 Git 外。正式构建热更新期间工具曾缓存到未写完的 JSON，清理编译缓存后已恢复正常项目首页，未清除登录或用户数据。
- 本轮未部署后端、未上传体验版或提审。真机动画观感待用户实际体验。
