# 资料删除与恢复前重放（T26）

本票 [#27](https://github.com/brycezhang/timenook/issues/27) 消费 T24 撤回与 T25 完整导出。工程决策见 [ADR 0014](adr/0014-independent-privacy-ledger.md)。本文描述本地机制和复现入口；当前实现、集成和审查尚在进行，不能据此宣称本票或正式恢复验收通过。

## 删除申请与逐层结果

沿既有 `POST /v1/projects/:id/care-requests` 申请 `kind: delete`，由具有 `care:write` 权限、MFA 和 CSRF 的运营人员沿原核验入口处理。核验先持久化独立拒绝依据，再投影永久项目墓碑和逐项清单；活动清理失败只进入重试，不能撤销已经生效的拒绝。重新同意不能恢复永久删除的项目。

| 入口 | 用途 |
| --- | --- |
| `GET /v1/projects/:id/deletion-status` | 当前发起人/绑定讲述者查询最少状态，内容拒绝后仍可访问 |
| `GET /v1/admin/care-requests/:id/deletion-status` | 删除工单的运营逐层状态 |
| `POST /v1/admin/care-requests/:id/deletion/reconcile` | 重试系统负责的活动清理 |
| `POST /v1/admin/care-requests/:id/deletion/items/:itemId/evidence` | 为历史对象、备份或供应商的一个项目记录受限核验引用 |

清单区分活动数据库、活动文件、缓存、对象历史版本、备份和供应商副本。一个项目完成只证明其对应层完成，没有人工总 `deleted` 开关。未冻结期限保持空值和待处理原因；回执不能建立或延长未经确认的期限。当前运营证据接口只接受明确隔离的 `record:synthetic-…` 引用，真实接入仍须 D03/D08 准入。

用户页分别呈现在线访问停止、活动清理、备份待到期/核验和外部待确认，不返回姓名、正文或地址。客户端复用 T24 的页面权限重验和临时音频/照片清理。设备原始录音、主动另存的 PDF/导出及纸书不由平台远程取回；新权利请求的输入也不作为旧资料缓存清除。

## 清理范围与不变量

`care/erasure-registry.ts` 与迁移中的登记表列明私有 payload 的类别、字段及行键。范围包含个人计划/实际问题、转录及各处内嵌副本、故事/追问输入输出、照片、书稿快照/检查文本、原声关联、导出清单、地址和运营私人证据。数据库触发器将擦除限制到已经登记的删除项，保留原有 FK、版本、金额、首本/生产及退款事实；不提供忽略全部 immutable 约束的开关。最少身份/哈希/权利/财务事实仍可能可关联，其依据、访问人和独立保留期限需要负责人确认。

随机输出和临时运行先登记持久所有权，再执行 I/O；已经有持久编号的录音、照片、书稿和导出复用其原标识。事件捕获当时的精确存储目标和任务范围，恢复时与旧库可发现目标合并，清理不扫描删除整个 Bucket 或其他项目的临时目录。活动文件会重复清理，以覆盖已经签发的上传或迟到写入；旧任务依 T24 拒绝，不因新 lease 或新授权重获资格。

D03 保留期限由原销售政策及原起算事件决定，通过到期扫描进入同一台账。制作期限或退款不代替资料保留期限。类别与副本层分别报告；某类原始素材到期不能直接缩短仍有效 PDF 的独立期限。嵌入副本、类别重叠和运营证据归属须使用明确选定的合成映射验证，正式规则仍待冻结。

## 独立源与恢复门闩

独立源包含受限的事件目录、固定锁文件和认证 head；32 字节密钥在业务备份和发布包之外托管。发布通过原生非阻塞 flock 串行化，在事件文件及目录同步后发布 head。缺失、截断、损坏、分叉、错误权限或数据库 authority 不符都拒绝私有能力；半写临时文件与完整认证后继按固定协议恢复。单事件上限 16 MiB，超限失败而不截断删除目标。

独立源是拒绝依据，业务库中的 `privacy_events` 和清单是投影。恢复前校验来源及连续 checkpoint、重放拒绝/永久墓碑，再执行活动清理；无法解释的目标或不一致不能静默跳过并宣称 ready。API 门闩位于 `app.init()` 触发的定时任务前，Worker 在恢复扫描、领取和供应商交互边界复验；健康探测的存活不代表私有能力可用。

活动进程固定绑定规范化数据库位置、数据库安装 UUID 和 authority 代次。恢复切换使用显式命令，在目标库重放后提升独立源代次；旧 API/Worker 不能跟随新代次自行继续。全源及认证 head 一起退回合法旧版本的检测依赖正式独立介质与运维防回滚措施，不能用本地 HMAC 代替。

## 本地入口与验证边界

仅使用回环 PostgreSQL/Redis、隔离 schema/前缀及合成资料。测试通过 `test/privacy-fixture.ts` 在迁移后显式创建独立源；重启复用同一个源，不在应用构造时自动创建。依赖安装须按仓库锁定的 Node/pnpm，`fs-ext` 是显式允许编译的原生依赖。

已编译 CLI 的入口如下，实际数据库身份须由配置位置和安装 UUID 派生；不要给一个随意 UUID 代替目标身份。密钥文件和源目录必须在 Git、业务数据和发布包之外。

```text
pnpm --filter @timenook/api privacy:journal bootstrap --root <独立绝对目录> --key-file <受限密钥绝对文件> --database-id <目标派生身份>
pnpm --filter @timenook/api privacy:journal inspect --root <独立绝对目录> --key-file <受限密钥绝对文件>
pnpm --filter @timenook/api privacy:recover activate
```

`bootstrap` 只允许明确的新源；`inspect` 只输出脱敏 head 元数据，不输出正文或密钥。恢复命令须先准备已经迁移的隔离目标库、原独立源及受限配置，不能在正在服务的业务库中试运行。测试专用配置文件入口额外要求 test 环境与回环数据库，不能用它接入正式环境。

真实 PostgreSQL/Redis、文件清理、独立进程恢复、故障窗口、到期边界及公开 HTTP 的最终结果在本票证据中另记。真实 D03/D06/D08、Linux/ECS 介质和权限、备份轮换、供应商回执及双端设备仍须各责任票验收；T29/T30 未由本轮实施。
