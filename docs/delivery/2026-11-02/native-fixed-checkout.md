# 原生固定套餐与订单恢复（#143）

本票消费 #142 的公开契约：`CurrentPackage.checkout` 由服务端给出资格及实付，套餐标价固定 99900 分；`PaymentOrderView` 分别返回 `listAmount`、`amount` 和 `isE2e`。本机工程实施与真实付款、供应商、Pixel 7 和实物结果分别记录。

## 已实现

- 正式 live 套餐页读取当前账号资格，展示 ¥999、确定条款与配送地区。只有获授权的支付验收路径展示实付 ¥0.01；普通订单实付 ¥999，前端不提供金额或优惠输入。
- 付款前确认服务说明；创建请求前持久化用户、API 分区的订单意图与幂等键，打开微信前持久化原订单编号。真实 `wx.requestPayment` 的成功、取消、失败与未知结果均查询服务端原单；界面不自行置为已付款。
- 重进套餐页恢复原意图；重试先恢复原单并进入订单页，不重新创建付款项目。订单页恢复待付/已付订单，允许继续真实付款、取消及查单。未知关单结果也重新查原单；已付项目入口固定指向该订单项目。只有服务端已查明终态后，用户明确选择另一位讲述者，才开始新购买意图。
- 正式构建继续移除网页、探针、演示页面与本地验证控件，保留真实订单付款/取消按钮。`paid-e2e` 项目可沿用服务端当前告知与证据前缀进入邀请、本人用途和同机协助；付款不代替授权。

## 已付项目内容 E2E

构建正式包后运行：

```sh
TIMENOOK_PAID_PROJECT_INPUT=/absolute/private/paid-project.json \
  pnpm run test:native-mvp -- --paid-project
```

输入必须为绝对路径、仅所有者可读写的 JSON 文件，只含 `orderId`、`projectId`。脚本使用当前真实微信会话查询原单，要求 `paid`、`wechat`、标价 99900 分、实付 1 分、`isE2e: true` 且项目完全一致；不符合即终止，不创建内部项目替代。

脚本创建独立网页验收讲述者账号，用真实邀请、账号绑定与本人用途接口参与该已付项目。原生发起人走已有同机协助采集与照片路径；网页讲述者用自己的会话确认每个故事版本，原生发起人与网页讲述者分别确认同版 PDF。其音频、照片、叙事与操作仍为明确合成输入，不能据此声称真人本人授权或目标用户验收。

网页验收账号的重新进入凭据保存于输入文件旁的 `.narrator.json` 受限文件，便于供应商失败后仍在原项目、原讲述者账号重试。该文件不得提交或展示。清理只撤销当次会话及临时输入，不删除付款、项目、本人选择或确认事实。
