# 时光里 MVP 实施规格

状态：2026-10-22 用户确认按复杂度复核收敛实施方式；保留全部 MVP 功能、T01–T30、父子关系和 45 条依赖。固定首版政策、复用探针能力、采用受控人工运营；文档修订不证明代码或验收完成。

## 问题与结果

实施起点为使用本机演示数据的 15 页原生小程序和浏览器预览；真实支付、讲述者授权、可靠原声保存、本人版本确认及实体交付仍需逐票验收。基于 2026-10-20 已定稿方案，把“真实原声 → 经本人确认的故事 → 确定书稿 → 同一版本实体交付”逐步接成可验收的服务。

一位成年讲述者、一位发起人、一个项目、999 元和一本首本实体书是首版边界。关系称呼动态可配置；制作、访问、保留及售后期限以不可变销售快照为准。尚未冻结的参数通过对应 ticket 形成证据，不在开发过程中擅自补值。

## 用户故事

1. 作为发起人，我希望先看清套餐、样书、配送和售后条款，以决定是否购买。
2. 作为发起人，我希望选择关系或自定义称呼，以表达赠礼对象而不改变价格和权限。
3. 作为用户，我希望微信登录后只访问自己获授权的项目，以保护不同家庭的资料。
4. 作为发起人，我希望付款后自动建立默认项目、计划和首本权益，以直接邀请讲述者。
5. 作为发起人，我希望退出后恢复同一订单和权益，以避免重复扣款及创建项目。
6. 作为讲述者，我希望看清邀请人和用途后申请参与，以决定是否授权。
7. 作为发起人，我希望确认真实申请人，以防转发邀请被陌生人冒领。
8. 作为讲述者，我希望分别选择采集、AI处理、共享和入书，以保有资料决定权。
9. 作为没有个人微信的讲述者，我希望在场授权他人协助，以完成记录并保留本人的确认和撤回权利。
10. 作为双方参与者，我希望调整章节、问题和顺序，以形成适合本人的采访计划。
11. 作为讲述者，我希望跳过、不适用或禁问某个主题，以避免被强迫回答。
12. 作为讲述者，我希望从默认问题、照片或自由讲述直接开始，以减少准备负担。
13. 作为讲述者，我希望停录后明确区分本机保存和云端保存，以知道资料是否安全。
14. 作为讲述者，我希望弱网、中断和退出后恢复已保存片段，以避免全部重录。
15. 作为讲述者，我希望转录完成后才收到一条可选追问，以按自己的节奏继续或结束。
16. 作为讲述者，我希望照片原图和衍生图分别保存，以兼顾预览和印刷质量。
17. 作为讲述者，我希望生成稿保留模糊与矛盾事实并指明来源，以方便本人核对。
18. 作为发起人，我希望协助文字校对但不替本人确认，以保留真实讲述者的决定权。
19. 作为讲述者，我希望确认具体故事版本并单独决定入书，以避免修改后的内容沿用旧授权。
20. 作为双方参与者，我希望主页显示真实阶段和下一步，以知道当前需要做什么。
21. 作为双方参与者，我希望完整预览同一份含全文、照片和原声码的 PDF，以逐页校对。
22. 作为讲述者，我希望内容变更后重新确认，以避免错误版本进入生产。
23. 作为发起人，我希望确认 PDF 和地址后使用首本权益，以无需再次付费取得一本实体书。
24. 作为运营，我希望交接时核对文件 hash 和接收回执，以避免错版或重复印刷。
25. 作为双方参与者，我希望查看真实物流并扫码听到所印版本原声，以完成实体交付体验。
26. 作为讲述者，我希望撤回后停止相关访问和处理，以控制后续使用范围。
27. 作为获授权申请人，我希望取得无需依赖平台读取的完整资料包，以保存自己的记忆。
28. 作为讲述者，我希望删除请求分别说明活动数据、备份和外部副本进度，以了解实际执行情况。
29. 作为发起人，我希望退款与质量售后可追溯且不重复退款，以按公示规则解决问题。
30. 作为运营，我希望识别失败、重试、回滚和恢复服务，以持续完成已售项目。

31. 作为发起人，我希望按购买时的规则查看制作期限、暂停和到期处理，以安排完成首本而不误以为资料同时删除。
32. 作为讲述者，我希望回听、导出与资料保留期限分别执行并可查询，以按约定保存自己的资料。
33. 作为讲述者，我希望账号需要更换时由客服核验本人并撤销旧账号访问，以继续原项目且不让他人继承授权。
34. 作为资料接收者，我希望下载的故事、PDF 和资料包说明 AI 整理与人工校对来源，以正确理解文字和真实原声的关系。
35. 作为不熟悉手机的讲述者，我希望按钮和正文清楚可用、能够快速开始录音，以独立或在协助下完成讲述。

## 实现决策

- 原生微信小程序保留，Vben 采用 web-antd 路线；后端 NestJS/Fastify 模块化单体，API、Worker 和 PDF 渲染分进程。
- Prisma/PostgreSQL 保存业务事实、约束、版本、Inbox/Outbox；BullMQ/ioredis 负责调度，Redis 丢失可恢复。
- 阿里云 ECS 与 API 域名复用 legal-agent，TimeNook 以 `/timenook` 路径分流，见 [ADR 0009](../../adr/0009-shared-ecs-api-path.md)。2026-10-25 按 [ADR 0011](../../adr/0011-shared-oss-and-deepseek.md) 进一步共用 deed 的 OSS AccessKey 和 DeepSeek API key，覆盖旧票据对应凭据独立要求；Bucket 按后续 [ADR 0013](../../adr/0013-dedicated-oss-bucket.md) 独立为私有 `timenook`。应用进程、数据库、队列及微信身份继续独立。ASR 为豆包文件识别，追问/整理为 DeepSeek，供应商经服务端适配器接入，无自动跨供应商回退。对象前缀、STS 与清理隔离须独立验证。
- 沿用 T01 已验证的 Node/pnpm 与依赖基线；实际升级时补受影响兼容验证，不重复初始化验收。
- 登录账号、讲述者 subject 和操作人分别记录；关系、付款、管理员身份都不自动授予私人内容或本人确认权限。
- 录音先持久保存及封存再转写；原声、原转录和 AI 稿独立，用户等待时可离开、补录和恢复。
- 后端内置一套默认模板，不实现运营模板创建/编辑/发布和多模板选择/切换。模板、个人计划、实际问题、故事和书稿分别版本化；旧项目不随代码模板更新改变，个人大纲和问题仍可编辑。
- 关键命令使用幂等键、expectedVersion、真实数据库唯一/复合外键与统一锁顺序；撤回/删除以 epoch、墓碑及任务 fence 防止迟到结果生效。
- 支付回调与查单共用核验入账；首本唯一；退款金额与权益影响分开；人工交接的未知结果不能自动重发。
- 受控媒体网关鉴权播放、PDF 和导出；包括缩略图在内均保持私有，下载至设备后的副本边界如实告知。
- 管理端与各小程序行为随对应 ticket 交付，不先建齐全部业务表。S0 测试入口只用于受控样本，不能作为生产授权替代。

- Commerce / LifeProject 只执行首版选定政策，按销售快照及幂等起算事件计算独立服务期限；IdentityAccess 提供本人参与及客服换绑，Fulfillment 提供交付事件，Media / Care 执行访问和保留到期。T10/T11/T12/T14/T21/T22/T23/T25/T26/T29 分别承担计算、事件、限制与恢复验收。
- 客服换绑保持讲述者 subject 不变，使用 D08 核验证据、工单、绑定版本和 access_epoch；旧账号本项目权限立即失效，新账号重新授权，历史确认保留。
- Book / Care 将适用的 AI 整理和人工校对来源标识随版本写入 PDF、确认稿及导出说明；真实原声不标为合成音频，具体适用方式由 D08 核验。
- 用户接口内部为 `/v1`，运营接口为 `/v1/admin`，支付/退款通知为 `/v1/webhooks/wechat-pay/payments` 与 `/v1/webhooks/wechat-pay/refunds`；公网统一加 `/timenook`。代理只剥离一次前缀，完整映射以 ADR 0009 为准，通知及部署由 T10/T27/T29 验收。

### 首版固定政策

首版只售一套 999 元套餐，采用一份经确认、可兑现的政策版本；版本可随套餐快照保存，无需另建通用政策平台。固定的是一组已选规则，具体数值仍由 T05 及对应 D 项负责人冻结；未决定项保持 pending，合成配置只用于测试。现有校验器能表达的枚举不是必须全部实现的分支。

| 政策 | 首版要冻结的唯一选择 | 执行归属 |
| --- | --- | --- |
| D02 制作权益 | 一个起算规则、未开始处理、暂停是否停钟及上限、制作到期动作 | T05 决定；T10 统一计算；T11/T12 提供参与事实，T14/T22/T23 执行限制 |
| D03 资料服务 | 分别确定回听、导出申请、包下载、各类资料与副本的期限/起算及到期处理；适用相同条款的类别可共用规则 | T10 保存适用期限；T21/T25/T26 执行，T23 提供交付事实 |
| D04–D06 额度、配送和人工时限 | 一组录音/照片/生成额度与供应商预算、一份地区清单、各服务时限与实际负责人 | 各消费者读取快照；客服处理超额、地区及履约例外 |
| D07 退款与质量处理 | 每类已约定情形的一项救济、金额、窗口及权益后果；保留部分退款和原单重印 | 客服核验事实及归类，T27/T28 执行受控动作 |
| D08–D10 授权、内容、关系 | 首版本人/协助/客服核验及供应商路径、一套默认大纲和一份关系目录 | T05/T09/T08 分别冻结；动态关系和个人计划编辑保留 |

D01 使用 T04 验证的一套书籍规格和排版。政策修订通过审核后的新版本生效，已购订单继续读取原快照，必要的历史版本执行仍保留；不批量迁移旧订单。人工决定不豁免本人授权、资金上限、版本确认或删除规则。尚未选定的暂停/起算等分支不提前建设，实际采用的边界与异常必须验证；销售承诺变化先更新决定、快照和受影响测试。

### 探针复用与生产集成

S0 的退出标准是已选方案的风险证据和可复用能力。完成其真实验收后，探针保留为受控诊断/回归入口，停止增加产品功能；不因本次简化删除已验证代码。下游在票据中记录复用的实现/提交、适用配置和生产增量，已有能力不另做一套。

| 来源 | 复用能力 | 生产票负责的增量 |
| --- | --- | --- |
| T02 | 录音生命周期、音频检查、私有暂存/封存、对象存储 adapter、Range 读取 | T14 接入项目/主体/用途、额度、片段与任务事务；T21/T24 接入版本回听及活动访问撤销 |
| T03 | 豆包/DeepSeek adapter、稳定外部请求、状态/错误映射、输出校验、提示词与计时口径 | T15 集中生产持久任务、Outbox、Worker、恢复与扣额；T17/T18 接入问题/转录/故事版本和本人偏好 |
| T04 | 图片转换、固定字体/PDF 渲染、分页、二维码与产物检查 | T16 接入生产资产归属；T20 接入确定书稿与来源标识；T21 接入真实书中原声路由 |

复用实际可共享的模块和 adapter，必要抽取随消费者票完成；不把 Probe 实体、测试身份或合成样本迁成生产身份/数据。通用任务由 T15 建立，T17/T18/T20/T25/T26 按任务类型复用；本轮不要求预建所有任务类型、独立探针运营系统、动态工作流或多供应商自动切换。保留已定 API/Worker/渲染分进程与资源限制。

### 人工运营边界

Vben 沿用现有登录和目录，业务票逐步补一个共享工单列表/详情、必要的操作表单、进度及到期提示；用户仍能提交申请并查询结果。无需为每种情形建设独立后台或自动审批系统。到期提示指管理端展示与运营跟进，不新增订阅消息或用户自动提醒。

| 操作 | 人工负责 | 系统必须保证 |
| --- | --- | --- |
| 换绑、无微信本人请求（T11/T12） | 按 D08 核验本人、范围和证据，记录工单 | 同一 subject、旧权限撤销、新授权、绑定并发与审计 |
| 校对、生产交接和物流（T19/T23） | 必要校对、审核、联系印厂、核对回执及录入物流 | 改稿重新确认、确定 PDF hash、唯一交接与权益，未知接单禁止重发；适用的微信发货管理仍完成 |
| 完整导出（T25） | 核验范围、发起/监督打包、核对并交付 | 受控工具生成完整文件/manifest/hash；完成和领取时鉴权、期限及来源标识；无微信替代交付留证 |
| 撤回、删除（T24/T26） | 处理身份争议、联系供应商、核实外部副本回执 | 访问立即失效、墓碑、活动数据清理、到期补扫和备份恢复防复活；不能等人工处理才撤销有效访问 |
| 退款、质量与重印（T27/T28） | 按冻结政策归类、批准金额/救济、核验印厂状态 | 资金预留/查单/对账、原单重印与版本确认；人工不能直接写成功状态 |
| 任务失败（T15 及消费者） | 判断脱敏错误，决定有限重试或接管 | 同一业务用例执行、稳定意图、预算/扣额与迟到结果检查 |

人工执行也须有实际处理人、D06 时限、状态与证据；这些结果纳入验收。管理端调用同一业务用例，CLI 仅用于受控维护/辅助执行，不代替票据要求的用户申请、状态查询或必要运营入口。

## 测试决策

每票以最高可用的公开入口验证用户可观察行为，沿用 TDD 与相关审查；同一行为不在多层重复断言。已有 CLI 或事务内公开模块不为测试新增 HTTP，消费者补鉴权与事务组合。唯一性、锁、并发和恢复使用真实 PostgreSQL/Redis，仅供应商网络可用测试替身。实际微信、云服务、供应商条款/账单、双端设备和印刷结果按责任票留证，自动测试不替代它们。

### 验收复用与唯一归属

一项能力由责任票留存主证据，消费者引用证据并验证新增集成行为，不在各层重复整套测试。复用须匹配实现提交、配置/协议、设备/环境和输入范围；变更、失败、证据缺失或范围不匹配时补验受影响部分。合成、真实供应商、真机、实物四类证据不能互相替代。

### 质量目标与证据归属

- T12/T14/T19 及其他面向讲述者的页面检查主按钮至少 48×48 逻辑像素；正文以 20 逻辑像素为设计起点，并由 T30 目标讲述者双端试用校准。检查正常/错误/等待状态，不靠缩小字号隐藏溢出；故事正文完整展示。
- T14/T19 提供“已绑定并授权、项目主页到开始录音”的完整路径；T30 记录目标讲述者、设备/微信版本、协助方式、计时起止和未完成原因，以不超过 60 秒为试点目标。
- T03 分别测量转录、追问和整理；T15/T18 贯通排队及依赖转写计时。T30 对总输入不超过 5 分钟的样本，以“用户提交整理且全部输入云端保存”到“成功出稿”为口径，目标至少 95% 在 3 分钟内成功；失败、人工接管及仍在处理的样本单列并保留在总体结果中，不靠排除失败达标。
- T30 在实测前记录样本规模、口音/设备/网络构成与排除规则，报告原始分母、成功率、达标比例和耗时分布。未达目标时记录差距与整改或经确认的目标调整，再决定是否进入付费试点；这些是内部目标，不能作为供应商 SLA 或已完成声明。
