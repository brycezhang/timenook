### 2026-10-28 普通商户配置决定

用户选择普通商户直连模式。以 `wutong_miniapp` 所调用的 `payment-service` 商户配置作为复用来源；TimeNook 独立对接微信支付，使用自己的身份、订单、通知和入账流程。配置来源与正式装配要求如下。T29 已将经只读接口验证的商户材料保存到 TimeNook 服务端受限待启用目录，未启用收款。

| 参数 | 配置来源与要求 |
| --- | --- |
| 商户号 | 来源 `PAYMENT_WECHAT_MCH_ID`，核验实际商户及 TimeNook AppID 绑定 |
| APIv3 密钥 | 来源 `PAYMENT_WECHAT_API_V3_KEY`，与所选商户号对应，经受限服务端配置交接 |
| 商户私钥与 API 证书 | 来源 `PAYMENT_WECHAT_MCH_PRIVATE_KEY_PATH`、`PAYMENT_WECHAT_MCH_PUBLIC_CERT_PATH` 指向的有效材料；验证匹配并提取对应序列号，目标文件路径按 TimeNook 环境独立设置 |
| 微信支付验签材料 | 使用该商户当前有效的微信支付公钥/ID，或平台证书/序列号；核验材料与标识匹配 |
| 小程序身份 | 使用 TimeNook 自己的 `TIMENOOK_WECHAT_APP_ID`、`TIMENOOK_WECHAT_APP_SECRET`；OpenID 由该小程序登录获取 |
| 通知地址 | 使用上文独立域名的 TimeNook 支付与退款接口，并验证公网通知 |
| 接入模式 | 普通商户，使用 `appid`、`mchid`、`payer.openid`；不配置服务商及子商户参数 |

来源变量名仅用于定位现有 `payment-service` 配置，不是 TimeNook 已支持的环境变量。T29 已接入普通商户 `readConfig` 与原生 HTTPS 装配，配置名见 `.env.example` 和 [T29 记录](../2026-10-28/t29-release.md)。用户明确独立小程序尚未申请下来，AppID/Secret 留空；商户材料仅在服务端受限目录待启用，不加载活动支付模式。回调已固定到独立域名；缺配置返回 503，真实下单仍因商品准入未完成而关闭。真实商户绑定、商品准入与收退款证据仍归 T05/T10/T27；这些票据的证据由 T30 复用。

部署顺序：先推进 T29 的工程装配、目标环境发布及恢复验收，再由 T30 衔接真实内部项目、双端、实物及付费试点验收。获授权的受控公网联调可先于两票完整关闭；正式部署验收归 T29，开放付费试点须满足 T30 门槛。配置决定本身不代表 T29/T30 或上游真实验收已完成。

## 真实验收与试点

T30 按[现有验收映射](../2026-10-22/README.md#验收追踪)复用适用责任票证据，补齐同一内部项目的付款→参与→录音/照片→本人确认→确定 PDF→首本→印厂接收→物流→纸书/原声/资料权利与售后。印厂文件 hash 须与双方确认 PDF 一致；模拟、真实供应商、真机、实物四类证据分别记录。

目标讲述者双端试用需记录设备/微信版本、协助方式、从已绑定授权项目主页到开始录音的原始计时和未完成原因；目标不超过 60 秒。出稿试验须事先记录样本数、口音/设备/网络构成与排除规则；对总输入不超过 5 分钟的样本，从“提交整理且全部输入已云端保存”计到成功出稿，报告原始分母、成功/失败/人工接管/未终态和耗时，目标至少 95% 在 3 分钟内成功。未达标先记录整改或经确认的目标调整。

销售仍须 A01–A24、X01–X06、D01–D10、T29 和实物/质量证据齐全，并获得实际售卖/招募授权。当前原生依赖与缺失真实验收保持，不因本地工程或本页整理关闭业务票据。
