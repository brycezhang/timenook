# 后台重构实施拆票草案

依据：[规格草案](admin-vben-refactor-spec.md)与已接受的 [ADR 0017](../../adr/0017-lifetime-service-and-retention.md)。本表使用审阅编号 R1–R8；尚未创建 GitHub 子票，测试入口、粒度与依赖待用户确认。确认后每票发布独立 issue 和原生 blocked-by，不改变既有 T01–T30 的真实验收责任。

2026-10-30 合并整理：R1/R2 的长期服务工程已随 [#105](https://github.com/brycezhang/timenook/issues/105) 交付，详见[开发说明](../../development-lifetime-service.md)；以下复选框保留原拟定的验收目标，不作为实时实施状态。后续后台票消费已交付契约并只补新增集成；真实设备、供应商和实物条件继续分别留证。

## 拆分与阻塞

本次开发重构直接按新模型硬更新，必要时重建相关开发数据和测试夹具；不做旧数据迁移、历史有限期兼容、旧备份/旧台账恢复、备份准备或回滚演练，也不为这些旧开发场景保留测试。新规则下的主动撤回、删除、权限校验及进程重启后的正确行为仍须验证。

| 编号 | 票据 | 阻塞于 | 可独立演示的结果 |
| --- | --- | --- | --- |
| R1 | 长期制作资格与服务期限操作退出 | 无新增票阻塞 | 套餐告知、录音与首本制作执行长期规则；双端无期限计时/审核入口 |
| R2 | 长期资料访问、完整导出与清理一致性 | R1 | 回听、资料和完整 ZIP 长期可用，自动扫描不误删；主动撤回/删除仍有效 |
| R3 | Vben 登录、主布局与路由导航 | 无新增票阻塞 | 飞书登录、权限菜单、面包屑、多标签、独立 URL 与刷新/回跳贯通 |
| R4 | 商品配置列表与编辑体验 | R1、R3 | 关系与套餐可查询、编辑、校验及预览，统一长期条款与权限反馈 |
| R5 | 客服工单列表与详情工作流 | R2、R3 | 分类查询、分页、详情及退款/质量/资料申请等动作完整可用，跨页关联正确 |
| R6 | 生产履约列表与人工进度登记 | R1、R3 | 从生产列表进入详情，核对 PDF、登记真实完成印制与物流，保留原单权益和取消约束 |
| R7 | 运行、任务与审计页面 | R3 | 各有路由与统一页面结构，任务和审计可过滤/分页并执行原有受控动作 |
| R8 | 整体回归与实际环境验收 | R2、R4、R5、R6、R7 | 同一候选完整通过业务/浏览器检查，实际入口和长期保留配置另行验证 |

R1/R2 是配套政策交付：中间工程提交可检查及合并，不能作为完整长期服务发布依据，实际切换须等 R8 的完整候选。R2 合并资料与完整包链路，避免将“长期可访问”和“后台仍按日期删除”拆成可发布的中间版本。R3 的应用组织可独立推进；业务页票只依赖它实际消费的政策与框架契约。

无新增票阻塞不表示无需前提：开工仍读取适用旧票与合并证据，确认当前登录、套餐、首本、媒体、客服、主动删除等所需契约已经交付。缺少真实账号、设备、供应商或商务条件时按项目规则分开记录。

## R1：长期制作资格与服务期限操作退出

**交付**：用户可在长期未开始或跨旧截止后继续录音、确认并提交首本；后台不再管理服务期限。

- [ ] 准入、套餐告知、中央服务政策及开发配置统一表达长期有效；不会要求负责人填写已取消的 D02 起算/暂停/到期字段。
- [ ] 录音及首本提交/审核不受业务时间经过限制，仍校验付款、唯一权益、授权和确定版本；退款冻结及生产争议保留。
- [ ] 删除服务期限菜单、权限、暂停/恢复计时和到期审核接口/工单类型；小程序无计时提示或到期审核动作。
- [ ] 底层确需日期时固定 `2099-12-31`，不成为实际截止；测试跨旧截止及占位日期仍有效。
- [ ] 以现有 HTTP、真实 PostgreSQL/Redis 和小程序/管理浏览器流程验证；当前模型及消费者硬更新，开发数据/夹具按需重建，无旧数据迁移或备份要求；记录 R2 尚待完成的访问/清理边界。

## R2：长期资料访问、完整导出与清理一致性

**交付**：授权用户可长期回听、查看与下载资料，持续申请导出及领取已完成 ZIP，时间推进和扫描不误删资料。

- [ ] 原声/书中入口、照片及必要衍生文件、转录/故事版本、书稿/PDF与关联清单长期有效；已完成资料包持续保留。
- [ ] 完整导出从申请、打包、完成到下载统一长期资格；流式读取、替代交付仍核对当下本人授权。
- [ ] API 定时器及 Worker 不再生成业务类别/包到期删除意图；孤儿扫描正确识别无到期或占位日期的有效长期资产。
- [ ] 未封存上传、失败临时产物、设备缓存与真实孤儿按用途安全清理，不误删唯一正式资产和仍在有效任务中的对象。
- [ ] 会话/临时下载能力/客服授权到期仍拒绝或要求重新鉴权；用户端无倒计时和远期定时器溢出。
- [ ] 新模型下主动撤回/删除继续终止流、逐层清理、阻止迟到输出；不保留历史到期事件、旧备份或旧开发台账的兼容/恢复路径。
- [ ] 真实依赖下验证跨旧截止、重启与重复扫描，实际 ZIP 完整可读及上述权利边界；准备 R8 的对象存储规则核实清单。

## R3：Vben 登录、主布局与路由导航

**交付**：运营使用完整 Vben 应用框架登录并访问权限内页面，每个功能/详情具备稳定 URL。

- [ ] 使用完整认证/主布局、路由元数据、菜单、面包屑、多标签页、统一品牌及当前管理员入口，保留框架来源/许可。
- [ ] 飞书登录后回到允许的目标页，错误回跳不离开应用；登录取消、不可用、失效及退出有明确反馈。
- [ ] 独立 URL、刷新、前进/后退、嵌套静态入口和同源 API 路径正确；403/404及无权限首页回退正确。
- [ ] 菜单与动作按已有权限显示，直接 URL/请求仍受服务端限制；客服身份不自动得到私人内容权限。
- [ ] 多标签页之间切换/关闭不保留失效私密数据；退出/权限撤销停止已打开页面及活动预览，晚到响应不回填。
- [ ] HTTPS 浏览器覆盖桌面/窄屏及上述行为，保留无凭据截图；登录真实供应商验收留给 R8。

## R4：商品配置列表与编辑体验

**交付**：关系目录、套餐草稿及版本在统一页面中完成查询、编辑、校验和预览。

- [ ] 关系与套餐独立路由，提供适用查询/筛选及完整数据的分页，列表/空态/错误/刷新一致。
- [ ] 表单、弹窗/抽屉与校验统一；原有停用、版本冻结、不可变预览、导入和权限边界保留。
- [ ] 长期服务条款只读展示，无动态期限配置；其他缺失商业参数仍拒绝可售发布。
- [ ] 从详情返回保留查询位置；重复提交/冲突/权限撤销有可恢复反馈。
- [ ] HTTP 与浏览器验证完整操作和受限账号，证明数据与当前业务契约一致。

## R5：客服工单列表与详情工作流

**交付**：运营按类型、状态及编号找到工单，从独立详情处理退款、质量售后、资料申请、换绑或必要校对。

- [ ] 服务端查询覆盖超过旧最近记录上限的数据，组合过滤、稳定排序、分页及权限边界正确。
- [ ] 各类工单使用统一摘要、状态、操作区和进度反馈，详情仅提供当前状态及权限允许的动作。
- [ ] 从质量工单跳转原生产单再返回，关联与查询位置准确；短操作使用标准表单/弹层。
- [ ] 私人材料按本次授权加载，关闭、标签切换/退出或授权失效时清理，重新进入须重验；不得跨工单缓存。
- [ ] 资料导出/删除按长期政策与主动意愿执行，退款和质量的独立窗口/原单金额及幂等保持。
- [ ] 浏览器与真实 HTTP 验证工单查询、详情动作、并发/失效及活动下载取消；不存在期限审核入口。

## R6：生产履约列表与人工进度登记

**交付**：运营查询生产单、核对确定 PDF、登记已完成印制与实际物流，用户端看到同一事实。

- [ ] 生产单具有筛选/分页、独立详情和工单关联；列表返回定位与统一反馈正确。
- [ ] PDF 书稿完成、已生产、已发货/物流各由实际事实形成；接单不冒充完成印制，必要最少记录端到端补齐。
- [ ] 下载 PDF/地址保持当前本人授权和限时能力；人工登记保留处理人、实际时间、版本及审计。
- [ ] 首本唯一、原单重印、双方确认、未知交接、撤回/取消与退款冻结不受布局改造破坏。
- [ ] 日期和物流字段使用统一组件/校验；微信平台结果与实际物流分开显示，不引入自动印厂或物流接口。
- [ ] HTTP、浏览器和对应小程序公开入口证明同一进度；线下印制、实物和平台真实回执继续单独留证。

## R7：运行、任务与审计页面

**交付**：运行、任务和审计独立页面统一显示状态、查询和处理结果。

- [ ] 运行状态正确区分加载、可用、故障及请求失败，不虚构经营统计。
- [ ] 任务按适用状态/类型/编号查询分页，详情与受控重试/接管保留当前幂等、预算和权限。
- [ ] 审计按适用时间/动作/结果/操作人筛选分页，字段脱敏与访问权限保持。
- [ ] 超过旧最近 100 条范围的记录可检索，稳定排序及翻页无重复/漏查；查询参数受服务端约束。
- [ ] 浏览器与 HTTP 验证空态、失败/重试、过滤、分页和受限账号。

## R8：整体回归与实际环境验收

**交付**：完整候选可审阅并具备可追溯的工程与环境结果；真实条件缺失时保持相应未验收。

- [ ] 整体浏览器链路、真实依赖回归、类型检查与构建覆盖最终提交；按变更影响完成定向检查及仓库必要 CI，实际环境结果分别记录。
- [ ] 候选包含配套长期资格、访问、导出和自动清理变更；以新模型核对政策、资料包及主动删除行为；相关开发数据可直接更新或重建，不安排旧数据迁移、旧备份恢复或兼容演练。
- [ ] 核实正式对象存储 lifecycle 不按服务期限删除必要资产；技术临时规则及主动删除边界分别留证，不能用本地测试推定云端正确。
- [ ] 实际部署按相应授权及发布流程执行，验证嵌套 URL、真实飞书登录/退出、静态资源和 Cookie 路径；本次开发环境直接切换新方案，不准备备份或回滚方案。
- [ ] 桌面/窄屏无凭据截图、交互结果、版本/环境及未完成的真机/供应商/实物项分别记录；不自动关闭既有 T29/T30 或开放售卖。

## 审阅点

请确认：上述 8 票的粒度与阻塞是否合适，以及以现有 HTTPS 浏览器、真实 HTTP/PostgreSQL/Redis 和小程序公开入口作为主要验收方式是否符合预期。确认后发布新规格及 tickets；无需重新确认已经确定的长期服务和界面方向。
