# 云服务、AI与微信支付接入依据

版本：V1.0 · 2026年10月20日 · 定稿。基础设施使用阿里云，文件ASR首选豆包（火山引擎），文本模型首选DeepSeek。本文记录官方接入约束；工程基线见[wutong技术栈对齐](wutong技术栈对齐.md)。具体账号、配置、性能和准入须通过发布前验证。

| [BullMQ生产要求](https://docs.bullmq.io/guide/going-to-production)要求noeviction，并区分生产者/Worker断线行为                                                                                          | 核验Tair对应配置、Lua、阻塞命令、锁续租、重试和持久化，队列与普通缓存避免淘汰策略冲突；RDS业务任务/Outbox仍作事实源。                                   |

## 2. 私有OSS与小程序文件上传

| 官方依据                                                                                                                                                                                             | TimeNook设计与验证边界                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [PostObject](https://help.aliyun.com/zh/oss/developer-reference/postobject)、[POST V4签名](https://help.aliyun.com/zh/oss/developer-reference/signature-version-4-recommend)提供表单上传及policy机制 | API生成指定暂存key、短过期和体积范围的表单授权，小程序wx.uploadFile直传。签名字段、security-token与实际AppID上传域名必须真机联调，不照搬旧PUT签名参数。 |
| [OSS STS临时访问](https://help.aliyun.com/zh/oss/developer-reference/use-temporary-access-credentials-provided-by-sts-to-access-oss)按策略和有效期授权                                               | 生产优先使用ECS RAM角色/受限STS签名；永久AK不下发。只允许本次暂存对象必要动作，不给客户端最终前缀写/读/列举权限；分片上传另行授权和验收。               |
| [STS与预签名有效期](https://help.aliyun.com/zh/oss/developer-reference/authorized-access-1)说明临时凭证与签名URL同时受限，按较早失效时间失效                                                         | ASR内部拉取及媒体网关使用短期源URL；有效期覆盖真正下载预算，不能只把URL的expires设长而忽略STS先过期。用户读取仍经业务授权网关。                         |

上传完成后检查存在、真实格式、体积、可解码/像素或时长与hash，再固定版本或复制到随机最终key并复验；数据库落库成功才封存。上传HTTP成功或回调不代替业务完成。ETag不作为通用SHA-256，最终文件单独计算内容hash。

原图、预览图、印刷图和必要音频衍生物分别记录，不以低清预览覆盖原始文件。原声和图片私有，图片/音频/PDF携会话经鉴权网关下载到临时路径，再交原生组件；不借用wutong的公共CDN字段发布私人素材。OSS历史版本、暂存、导出、衍生图和未完成分片均纳入生命周期与删除清单；图片处理费用另计。

## 3. 豆包录音文件识别

首选豆包标准版文件识别，以已封存音频URL异步提交和查询。服务规格以[标准版API](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelrecordingfilerecognitionstandardversionAPI?lang=zh)、[任务提交](https://docs.volcengine.com/docs/DoubaoVoice/task-submission-http-1?lang=zh)和[模型列表](https://docs.volcengine.com/docs/DoubaoVoice/model-list?lang=zh)为准；具体资源与模型经S0短片段评测后锁定。

| 接入约束                                  | TimeNook处理                                                                                     |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 已录文件由服务端通过URL提交，结果异步查询 | 首版采用1–5分钟短段；异步等待释放Worker，转录完成并校验后才推进追问或整理                        |
| 资源、鉴权和请求ID由所选API定义           | 适配器固定服务资源/API配置，使用稳定供应商请求UUID关联提交与查询，不混用不同规格的状态码或鉴权   |
| 标准版有独立的处理时限                    | 不视为几分钟出稿保证；实测短段延迟，未终态显示处理中、可离开，不因界面等待超时重复提交           |
| 供应商从文件URL取源                       | 私有OSS签发限时公网HTTPS源URL，覆盖实际取源窗口与STS剩余有效期；阿里云内网地址不可用作跨云源地址 |
| 外部请求可能出现网络结果未知或重复返回    | 提交前持久化请求UUID和尝试状态，先查原任务再受控恢复；结果按租约、输入hash和授权epoch复核入库    |

源URL仅供本任务取源，不下发用户或记录到普通日志。豆包仅接收授权音频；照片、订单和无关故事不作为转写输入。音频格式、采样率、方言质量、配额和实际费用均须用选定资源验证。无有效语音时保留原声并提示回听或补录，不生成虚构故事。

D03/D08须明确实际处理地域、传输、供应商保存、训练使用及删除能力，隐私告知对应真实服务和用途，不以其他厂商条款代替。

## 4. DeepSeek文本服务与用量

首选DeepSeek官方API完成当前故事的可选追问和结构化整理。[API说明](https://api-docs.deepseek.com/)支持OpenAI兼容的Chat接口；[模型列表](https://api-docs.deepseek.com/api/list-models/)用于核对账号可用模型。模型ID、上下文、输出预算和提示词经样本评测锁定，任务保留实际模型及配置版本，不使用未受控的动态默认值。

[JSON Output](https://api-docs.deepseek.com/guides/json_mode)通过`response_format`及相应提示词请求JSON。服务端仍须做JSON/Schema、来源和事实校验，处理空响应、截断、超时及格式错误；结构正确不等于事实正确。模型只提出问题或稿件，不修改计划、确认内容、授予权益或投产。

输入限于当前问题、必要转录、当前故事问题历史和用户明确偏好；密钥仅在服务端，业务日志不保存原文和完整请求。实际服务条款、数据处理地域、保存/训练使用与删除能力按D03/D08核对。不自动切换到未经准入的供应商或渠道。

费用分记ECS、RDS、Tair、OSS存储/请求/跨云出网、图片处理、豆包识别时长、DeepSeek token及人工。系统重试费用与销售额度分账，按实际用量及账单核算套餐成本。

## 5. 微信支付：普通商户小程序闭环

| 环节      | 官方机制                                                                                                                                                                                                                  | 项目处理                                                                                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 开通条件  | 小程序认证、JSAPI/小程序支付权限、AppID 与商户号绑定；交易类小程序还需按规范接订单发货管理。[接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)                                                               | 将主体/类目/权限/发货要求列为上线门槛；“代码可下单”不等于当前 999 元数字服务与实体书组合已获准销售，iOS/Android 分别验收。                                           |
| 下单      | 普通商户 `POST /v3/pay/transactions/jsapi`，需商户号、AppID、对应 AppID 下的 `openid`、唯一商户单号、金额（整数分）与通知地址，返回 `prepay_id`。[下单接口](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)          | 价格与 SKU/服务/实体权益快照由后端确定；本地支付尝试先落库，网络结果不明先查单，同单号同参数受控重试。                                                               |
| 调起/结果 | `wx.requestPayment` 使用签名参数；前端回调不能作为可靠订单最终状态。[调起支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791898)                                                                                       | 前端返回“确认中”，后端通知或主动查单确认后才发权益；前端取消也不能直接关闭可能已成功的交易。                                                                         |
| 通知      | 通知需用平台证书/微信支付公钥验签，APIv3 密钥解密；5 秒内响应；可能重复，且必须结合查单。[支付通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791902)                                                                  | 在时限内验签、解密/核对交易并可靠保存已验证Inbox后应答，保存失败则失败应答；后续幂等激活业务，核验商户号、AppID、单号、总额/币种、交易状态。单纯验签通过不能发权益。 |
| 查单      | 普通商户 `GET /v3/pay/transactions/out-trade-no/{out_trade_no}`，带商户号。[商户单号查单](https://pay.wechatpay.cn/doc/v3/merchant/4012791900)                                                                            | 覆盖前端返回、通知缺失、超时、定时对账；与通知复用核验与状态推进代码，避免重复开通/重复打印。                                                                        |
| 退款      | `POST /v3/refund/domestic/refunds`；受理成功不等于退款成功；失败重试必须复用原 `out_refund_no`。[退款申请](https://pay.wechatpay.cn/doc/v3/merchant/4012791903)                                                           | 建退款单与权益/生产进度联动；不自动把“申请受理”写成“已退款”。                                                                                                        |
| 退款确认  | 可查 `GET /v3/refund/domestic/refunds/{out_refund_no}`；最终结果由退款通知/查询确认。[退款查询](https://pay.wechatpay.cn/doc/v3/merchant/4012791904)、[退款开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031) | 部分退款独立记账，限制累计已退+处理中金额；退款失败/异常可追踪，不直接删除作品数据。                                                                                 |

订单、支付尝试、退款、服务权益、印刷履约分别建模。支付成功只证明交易收款；不能代替讲述者同意、内容确认或印刷授权。价格/商品形态、数字服务权益何时开通、成书后退款边界由产品与运营确认，并与平台实际准入结论一致。
