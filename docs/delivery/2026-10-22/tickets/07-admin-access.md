# T07 · 建立独立运营登录与受限管理入口

GitHub：[#8](https://github.com/brycezhang/timenook/issues/8) · 状态以 GitHub 为准。
阶段：S1

## 交付结果

运营使用 Vben 管理端登录，看到权限内的运行信息，并留下操作审计。

## 验收条件

- [ ] 管理员与小程序用户使用独立账号及会话，采用飞书白名单登录（无密码/MFA，见 ADR 0016），落实 HttpOnly/Secure Cookie、CSRF 和注销；新增实现和证据见 #81。
- [x] 提供最小权限的受保护管理页与 API，匿名、小程序会话、缺权限和无效 CSRF 请求均被拒绝。
- [x] 审计记录操作人、动作、请求标识及结果；日志不记录正文、会话令牌、云密钥或完整地址。
- [x] 初始管理员通过受控命令建立，不内置生产默认口令；验证管理端登录/退出和服务重启后的会话规则。
- [ ] 管理 API 内部 `/v1/admin`，公网为 `https://timenookapi.threeminreading.com/api/v1/admin`；管理页面为同域 `/admin/`，Cookie Path 为 `/api/v1/admin`。本地验证正确基址、Cookie/CSRF 和页面请求；正式域名、静态资源及真实管理员 MFA 由 T29 验收。

## 实现边界

沿用已有独立登录、权限与审计；后续运营票共享最小工单列表/详情和必要操作表单，不在本票预建全部后台。正式管理员与部署归 T29。

## 测试决策

- 现有范例：[admin.test.ts](../../../../apps/api/test/admin.test.ts)、[access.spec.mjs](../../../../tests/admin/access.spec.mjs)；仅作测试方式参考。
