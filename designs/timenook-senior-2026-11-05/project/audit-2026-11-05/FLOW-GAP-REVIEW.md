## 2. 已确定的设计决定，继续保留

这些是有意的新方案，不列为需要恢复的“遗漏”：

- 品牌统一为“时光故事”；两 Tab 固定为“岁月成书 / 我的”。
- 未购买首页保留大图、三项介绍、底部固定购买卡；不恢复“送给妈妈 / 送给爸爸”首页入口。
- 首页显示当前项目并支持切换；我的采用常规个人页，我的订单仍可进入购买所得项目。
- 老年人界面保持大字号、明确主按钮、少量入口；原实现中的折叠区域改成二级页面。
- 章节列表无图片、无不存在的副标题；排序在列表完成；进入章节就显示可编辑正文。
- 不恢复独立制作授权页。制作资料用途并入条款是已定方案，后续实现需要同步调整相关接口与规则。
- 首本一本已含在套餐中，印刷阶段显示本次 ¥0；不因为参考效果图而增加“加印 100 元”、模板商城、固定 200 页、固定物流或固定发货天数。

## 3. 完整流程逐段结论

“部分覆盖”表示主路径已有画稿，但缺少实际已实现能力或必要状态；“模型不一致”表示照画稿实现会改变当前业务规则。

| 步骤 | 用户任务 | 设计现状与健康度 | 改稿方向 |
| --- | --- | --- | --- |
| 1 | 认识产品、浏览未购买首页 | 基本完整；新版视觉和购买卡可保留 | 补套餐加载失败、暂未开放购买；品牌残留清理 |
| 2 | 微信登录并返回原任务 | 有登录、取消、协议阅读和返回目的地的模拟路径；部分覆盖 | 补登录失败、会话失效、重新登录后继续原任务 |
| 3 | 新购一本、填写信息、付款 | **模型不一致**：自购被直接赋予讲述者身份；支付总是成功 | 澄清自购范围；补称呼、配送范围、原订单恢复和支付结果 |
| 4 | 从我的订单进入项目、首页切换 | 点击路径已验证；**订单与参与项目混用** | 购买订单与参与关系分别取数；未付款订单不能进入已购项目 |
| 5 | 邀请家人、确认参与身份 | 只有邀请卡示意，流程不完整 | 补接收邀请、申请、待核对、绑定成功及邀请失效 |
| 6 | 老人无微信，由家人同机协助 | 缺少设计入口 | 补“本人在身边，一起记录”，及故事/书稿当次确认协助 |
| 7 | 确认和调整资料用途 | 有三项全选才能继续的原型；与现有可分别选择不一致 | 开始页保持简洁；独立二级页调整用途、拒绝或撤回 |
| 8 | 选择话题、开始录音 | 正常录音/暂停/回听已有；话题管理部分覆盖 | 保留“换个话题”，二级页补自己的问题、稍后聊、不想聊 |
| 9 | 保存录音、等待整理、回来继续 | 缺少关键恢复状态 | 区分本机保存、上传、云端确认、转写、故事整理；补重试和原录音恢复 |
| 10 | 找到故事、阅读、修改、决定入书 | 单篇确认主界面清楚；列表入口和功能不完整 | 常驻故事列表入口；完整编辑、原声、照片、不入书/撤回确认 |
| 11 | 添加照片、照片说明及顺序 | 缺少；只有封面照片示例 | 故事详情进入照片页，支持上传失败恢复、说明和顺序 |
| 12 | 调整书封、章节顺序与正文 | 直接编辑行为已验证；**章节数据模型不一致** | 章节包含多个故事；直接编辑需落到故事新版本并重新确认 |
| 13 | 生成和预览完整书稿 | 主流程及生成/失效状态已有；预览是固定 6 页示例 | 表达真实完整 PDF、实际页数、打开失败；清理旧品牌 |
| 14 | 讲述者确认本版内容 | 有单独角色页面和改稿后重确认；部分覆盖 | 补等待本人、协助确认及本人拒绝后的返回路径 |
| 15 | 发起人保存地址、确认印刷 | 核心规则基本完整；缺真实配送范围和部分阻塞状态 | 使用原订单配送范围；补确认已存但提交待核实、资格改变等 |
| 16 | 查看制作、物流、交付 | 有待审核、已印好、已发货、待核实示例；部分覆盖 | 补制作中、已交付、取消后修订，以及适合各状态的下一步 |
| 17 | 退款、质量问题、原单重印 | 缺少设计 | 从订单详情/制作详情进入申请和进度，不增加首页入口 |
| 18 | 导出资料、撤回/删除、查看服务进展 | 我的页仅说明性入口；缺少可执行闭环 | 二级“资料与隐私”“帮助与服务”，补导出/删除进度/工单 |

## 4. 差异清单与具体设计建议

优先级：**P0** 为重构前必须明确的业务模型或主流程断点；**P1** 为完整功能改稿必补；**P2** 为一致性与可用性完善。

### P0：先修正会影响业务闭环的差异

| 编号 | 差异、影响与证据 | 设计稿修改建议 |
| --- | --- | --- |
| D01 | **订单不等于参与项目。** 原型用同一 `projectItems` 生成“我的订单”，全部标 ¥999/已购买。实际订单按 buyer 查询；参与列表包含发起人、已绑定讲述者、待确认邀请。受邀老人可能从未付款，却应该进入当前项目。[订单接口](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/apps/api/src/payments/orders.ts#L463) / [参与列表](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/apps/api/src/identity/participation.ts#L368) | 保留“我的订单 → 进入项目”。首页是否展示项目，以可访问的参与关系为准；受邀但没购买的人也展示项目首页。“切换项目”列出本人可访问项目；订单页展示本人真实订单。待邀请者进入邀请状态，不能被当作未购买客人反复促购。 |
| D02 | **“写我的故事”是超出现有角色规则的新能力。** 原型付款后直接赋 `role:narrator`；当前参与申请明确拒绝发起人绑定自己，付款人仍是发起人。原型也只有 initiator 能填写地址/提交制作，自购 narrator 没有完整寄送闭环。[禁止自身申请](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/apps/api/src/identity/participation.ts#L349) | 不能将这一入口标记为“已实现功能换皮”。按现有范围交付时，新购流程沿用为另一位讲述者建书；若保留自购，须另补“同一人兼具付款与讲述职责”的确认和寄送稿，并列为业务扩展。无需恢复首页父母快捷入口。 |
| D03 | **邀请和同机协助缺失。** 现有实现有邀请申请、发起人核对绑定、过期/重发、无微信同机协助；原型只是静态邀请卡。发起人首页还按角色固定显示“查看邀请卡”，无法表达家人已加入后的下一步。[邀请](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/invite/index.ts#L130) / [同机协助](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/assisted/index.wxml#L1) | 增加家人参与二级页：邀请未发出、等待加入、待核对、已加入、邀请过期。当前项目主按钮根据真实下一步改变；同时提供“家人在身边，一起记录”。协助操作不等于替本人确认内容。 |
| D04 | **录音保存被一个成功页跳过。** 原型 `saveRecording` 直接进入 saved。现有实现区分本机片段、上传、封存、ASR、故事整理，且支持中断恢复、无语音/无内容、重试。[处理状态](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/interview/index.ts#L772) / [故事任务](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/story/index.ts#L34) | 不新增多步骤向导。复用同一个状态页，分别显示“已保存在这台手机”“正在上传”“已保存，正在整理”“需要重试”。失败时给一个明确下一步，并保留原录音；首页在有未完成片段时显示“继续上次记录”。 |
| D05 | **章节被当作一块独立正文。** 现有目录是 chapter → 多个 storyRefs；正文属于故事版本。原型 `bfSaveChapter` 只写 directory.body，未把修改提交到对应故事版本。列表还缺新增/移除章节、故事归章和故事顺序。[目录能力](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/book/index.ts#L443) / [正文修改](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/edit-story/index.ts#L293) | 保留“点章节就能编辑”。章节详情直接展开本章各故事的可编辑正文，保存到相应故事新版本；受影响故事需本人重新确认后再生成书稿。目录继续直接上移/下移；“添加章节”“调整本章故事”放本层或二级操作，不恢复缩略图、副标题或额外编辑开关。 |
| D06 | **制作授权页的取消尚未反映到实现契约。** 原型已按决定取消；当前 production 仍有确定 PDF 与地址的限时交接授权，并参与后续制作流程。[当前制作页](https://github.com/brycezhang/timenook/blob/473fb6b23be0091793e6219540c8b5c8a8e0d001/miniprogram/pages/production/index.wxml#L21) | 设计继续不设独立授权页。将“条款内制作用途说明 → 用户同意记录 → 已确认版本与地址 → 制作交接”列为重构时需一起更新的规则。不要只删按钮、让制作卡在不可见条件上；本人内容确认、地址确认和资料用途管理仍分别保留。 |

## 5. 下一轮改稿的安排

### 第一批：修正关系，保证主链路成立

1. 先修 D01/D02：明确“订单、项目参与、讲述者、发起人”对应关系；据此补首页、订单、切换、自购范围。
2. 补家人参与和同机协助，以及日常首页的故事列表入口。
3. 补录音保存/恢复和故事确认状态。
4. 保留当前章节直接编辑样式，修正背后的多故事/多版本关系。

### 第二批：补齐二级能力

- **我的订单 → 订单详情 → 退款 / 售后**。
- **当前项目 → 已记录的故事 → 故事详情 → 照片 / 原声 / 故事操作**。
- **录音 → 换个话题 → 想聊的话题**。
- **我的书 → 章节列表 → 章节直接编辑 / 调整本章故事**。
- **我的 → 资料与隐私 → 用途 / 导出 / 删除进度**。
- **我的 → 帮助与服务 → 当前项目工单 / 账号绑定帮助**。
- **纸书扫码 → 书中原声**，不强迫绕首页。

这些是二级能力，不要全部堆到“我的”首屏，更不要放到首页宫格。无需新增 Tab，也不使用折叠。

### 第三批：补状态稿，不增加正常操作步骤

统一补登录失败、会话失效、订单恢复、录音保存失败、故事待核对、照片失败、生成失败、等待家人、地址未保存、提交待核实、制作取消、售后处理中。每种状态只突出一个下一步，说明性长文进入二级页。

### 保持的首页结构

- 无可访问项目：家庭/书籍大图 → 三项产品介绍 → 底部固定购买卡 → 两 Tab。
- 有可访问项目：当前项目与切换 → 书籍图片和一句状态 → 一个当前主任务 → “已记录的故事”入口 → “我的书”入口 → 两 Tab。
- 即使用户本人没有付款，只要已被邀请并可访问项目，也采用第二种首页。对外无需展示“权限”“绑定版本”等实现术语。
