## 完成范围与外部边界

本地代码与模拟外部微信网络已通过，真实微信验收待完成。用户确认正式 TimeNook AppID/Secret、OSS/RAM 尚未准备，先完成本地开发与测试。本票应保持未关闭；没有复用其他产品身份、创建正式账号、发起真实支付或修改远端服务。

内部 HTTP 入口仅为 `POST /v1/sessions/wechat`、`GET /v1/users/me`、`DELETE /v1/sessions/:sessionId`。服务端自行换取微信身份，以 `(app_id, open_id)` 唯一建立账号；账号恢复指新 code 登录仍得到同一账号。没有提前交付手机号、讲述者绑定、项目权限、支付或销售参数。

会话为随机 32 字节的不透明 bearer token；服务端只有 SHA-256 摘要、用户、有效期和撤销时间，签发响应为 no-store。每个 code 在真实 PostgreSQL 以 AppID+摘要预占一次，外部调用未知结果也不再次兑换，10 分钟后允许清理。身份创建使用事务级身份锁及数据库复合唯一键；session_key、unionid 均不保存、不回传，网络异常不透出 URL/code/Secret。摘要存储通过 schema/实现审查确认，业务测试没有通过查询数据库侧通道断言。

外部网络只在 `environment=test` 允许构造注入；没有模拟身份环境开关，生产与开发拒绝测试 transport。真实适配器固定 HTTPS 微信地址，禁止重定向，设置 5 秒超时。未配置身份的开发登录返回 503，生产缺失身份配置拒绝启动。真实 Redis 负责原子登录限流；只信任 loopback Nginx，外部伪造 X-Forwarded-For 不改变来源。

小程序显式区分本机演示/真实服务；真实服务只开放账号入口，演示 store 的读写与购买路径均受模式约束。会话存储按 API 基址独立，不迁移演示资料；请求使用统一 envelope、requestId 和 Authorization。401、退出及迟到响应不会恢复或覆盖旧账号；网络失败保留错误，不生成模拟购买成功。退出的服务端撤销失败会明确显示未确认。原 15 页演示保留。

公网目标按 ADR 0009 为 `https://lawyerapi.threeminreading.com/timenook/v1`，不是已部署服务；Nginx、ECS、数据库云资源和微信合法域名均未改动。

## Spec 审查 P2：原生页面再次显示打断登录

修复基线 `d295678c8e25159f3c50c38a7b85f5c65722fa5c`。独立 Spec 审查复现：`page.login()` → 网络响应前 `page.onShow()` → 登录201，服务端会话已经取得，但页面仍为 `userId="" / status="请使用微信登录" / busy=true`。原因是 `onShow` 增加页面身份版本，旧登录结果及其 `finally` 都被丢弃；再次显示不能解锁按钮。退出进行中的 `onShow` 还会覆盖“正在退出”。

新增 `tests/home-session.test.ts` 以 esbuild `write:false` 打包真实 home 页面及真实请求/会话模块，在隔离运行环境注册 Page，只替换原生微信的注册、存储、login 和 request 边界。通过实际页面公开 `login/logout/onShow` 生命周期操作及页面绑定数据观察结果，不读取或断言私有版本号，不替换内部 SessionClient。

先运行两项精确回归均失败（0/2，`/tmp/timenook-t06-home-lifecycle-red.log`），输出明确包含 `busy=true`、空账号和错误提示。修复只在 `onShow` 入口保留正在执行的身份操作：已有 busy 操作继续拥有其结果及 finally，返回前台不会启动竞争的恢复。两项转绿（2/2，`/tmp/timenook-t06-home-lifecycle-green.log`）。

随后补充登录失败后可重试成功、退出网络失败仍释放按钮并显示远端未确认、旧账号恢复响应迟到不能覆盖退出后新登录的账号。页面5项与已有会话7项一起12/12通过（`/tmp/timenook-t06-home-lifecycle-regression.log`）。最终 `pnpm check` 共75项通过，`pnpm check:native` 两编译器各15页通过，日志见上表。保留主线程的 `.btn` 样式修正；本修复没有变更后端、迁移、会话存储契约或非阻塞 Redis 重复连接项。
