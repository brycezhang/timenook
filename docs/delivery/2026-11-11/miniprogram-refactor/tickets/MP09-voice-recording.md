# MP09 · 语音讲述、照片操作与可靠保存

状态：本地功能已实现，原生与外部待验；GitHub [#175](https://github.com/brycezhang/timenook/issues/175)，父规格 [#166](https://github.com/brycezhang/timenook/issues/166)。父规格：[小程序全量重构](../spec.md)。

## 交付结果

从当前推荐题直接开讲，录音中加照片先暂停；结束自动保存并形成正确归属的故事，失败可恢复。

对应差异：F12。主责画板：`RecordReady`、`RecordReadyPhoto`、`Recording`、`RecordPaused`、`Upload`、`UploadFailed`、`RecordBlocked`。详见[画板对照表](../DESIGN-MAP.md)。

## 验收条件

- [ ] 首页带当前题到准备页，选题只从换题进入；麦克风和开始文字整块可点，提问来源与章节保持。
- [ ] 无照片、有照片、录制、暂停、保存、失败和权限状态按画板完成；所有起点可关联/逐张移除照片。
- [ ] 录音中加照片先暂停，继续不丢时长；结束和 10 分钟上限自动保存，同故事可续录多段，累计额度复用现行 6 小时策略。
- [ ] 离开提供保存选择，上传失败可重试，整理后台继续；录音结束不要求额外封存/转写提交。
- [ ] 补录不换题或新建故事，新故事不恢复上篇；切换项目仍保存到录音所属项目，权限拒绝后可恢复。
- [ ] 本票全部主责画板完成设计与原生 UI、交互对照，记录 390px/320px、真实入口、截图与差异处理；不留死入口或用样例数据冒充业务。
- [ ] 实现、相关检查、原生验证及外部待验分别记录，改动与测试只覆盖本票实际边界。

## 数据与契约边界

本票按新方案直接修改相关前后端、共享契约和数据库。开发数据可破坏性重建，不做旧模型兼容、双写或旧接口别名。影响现有网页/后台消费者时同步适配，不扩展视觉范围。

## 测试决策

复用可靠录音、上传恢复和 API 封存测试；开发者工具录制/暂停/照片/继续/保存/补录路径。合成硬件输入和 iPhone 真机录音分别记录。

复用现有测试入口，优先验证公开行为；数据库约束使用真实 PostgreSQL/Redis。外部待验不视为功能缺失，已实现能力与未验环境分别说明。
