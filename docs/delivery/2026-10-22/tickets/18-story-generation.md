# T18 · 从完整转录清单整理可核对故事

GitHub：[#19](https://github.com/brycezhang/timenook/issues/19) · 状态以 GitHub 为准。
阶段：S2

## 交付结果

用户提交整理后取得带来源、待本人确认的第一人称故事；原声和原始转录保持独立。

## 验收条件

- [ ] 提交时冻结全部已选封存片段/转录依赖及 baseVersion，不漏掉仍在转写的后半段；空白无效语音不生成故事。
- [ ] 校验标题、段落/sourceRefs、主题和 reviewItems，拒绝无来源引用、无效 JSON 与空段落，保留模糊事实与矛盾核对项。
- [ ] 补录/改稿/撤回期间迟到结果标为 obsolete，不覆盖新稿；失败从原素材恢复，明确用户重生成与系统重试额度。
- [ ] 小程序显示实际任务阶段、AI 整理标识、全文和待核对项；已保存原声可回听，退出返回恢复同一任务。
- [ ] 沿用 T15 关联事件，验证[端到端计时口径](../spec.md#质量目标与证据归属)，包括排队/依赖转写与失败、人工接管、未终态；T30 统一测量真实样本达标比例。
- [ ] 稿件与等待/失败页面符合[页面质量要求](../spec.md#质量目标与证据归属)，保持完整正文及清晰状态；AI 整理和人工校对来源由 T20/T25 继承到文件。

## 实现边界

复用 T03 整理 adapter/输出契约与 T15 任务机制，增加完整输入快照和稿件版本。事实由本人核对，必要时运营校对，不自动裁决矛盾。
