# 营销官网本地预览验证

日期：2026-10-28。规格 [#69](https://github.com/brycezhang/timenook/issues/69)，实现 [#70](https://github.com/brycezhang/timenook/issues/70)。本次为本地工程与预览，不代表正式微信进入或真实交易验收。

## 已实现

独立 `apps/website` 静态应用，完整六段单页、品牌 Logo、999元套餐、样书翻页、讲述/整理稿切换、原生折叠问答、未开放时的下单提示与焦点恢复。首版没有咨询入口。公开素材白名单沿用现有书籍、亲情照片和用户 Logo，所有示例明确标注。

官网可独立开发、构建、打包。CI 增加官网浏览器检查和独立预览 artifact；仓库原有整仓 CI 策略保留。网站包与 API/Admin 包分离，未操作服务器、真实微信账号、用户资料或资金。

## 本地结果

- `pnpm typecheck`：小程序预览、contracts、API、Admin、官网均通过。
- `pnpm build`：上述应用均构建通过，原生小程序 25 页成功生成；官网脚本约 4kB，CSS 约 16kB（未压缩，另有现有图片）。
- `pnpm test:website`：15/15，通过 320×760、390×664、1440×960 三种视口的五组公开行为检查。官网的源代码、Vite/Playwright 配置与测试均纳入官网类型检查。
- `pnpm test:frontend`：361/361，通过共用演示数据所在小程序前端的现有回归。
- `node --test tests/ci/*.test.mjs tests/release/*.test.mjs`：15/15，通过原有 CI 分流和应用发布包回归。
- `pnpm package:website <新目录>`、压缩包目录检查及 SHA-256 校验通过；包内仅为 `index.html`、`robots.txt`、官网 JS/CSS 与三张公开图片。清单记录 Git 提交、工作区是否有未提交变更、预览标记和 archive hash。

API 的数据库/Redis 全量回归、原有管理端浏览器检查及最终提交上的完整结果由 PR CI 执行；以上本地结果不替代尚未返回的 CI。

## 浏览器与视觉核对

内置浏览器实际打开本地站点，验证下单提示、关闭后焦点恢复与样书下一篇；页面错误/警告日志为空。Playwright 对构建后的站点执行独立自动回归及截图，不代替微信真机结果。

已使用 `view_image` 对照[布局参照](../../../design/website/layout-concept.png)、桌面完整页/首屏、手机完整页/首屏和弹窗。生成参考尺寸为 774×2032，是桌面长页缩略布局；实现以 1440px 桌面和实际手机尺寸阅读为准。另在内置浏览器实测 774×2032 的响应式中间布局，内容宽度为 774px，无横向溢出；不对桌面缩略图逐像素照搬。

## 审查修复

Standards 首轮发现部分点击区域小于设计约定的 48px，已统一按钮点击尺寸，并在三种视口的既有布局测试中验证。Spec 首轮发现整理示例包含讲述示例未提供的细节，已补齐讲述示例中的对应事实，并补充对照内容检查；不把虚构新事实展示为整理能力。修复后的固定提交仍须分别完成两轴复核，结果见实现票和 PR。
