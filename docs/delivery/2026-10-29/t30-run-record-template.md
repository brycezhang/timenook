# T30 执行记录模板

日期：2026-10-29。配合[验收清单](t30-acceptance-preparation.md)和[负责人确认](t30-owner-confirmations.md)使用。**本页全为待执行模板，没有实际样本、试用、支付、实物或性能结果。** 执行时在受限证据库新建记录，仓库只回填脱敏结论/引用，保持原始分母和失败历史。

## 1. 预登记与共同字段

每次运行先固定以下内容，变更后另建运行记录，不覆盖原结果：

| 字段 | 待记录内容 |
| --- | --- |
| 记录与状态 | runRef、记录人/复核人、创建/执行/截止时间和时区；未执行/进行中/成功/失败/待核实 |
| 验收范围 | A/X/D 编号、主责任票、是否仅分项；合成工程/真实供应商/真机/实物分别标明，可多项并存但不互相替代 |
| 代码与产物 | 应用提交 SHA、实际构建 SHA、必要时文件树一致性、release/候选包 SHA256、适用 PR CI 与完整 main CI 引用；文档 CI 单列 |
| 环境与配置 | 运行环境/资源隔离范围、配置版本或指纹、存储域、D01–D10 适用版本；只记引用，不复制 Secret 或完整连接串 |
| 供应商 | ASR/文本实际供应商及中转路由、资源/模型/参数/提示词版本，条款/地域/保留/删除核验引用；记录真实请求关联引用 |
| 人与授权 | 项目/讲述者/发起人/操作人匿名引用、本人/协助/客服授权及具体用途/版本/期限；原始身份材料只在受限库 |
| 样本计划 | 样本总数与分组、口音/设备/微信版本/网络、输入时长与照片格式、事前排除规则和观察截止时点 |
| 证据位置 | 原始日志、截图/录屏、文件清单/hash、账单、接单/物流/销毁回执的受限引用；只在实际产生后填写 |

实际代码/配置/设备/输入范围与既有责任票匹配时引用其主证据，并记录本轮新增集成；不适用部分明确补验。

## 2. 同一真实内部项目的衔接表

以下用于未来正式内部项目；离线内容评测/打样可先单独记录，但不填成已走完真实付款至实体交付。

系统核验止于确定生产 PDF 的生成/确认/人工下载，以及“已生产”“已发货/物流”等进度的手工记录与查询。下表印厂、印制、物流与实物步骤均由运营线下执行后填报，不要求系统对接印厂或物流接口；系统功能与线下运营证据分别归档。当前尚缺独立“已生产”完成事实，见[实现差异](t30-acceptance-preparation.md#系统边界与设计核实)，不把印厂接单写成完成印制。

| --- | --- | --- |
| 付款与项目 | 原订单/支付单/交易事实、999 元、已核验状态；project/subject/首本权益唯一；旧销售快照及独立期限 | 待执行 |
| 参与与授权 | 同一 subject、实际 operator、邀请绑定/同机方式、告知及用途；账号换绑不改变主体/历史 | 待执行 |

| 转写/追问/整理 | 原始转录、Task/attempt/供应商请求、可选追问、sourceRefs 与故事版本；失败、未知与重试事实 | 待执行 |
| 本人故事确认 | 正确 story version/hash、采集/AI/共享许可、单独入书决定；校对不改原声，改稿需重确认 | 待执行 |
| 书稿与双方确认 | 确定 book version/PDF hash、目录/全文/照片/来源标识/原声关联；双方同版确认，发起人另确认地址 | 待执行 |

| 已生产 | 运营核实实体书完成印制，人工登记实际完成时间、处理人及记录引用；不由接单、PDF 下载或等待时长推断 | 待实现对齐 / 待执行 |

## 3. 目标讲述者双端可读性与开录

每次试用记录：participantRef、独立/同机协助方式、operatorRef、设备型号、OS/微信版本、字号设置、网络、页面状态和代码/配置。

| 项目 | 口径 / 待填结果 |
| --- | --- |
| 起点 | 已完成绑定并授权的项目主页；保留原始开始时间，不把登录、购买或邀请混入该项计时 |
| 终点 | 实际麦克风开始录音；保留原始时间及可核实的事件/录屏引用 |
| 结果 | 耗时秒数；是否达到不超过 60 秒的目标；未开录/失败的原因；协助次数和人工耗时 |
| 可读性 | 主按钮至少 48×48 逻辑像素，正文以 20 逻辑像素为起点；实际讲述者是否看清、理解用途/状态，正常/错误/等待及完整故事正文有无溢出 |
| 处置 | 问题编号、负责人、修复或目标校准决定、受影响范围及重测引用 |

浏览器工程样本（如历史自动化 172ms）和 Mac 原生编译单列，均不填成目标讲述者真机成绩。iOS/Android 分别记录，未完成的设备组合保留缺口。

## 4. 端到端出稿计时与质量

执行前冻结样本分组/数量、口音/设备/网络、排除规则和观察截止时间。对每个样本记录如下字段：

| 字段 | 口径 |
| --- | --- |
| sampleRef、输入清单 | 受限样本引用、所有片段/照片引用、录音总时长，注明是否属于不超过 5 分钟范围 |
| submittedAt / allInputsSealedAt | 用户提交整理与本次全部输入已云端保存的两个真实时点 |
| startAt | 两者均已满足的时刻，即 `max(submittedAt, allInputsSealedAt)`；录音/上传耗时另列，不改写原始时点 |
| readyAt / elapsed | 成功出稿时点及与 startAt 的差；排队、等待转写/依赖和重试时间纳入该间隔，转录/追问/整理阶段另列 |
| 状态 | 成功、失败、人工接管、未终态；每样本保留状态时间线，截至截止时点报告其实际状态，未知结果不改写为失败或重新提交 |
| 内容审校 | 对原声/转录/稿件的来源核对，模糊/矛盾/拒答与禁问、中性单题、AI/人工来源；审校人、问题与处置引用 |
| 费用与人工 | 真实音频计费、token/重试/出网账单引用，逐次人工操作秒数；接口 usage 和供应商账单分开 |

报告保留预登记数、所有已尝试数、每项排除及事前依据；原始分母 N 为进入既定范围的全部实测样本。超过 5 分钟等范围外样本单列，不能按运行结果追加排除规则。

- 成功率 = 截止时点成功样本数 / N。
- 3 分钟达标比例 = 在 180 秒内成功出稿的样本数 / N，目标至少 95%。失败、人工接管和未终态均保留在 N 中，不计作本项成功。
- 同时报告成功/失败/人工接管/未终态数量与原始逐样本耗时，成功样本的耗时分布单列；未终态记录已等待时间，失败/接管记录发生时点，避免将“无 readyAt”写成 0 秒。
- 保留差距、整改、重新测量及实际负责人明确的目标调整/试点决定。少量样本不推导供应商 SLA、口音全面覆盖或稳定性承诺。

## 5. 付费试点漏斗与成本（获准开放后填写）

当前不招募、不收款。未来按 [PRD 第 14 节](../../时光里_岁月成书_MVP_PRD.md)记录同一渠道、项目与观察窗口；测试、赠送和全额退款从真实付费指标按原定义区分，并保留各自计数。

| 指标 | 既定口径 / 需要保留的字段 |
| --- | --- |
| 访问到付款 | 同一渠道 100 名真实目标购买者、实际支付/取消/退款；初始目标 10–15 人真实付款 |
| 激活 | 支付满 7 日项目为分母，其中首段成功保存的比例，目标至少 70%；未满窗口另列 |
| 持续讲述 | 首篇确认满 14 日项目为分母，完成至少 5 篇确认故事的比例，目标至少 50% |
| 成稿 | 支付满 45 日项目为分母，双方确认生产稿比例，目标至少 40% |
| 交付 | 承诺到期项目逐单核对；交付后 7 日访谈双方，记录按时/像本人/推荐理由与问题 |
| 单项目贡献 | 999 元实收，分别记录支付、AI、存储、必要人工、印刷、物流和售后实际成本，目标覆盖可变成本；人工逐任务计时 |

分批累计 30–50 个真实项目，观察至少一个完整成书与交付周期。每批记录批准人、适用版本和范围；没有完整观察窗口时报告尚未成熟，不提前计作失败或达标。

## 6. 每项结论与问题闭环

每个 A/X/D 或 T29 证据条目使用：`编号 → 责任票 → 实现/配置/环境/输入范围 → 主证据及本轮增量 → 通过/失败/待执行/待核实 → 复核人/时间 → 缺口/整改/重测引用`。

原声丢失、跨项目访问、错版印刷、重复收费、删除后仍可访问按 PRD 记为上线阻断；其他质量差距也须保留处置决定。T30 的完整关闭仍以七项原验收及依赖证据为准。
