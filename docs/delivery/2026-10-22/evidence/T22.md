票据 [#23](https://github.com/brycezhang/timenook/issues/23)，基线 `ca57d1c2183f4bc42b680674213bc71ac9c4272f`。本票消费 T21 PR #57 的固定版本原声入口和当前授权，T20 PR #56 的不可变书稿/PDF/hash，以及 T10 PR #43/#45 的已核验付款、唯一首本权益和独立制作期限。本人和同机证据沿用 T11/T12。T21 最终独立复审无残留，PR CI 40267879278 与精确 main CI 40269778533 成功；适用证据见 [T21](T21.md)、[T20](T20.md)、[T10](T10.md)、[T12](T12.md)。

仅在现有隔离合成模式中推进，外部微信/支付/AI 调用使用明确替身，数据库与 Redis 使用真实本地依赖。正式商业参数、账号、印厂和设备条件仍由责任票验收；不部署云端、不开放售卖、不调用真实资金或私人素材。原生 blocked-by 保留，上游 OPEN 不等于工程契约未交付，也不等于真实验收通过。

## 约定的验证边界

沿 T22 和父规格已约定的公开入口逐片 RED→GREEN：双方确认和首本提交 HTTP、真实 PostgreSQL 并发，以及小程序 Page/平台接口。后端和前端的增量结果分别记录于 [后端](T22-backend.md) 和 [前端](T22-frontend.md)。最终固定提交、独立 Standards/Spec 审查及 PR/main CI 以 GitHub 交付记录为准。

浏览器目标流程为“讲述者核对同版完整 PDF 并确认内容→发起人核对 PDF 与配送地址→地址修改要求重新确认→唯一预留首本且无需二次支付”。Browser plugin not available；使用仓库现有 Playwright 配置，连接实际 Page、HTTP、PostgreSQL、Redis 和 PDF 渲染器，外部服务继续使用合成替身。浏览器小样本的私有套餐明确设置 `minPages=1`、`bleedMm=0`，只用来匹配现有合成排版器；默认样本的 `minPages=48`、`bleedMm=3` 不变，不将少页数或出血不符的书稿放行。
