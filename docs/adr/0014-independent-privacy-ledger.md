# 撤回与删除以独立台账为恢复依据

旧业务数据库备份可能包含已经撤回的授权和已经删除的资料；只把墓碑或 outbox 放在同一备份中，恢复后仍可能重新开放访问。T26 选择在独立受限的本地文件系统中先持久化经过认证的撤回/删除事件，再在 PostgreSQL 投影。API 和 Worker 开放私有能力前先校验并重放；运行时持续检查。新建源和恢复切换分别由显式命令执行，服务不能因缺源自动初始化或自动取得写入权。

独立源使用固定锁文件的非阻塞原生 flock、不可覆盖的事件文件、链式认证及经过认证的 head，按文件和目录 fsync 发布。活动进程固定绑定数据库位置、安装身份及切换代次；恢复到另一安装须在完成重放后显式 promote，使旧进程失去权限。这引入 Node 原生依赖和运维介质要求，换取跨进程排他、崩溃后确定性恢复及与业务备份分离的拒绝依据。首版只支持同一主机上的本地 POSIX 文件系统；不提供 NFS 或多主机锁的隐式降级。

本地竞争采用规范来源路径下的FIFO直接交接；连续短读取不能反复抢走已经排队的读取者。队列只负责进程内公平性，不替代内核flock或形成持久化锁记录。保留从入口开始的单一5秒获取预算和超时拒绝；过期等待者不能释放当前owner，只有当前owner在原生unlock、自己的FD close之后才交接。已经持锁的完整认证work、源格式及失败后重放规则保持。

资料永久删除采用按项目、类别、行键和列登记的单向擦除；数据库仅允许匹配删除清单的清空，并保留原有版本、引用和资金约束。财务与最少权利事实继续按各自用途处理，不把全部历史记录作为内容整行删除，也不把退款当作删除触发。原声等某类到期与仍有效 PDF 的保留分别判断；类别重叠和副本期限由 D03 冻结。

完整合法旧源、head 和密钥一起回滚，无法只靠同一介质上的认证链自行识别。独立介质、账号权限、密钥托管、防整体回滚、正式恢复时限及外部副本证据仍由 T29 和对应负责人验收。本决定记录工程取舍，不代表正式政策、部署或真实删除验收通过。接口与运行约束见[开发说明](../development-deletion-ledger.md)。

故事否决恢复使用 `journal_denial` 来源，只能复制独立已认证事件中的实际主体、操作人、版本/hash 与否决选择，证据引用指向该事件 hash。它不冒充原来的 self/assisted 确认证据，不创建肯定授权；原 assisted evidence 不在旧备份时也不虚构补建。已有普通操作记录保持原来源，缺少真实主体/操作人时恢复继续拒绝开放。

拒绝包含确认位为 true、入书位为 false 时，投影 true 位还要求旧库已有同主体、绑定、epoch 和版本/hash 的真实肯定确认；没有依据只建立待核实 hold。旧版缺少目标捕获的撤回或核验删除也采用按项目 hold，旧删除已知全项目拒绝仍为永久墓碑，但六层清理继续待核实，不能用当前新任务补造历史范围。

类别到期与永久全项目删除分别建模，导出下载期另按精确包标识记录。业务库中的可空 payload 只允许由匹配 durable item 的单向清空改变，原 FK、版本、hash 和资金事实保留；同一字段因明确重叠类别已经清空后按原 receipt 幂等完成。没有实际副本完成事实的外部层保留 pending。类别重叠的具体合成选择记录在开发说明中，不据此冻结正式 D03。

混合照片临时目录按精确文件归属拆分原图与衍生图，类别到期不误删另一类独立产物。固定 PDF 的只读入口可使用认证冻结 snapshot 延续自身期限，同时保留当前身份、epoch、真实编辑版本及配置变化的失效判断；擦除 live 输入不改变原 PDF hash。activeData 到期后退款及否定权利执行继续仅写最少资金/权利事实，不能重新写私人证据或肯定授权。

独立发布安排在所有可能失败的 PG 准备写入之后、COMMIT 之前。发布前的准备失败完整回滚；发布后 COMMIT 失败或进程退出仍以独立源为拒绝依据，重放恢复投影与原操作的幂等结果，不把已发布拒绝撤回为普通事务失败。

activeData 的原截止同时限制公开写入口。协助用途到期后不新增肯定授权，否定继续只存最少事实；过期的精确故事否决先发布独立事件，再以既有 `journal_denial` 投影和事件 hash 表示来源，不新增肯定的协助版本凭据。保留 true 确认位还要求当前版本/绑定/epoch 已有真实肯定 basis。已核验换绑、资金及履约状态继续按原规则处理，新私人证据省略；旧 raw 仍只由匹配台账的擦除清空。SQL 例外限于已发布 activeData 分类后的精确最少事实，不放松永久 all、旧绑定、授权和原不可变约束。

履约 `tracking` 原先混合物流私人正文与实际发货时间。新增 `FulfillmentAttempt.shippedAt` 保存已经存在的最少实际时间，与 `deliveredAt` 一起保持不可覆写及先后约束；原有 carrier/number/WeChat/回执到期后不再新增。升级只从旧 tracking 中可验证的真实时间回填，缺失或不合法保持 NULL 并显式待核实，不用创建时间、租约或 hash 猜测。交付及重复回执使用独立时间和原稳定 command hash 验证原输入，保留到期后的合法履约和 D07 资金处理能力。质量案的退款判定只处理原案、原窗口和已购政策下的最少资金事实，私有材料访问与新的重印授权仍分别受原期限约束。

运行中已持有项目锁的流检查仍认证完整独立源和业务 checkpoint 的对应连续前缀，并要求当前项目后缀的每项事件存在匹配 source/id/generation/hash 的已提交 receipt（UUID按数据库大小写等价语义规范化比较）；其它项目正常发布/提交间隙不撤销本项目的既有权限。无 scope 的启动/恢复/请求入口继续全量重放，认证、authority、前缀冲突仍全局拒绝。流的实际业务 scope 检查可能等待 PG 锁，因此返回后必须再次验证 source/fence，避免发布后回滚令旧授权多发一块字节。该检查不启动嵌套重放。

active_database 的目标载荷受不可恢复 SQL 约束，已完成的逐项擦除及其完成时间保持单向；旧异步失败不得覆盖数据库当前 completed receipt。active_files/cache 的迟到副本与 SET 则必须继续重扫，失败仍可回到 pending。核验可以在一次 inline reconcile 的单项失败后返回201，含义是拒绝和待执行项已持久，不等于物理清理已完成。
