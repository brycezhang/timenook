# 正式 Vue 网页规格草案

状态：本地审阅草案。用户要求暂不发布执行票；网页首版支付宝 Page/WAP 已确定，由 TimeNook 后端调用现有 payment-service，暂不接支付宝系统退款、不修改共享服务。Vue、手机号统一账号与排除演示代码决定见 ADR 0019。

## Problem Statement

已审阅的新网页设计只有独立 Vue 原型。现有产品网页仍通过小程序页面运行器渲染，使用旧内测登录/项目规则，未与现行项目成员、自动上传和直接印刷规则对齐；正式网页缺少手机号验证码登录与可用的网页购买路径。小程序虽然保存手机号，账号仍按微信身份创建，不能保证同号网页用户与小程序用户共享同一账号和项目。

## Solution

在现有产品网页入口交付移动优先的 Vue 正式应用，按最新设计提供公开首页/样书、验证码登录、项目、录音/照片、故事、真实书稿/PDF、印刷与制作进度。网页和小程序使用同一已验证手机号解析同一 TimeNook 产品账号，复用已有后端业务与权益。

「状态预览」及原型场景切换完全留在设计资料中，正式应用只展示真实会话、权限、业务列表与任务结果。登录不自动创建订单或项目；公共样书与私人内容分开。网页首版使用支付宝 Page/WAP，沿用 deed 的后端调用模式；小程序继续原生微信支付。

## User Stories

1. 作为访客，我希望在手机或电脑阅读产品介绍、套餐和完整条款，从而决定是否开始记录。
2. 作为访客，我希望无需登录即可翻阅明确标注的样书，从而了解故事成书效果。
3. 作为访客，我希望访问私人项目之前才被要求登录，从而能先了解产品。
4. 作为网页用户，我希望通过手机验证码登录，从而无需领取内测登录链接。
5. 作为网页用户，我希望明确同意当前条款，并能取消登录，从而自主决定是否继续。
6. 作为网页用户，我希望知道验证码发送失败、重发等待、过期或输错，从而能正确重试。
7. 作为已有小程序用户，我希望使用同一手机号网页登录后看到相同项目和昵称，从而继续记录。
8. 作为先使用网页的用户，我希望之后在小程序授权同一手机号直接回到同一账号，从而不用再手动配对。
9. 作为用户，我希望两端同时首次登录仍只产生一个账号，从而不会分散项目和权益。
10. 作为尚无项目的用户，我希望看到明确的空态和开始入口，从而知道下一步怎么做。
11. 作为项目成员，我希望选择和切换所有有权访问的项目，从而继续购买或受邀参与的故事书。
12. 作为项目成员，我希望项目名称在首页、列表和详情一致，从而能辨认长名称或改名后的项目。
13. 作为用户，我希望修改昵称并在两端继续使用，从而保留自己的称呼。
14. 作为购买者，我希望登录后回到购买确认，从而不会因为登录就被下单或扣款。
15. 作为网页购买者，我希望通过电脑支付宝 Page 或手机 WAP 完成支付，从而在两端获得同一个新项目。
16. 作为网页购买者，我希望取消或遇到未知支付结果时能查询原订单，从而不重复付款或重复创建项目。
17. 作为项目成员，我希望网页邀请链接在网页登录并接受、小程序分享在小程序登录并接受，从而共同记录同一本书；从微信聊天打开网页链接也不强制跳转小程序。
18. 作为项目成员，我希望浏览、搜索和筛选真实故事，从而找到想补充的片段。
19. 作为项目成员，我希望编辑故事并选择是否入书，从而整理当前书稿。
20. 作为项目成员，我希望内容被其他成员修改后收到版本冲突提示，从而不覆盖对方的修改。
21. 作为项目成员，我希望从题目、自定义话题或照片开始讲述，从而更容易开口。
22. 作为项目成员，我希望录音可暂停、继续和结束，并回听原声，从而保留真实讲述。
23. 作为项目成员，我希望录音结束自动上传，失败能重试或恢复，从而不用理解内部封存阶段。
24. 作为项目成员，我希望整理中的内容保留在页面并显示真实进度，从而知道可以离开后再回来。
25. 作为项目成员，我希望上传照片、填写说明并在相应故事中查看，从而让回忆更完整。
26. 作为项目成员，我希望编辑封面照片、寄语和目录，从而制作自己的故事书。
27. 作为项目成员，我希望生成、阅读并下载有权访问的真实 PDF，从而确认和保存当前成书效果。
28. 作为项目成员，我希望修改内容后生成新的书稿版本，从而不覆盖已经提交的文件。
29. 作为项目成员，我希望从书稿或书中入口听到对应版本的原声，从而保留声音与故事的联系。
30. 作为项目成员，我希望书稿就绪后再填写地址并提交印刷，从而不提前填写配送信息。
31. 作为项目成员，我希望看到真实生产、发货和物流状态，从而了解制作进展。
32. 作为用户，我希望退出、换号或失权后旧私人内容与媒体被清理，从而避免混入其他账号的资料。
33. 作为手机用户，我希望关键按钮、阅读与录音操作适配窄屏，从而能用真实手机完成整条路径。

## Implementation Decisions

- Vue 3、TypeScript、Vite、Vue Router，采用 shadcn 式基础组件和已定品牌 token；独立网页视图，复用现有后端、契约与浏览器媒体能力。
- 规范化的已验证手机号具有唯一账号归属；短信证明与微信服务端手机号证明进入同一账号解析事务。账号 UUID 继续持有成员、项目和权益；微信身份关联至该账号。
- 支持网页先登录、小程序先登录及并发首次登录，均不得新建第二个账号。当前昵称优先保留，新号默认昵称沿用现有规则。
- 手机号只在 TimeNook 产品账号内联通，不把 deed/wutong 用户或 token 直接转换成本项目身份，也不改飞书管理后台登录。
- 网页首版按中国大陆 +86 短信规划。发送验证码不创建账号或订单；验证码有有限时效、重发等待、次数和发送来源限制，成功验证只可消费一次。
- 参考 deed 的 NestJS 阿里云 sender 接入方式，在 TimeNook 内管理验证码与用途；供应商配置和真实投递单独验收。现有共享 auth-service 不具备可直接使用的通用手机号证明契约。
- 网页继续使用现有 Secure/HttpOnly Cookie、同源、CSRF、会话重验及退出机制；小程序保留 Bearer 会话，网页退出不替代小程序会话撤销。
- 旧内测链接、mock 登录/购买和二维码账号配对不作为新正式登录流程保留；开发阶段不建设旧账号迁移或兼容层，实际数据处置单独确认。
- 项目列表和受保护操作以当前项目成员规则为准，不复用旧网页“创建人/讲述者”列表判断。
- 邀请遵循入口所在端：网页链接在网页完成手机号验证码登录及接受，小程序分享在小程序完成手机号授权及接受；微信内打开网页链接仍留在网页。登录后返回原邀请，两端关联同一账号和项目，不新增手动微信绑定；收到链接或仅登录不自动加入。
- 新购复用现有订单与首本权益，按支付宝渠道接入支付确认、查单和关单；按首版不接系统退款、不修改 payment-service 的约束实施，已有微信退款按原规则。订单归属当前产品账号，付款人身份不改变项目归属。服务端固定金额、币种、业务关联和唯一交易校验继续有效。
- 支付浏览器回跳只触发服务端核验，不能据此前端事件创建项目。真实商品和验收实收由服务端决定；现有微信临时 1 分配置不自动适用于支付宝。
- 可靠录音保存、上传恢复、原件摘要、私有下载与任务处理复用既有能力；用户只操作录音与自动上传结果，不增加内部技术阶段。
- 书稿继续版本化，封面照片/章节/故事变化后重新生成；采用真实 PDF 和当前权限读取原声。地址与确定书稿版本在提交印刷时校验，不恢复双方确认门槛。
- 状态预览、查询参数伪造账号、示例个人项目、假登录、模拟支付和延时器生成假书稿均不进入正式源码、依赖图或发布包；公开样书独立标注为公共示例。

## Testing Decisions

- 优先使用现有公开 HTTP、真实 PostgreSQL/Redis、Cookie/CSRF 与浏览器媒体测试边界，检查用户可观察的行为，不围绕组件私有状态写形式化测试。
- 定向验证网页先登录/小程序先登录/并发首次登录，同手机号仅有一个账号，并在两端返回同一昵称、成员与项目。
- 验证验证码实际发送适配器、消费一次性证明、过期、错误、重发限流和供应商拒绝。供应商网络可在隔离测试替换，不给正式应用添加假短信开关。
- 验证取消登录、恢复原入口、无项目、跨标签页换号、退出与迟到响应不会恢复旧私人内容。
- 按项目成员、故事版本、上传恢复、照片与原声私有访问、书稿固定版本及首本权益补受影响的行为回归。
- 支付通过公开订单/确认/查询边界验证金额、归属、幂等、未知结果和关单；真实数据库/Redis 验证并发唯一性。支付宝首版不接退款 API，不能误入微信退款链路；已有微信退款按受影响范围验证。
- 新增本轮 Vue 路径的定向浏览器检查，覆盖移动/桌面及 320px 窄屏、生产构建与深链。遵守现有必要 CI，不恢复退役旧产品浏览器套件或额外增加合并流程。
- 实际短信到达、同号双端真实登录、手机麦克风、iOS/Android、选定渠道实际付款、真实 OSS/ASR/PDF 与实物分别记录；支付宝退款不列入首版，不用合成输入或截图代替真实验收。
- 类型检查、构建和相关检查通过后停止本项验证；仅对新变更、实际失败或明确缺口追加检查。

## Out of Scope

- 首版支付宝系统退款，以及修改或移植 payment-service；既有微信退款与售后规则不由本轮改写。

- 修改营销官网、飞书管理后台登录或重做小程序视图。
- 把「状态预览」及其他原型演示控制写入产品源码或发布包。
- 国际短信、自助手机号换绑、跨账号项目/资金合并以及 deed/wutong 账号迁移。
- 新增通用跨端 UI/会话框架、恢复旧开发版本兼容、旧资料迁移或备份工程。
- 新的退款/资料/售后菜单、本人/双方确认门槛、服务期限及独立运维增强项目。

- [支付宝调研](../../research/2026-11-08-web-alipay-reuse.md)：按用户后续约束，首版不接系统退款、不修改 payment-service。现有创建、prepare、账本查询及关单可用，逐单覆盖回跳地址，通知仍进入共享服务；仅开发 TimeNook 后端和 Vue，粗估 2–4 工程日，前提是账号/Vue 基础就绪且现有支付宝应用适用。商户、通知/对账调度及真实资金另验，退款改造后续另排；微信内浏览器不承诺直接支付。
- 网页首版支付宝 Page/WAP 已确定；小程序保留原生微信支付，不在本轮新增网页 Native/H5/公众号 JSAPI 或支付订单跨端交接。商户与真实资金验收仍独立，用户仍要求保留草案、不发布执行票。
- 子票按可演示的完整业务路径拆分，使用原生父子和 blocked-by；用户已明确本轮仅保留计划草案，不发布 GitHub 规格或执行子票；后续拆分待新指令执行，不重新开启已退出当前队列的旧网页票。
