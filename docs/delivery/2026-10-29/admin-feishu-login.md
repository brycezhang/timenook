# 后台飞书登录与账号简化

2026-10-29，Refs [#81](https://github.com/brycezhang/timenook/issues/81)。用户确认不需要 MFA，后台在控制访问的前提下尽量简化。采用 [ADR 0016](../../adr/0016-feishu-admin-login.md)，登录页面只提供飞书登录；本页区分既定方案、工程证据和实际运行结果。

## 公开行为与范围

- 运营点击飞书登录，经飞书授权回到 `/admin/`，不再输入时光里密码或动态验证码。不提供密码、MFA、自动注册、通用账号审批或组织同步功能。
- 管理员仍与小程序用户隔离。受控 CLI 将所配置应用内的飞书身份、企业及权限加入白名单；只绑定实际批准的人，不因同企业或授权成功自动授予后台权限。支持零业务权限账号，页面和 API 继续按显式权限受限。
- `GET /api/v1/admin/session` 返回会话和当前登录可用状态；`POST /api/v1/admin/feishu/login` 要求当前匿名会话、Origin 和 CSRF，返回授权跳转 URL；`GET /api/v1/admin/feishu/callback` 核验授权后只跳转固定后台入口。回调失败显示固定安全提示，地址、审计和响应不泄露授权码、令牌或原始供应商错误。
- OAuth state 必须短期、浏览器绑定且只消费一次。采用最新 v3 文档的保密客户端授权码模式，由服务端 App Secret、授权码及固定 HTTPS 回调交换令牌；授权与 token 请求都不使用 PKCE 参数，不保留旧端点或自动回退。只有明确的回调入口接收跨站顶层 GET，不能放宽其他管理请求。主会话 Secure/HttpOnly、host-only、SameSite=Strict；独立短期回调 Cookie 使用 SameSite=Lax。Nginx 对准确回调路径关闭含请求行的日志并设置 no-referrer，应用审计保留固定结果。会话和成功审计同事务，提交后签发 Cookie。
- 保留有限会话期限、无静默续期、来源/CSRF 校验、限流、禁用与权限重验、退出撤销。Redis、身份供应商或成功审计不可用时不授予权限。应用密钥只在服务端；开发缺少飞书配置时明确不可登录，生产或部分配置错误拒绝启动。
- 仅在 `environment=test` 的构造入口允许替换飞书外部 HTTP 边界；正式运行没有模拟登录、可任意替换身份源的环境开关或默认管理员。
- 开发阶段直接调整现行文档、契约和模型，删除旧密码/MFA 入口、运行时代码和依赖。历史恢复测试在开发依赖中单独固定其历史版本所需的 `otplib`，不接入新版登录。历史证据保持其原有日期和适用范围，不把当时的结果追认为新方案通过。
- 已有或恢复出的旧管理员仅保留为停用的历史经办主体，不推断飞书绑定、不沿用旧会话。生产、售后及审计引用保留；新登录必须通过当前受控 CLI 单独批准完整飞书身份。数据库拒绝启用缺少完整绑定的账号。
