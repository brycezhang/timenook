## 核心判断

品牌视觉已可辨认，主要问题是正式功能不断叠加后，任务、恢复、授权、校对等操作占用了主要阅读与讲述区域。两端业务步骤相同，呈现层已有分叉：网页在 `preview/main.ts` 对 live 页面另行渲染；小程序仍有原生 live WXML 的多按钮布局。应建立共享的页面状态与文案约定，分别实现平台呈现。

1. 项目首页显示一个主要行动、最近未完成讲述、待本人确认和故事列表。历史任务进入“保存与处理详情”，故障必须留下可见的入口。
2. 讲述仍按选题 → 准备／录制 → 回听 → 保存／处理 → 核对故事推进；每一步保留一项突出操作。照片、自由讲述、自拟问题保留，追问由用户主动请求且可跳过。
3. 故事阅读优先，原声、正式转录和来源可展开。确认区只保留「确认」按钮，不再使用复选框或说明输入。按当前入书用途保存本版决定，并在按钮上方说明是否入书；未获入书同意时只确认内容。发起人没有本人决定按钮，同机协助走当次核验。
4. 书稿明确版本，变化后提示生成新版；不让在线改稿悄悄替换确定 PDF。双方确认同一版本后，由发起人确认地址。内测生产关闭。
5. 官网保留 999 元套餐和样书，内测入口写明用途；“登录和支付为模拟体验”需按真实账号装配重写，不能把受控登录、演示购买及正式销售混成一个入口。

## 第二轮反馈与代码对齐（2026-10-30）

用户要求只保留「确认」按钮、拉开选题操作布局，并据当前代码核实保存／文字处理展示。已在当前原型更新；首版存档为 `index-v1.html`、`app-v1.js`、`style-v1.css`。本次仍只修改提案与文档，不修改业务前端或接口。

### 确认与选题

- 故事确认区删除两组复选框和独立说明输入，只保留「确认」。已确认时显示不可重复点击的「已确认」；修改故事后恢复「确认」。
- 「确认」记录当前故事版本的内容决定；当前已明确同意入书用途时，按钮前明示“确认后，这版故事将用于人生书”，同一次操作记录本版入书许可。未同意入书用途时明示暂不入书，不自动扩大权限。调整用途与撤回仍在既有资料服务入口，发起人仍不能冒充本人确认。
- 当前正式前端 `miniprogram/pages/story/index.ts` 的 `decideLive()` 仍要求分别选择并手填 3–160 字说明，正式接口 `StoryDecisionDto` 仍要求 `confirmed`、`allowInBook`、确定版本／内容 hash、`noticeVersion`、`evidenceRef`。后续实现单按钮时，要从实际点击事件生成可追溯的操作记录并传递字段，不能用假“本人手写声明”填充证据。本轮不把新 UI 追认为现有代码已支持。
- 选题卡使用纵向操作区：主按钮占整行；“换一个问题”独立居中一行，两行至少 12px 间隔、次操作命中区至少 48px。只改选题卡，不影响其他文字链接布局。

- 上传成功并不等于可靠保存；`seal-error` 展示“保存结果待确认”，重查同一片段，保留本机文件。
- `succeeded` 才展示“文字已转写”和整理入口；多片段时须全部选定片段成功，仍遵守现有整理门槛。
- `failed` 仅在 `retryable=true` 时显示重试转写；否则转服务入口。原型“转写失败，可重试”是明确的可重试样例。
- `no_speech` 引导回听／补录；`manual_review` 引导服务；`invalidated` 要求核对权限；`AI_AUTHORIZATION_REQUIRED` 优先显示待本人 AI 用途选择。
- 如果封存接口 `storage` 返回测试环境，本机／测试环境文案必须相应调整，不能一概写云端。原型使用受控已封存样例，不代表真实供应商或设备验收。

实施清单 U01／U02 消费以上状态映射，U03 消费单按钮确认的新交互与操作证据适配。

## 第三轮反馈：简化开始确认页（2026-10-30）

按用户最新要求，资料用途入口不再逐项选择，也不采用四组默认勾选控件。页面用“准备好了，就慢慢说”、一句说明和「确认并开始」完成开始前确认；说明为“录音会保存并由 AI 整理成故事，和小许一起核对，确认后收入书中”。详细用途放入默认折叠的“了解资料如何使用”。这项决定替代前文资料用途页逐项选择的旧 UI 方案。

- 打开页面不改变任何用途状态；点击「确认并开始」时，一次记录录音保存、AI 处理、向当前发起人共享、确认故事后用于成书四项用途同意，然后直接进入录音准备。
- 讲述者可以直接确认；发起人仍使用本人在场的协助入口，认识讲述者不自动成为其本人。本轮未改变正式身份和同机协助证据模型。
- 既有资料服务中的用途调整、撤回和删除入口保留；故事编辑后的版本确认、双方书稿确认继续适用。
- 正式实现需记录点击对应的当前账号、讲述者、告知版本、用途集合及实际操作证据；不把“认识发起人”记录成既有授权事实。本轮仅更新可点击原型与实施说明，尚未改正式接口、业务代码或部署。
- 第二轮原型存档为 `index-v2.html`、`app-v2.js`、`style-v2.css`，当前入口仍为 `index.html`。

## 实施时的最新反馈（2026-10-30）

用户对“入书用途记录”批注明确“不需要这个用途说明”。不新增独立入书用途记录、选择或说明；用途开始只一次记录既有采集、AI、共享三项。开始说明收为“录音会保存并由 AI 整理成故事，和发起人一起核对”。故事确认区只有「确认」按钮，沿用确定故事版本的确认与入书决定，不再放置单独入书用途提示段。该决定覆盖第二、三轮相关的四项用途及单独入书说明描述。

正式实施基线消费线上实际已发布的 `dd2f197`（#117/#118/#119 代码链），保留持续内测登录、共源 WXML、原声暂停和时间轴。工程票据为 [#120](https://github.com/brycezhang/timenook/issues/120) 及子票 #121–#124；运行与平台结果在本次发布记录中分别记载。
