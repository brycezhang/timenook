## 已修复

- 模拟购买后邀请页空白：原构建保留了指向 `miniprogramRoot` 外部 `packages/contracts/src` 的运行时引用，上传包内缺少该模块，邀请页无法注册。现在将包外依赖打入消费者，包内服务继续共享 CommonJS 模块，保留会话和录音实例。
- 从首页选择爸爸却创建妈妈项目：原生 `onLoad` 收到编码的中文，浏览器桥接已解码。套餐页现在识别两端参数，封面和后续项目保持所选对象。
- 底部 Tab 切换整页重建：项目、成书、我的原来全部调用 `reLaunch`。现在在 `app.json` 注册三个原生 Tab，使用统一自定义底栏与 `switchTab`，同一 Tab 点击不重新进入，往返保留 Page 实例和筛选状态。进入 Tab 的其他入口同步调整；live 项目使用当前会话的既有项目选择传递，无 URL 参数。缓存页重新出现时同步当前项目，跨项目不沿用旧协助会话；原有失权、过期与离页清理规则保留。
- 网页桥接同步保留 Tab 页面实例和滚动位置，明确的新项目参数继续进入对应项目；退出应用时清理缓存页。

## 完整原生模拟体验 E2E

命令：先 `TIMENOOK_API_BASE_URL=https://timenookapi.threeminreading.com/api/v1 pnpm build:frontend`，再 `pnpm test:native-e2e`。要求 Mac 官方微信开发者工具已登录并允许 CLI。

脚本复制已构建的小程序到全新临时项目，通过官方 `miniprogram-automator` 操作公开 Page/组件事件和原生路由，截图核对实际渲染；弹窗确认使用测试替身。录音管理器在测试副本加载前替换为合成静音输入，通过本机 HTTP 下载获得原生临时文件，后续使用真实 FileSystem 保存及项目持久化；测试副本单独允许本机下载，没有改动或上传生产包的录音实现/域名校验配置。没有复用或清除用户项目，反复运行不受上次地址、订单或确认影响。每次使用独立自动化端口，等待端口和基础库就绪后连接 SDK，结束时关闭本次测试窗口。

同一次运行全部通过：

1. 妈妈模拟购买 → 项目建立与邀请。
2. 参与确认 → 讲述准备 → 换题 → 合成 MP3 录音输入 → 原生临时文件保存为本机原声 → 回听提交页。
3. **同一购买项目**进入明确标注的示例故事 → 故事确认 → 完整书稿两项确认 → 首本页面 → 空地址阻断 → 合成地址 → 本机模拟订单；项目 ID 全程一致，录音索引仍保留。
4. 另外打开明确标注的示例项目 → 三个 Tab 往返与同 Tab 点击，Page 实例和待确认筛选保留。
5. 故事确认 → 修改标题 → 原确认失效 → 再次确认。
6. 再送一本 → 爸爸套餐/封面/项目一致 → 我的项目仍保留前两个人生项目。

实际环境为微信开发者工具 Stable 2.01.2510290，基础库 3.17.6。最终通过证据在操作者本机临时目录 `/var/folders/7t/xgv_t04j7k74jfdhdh1p41tr0000gn/T/timenook-native-e2e-olDpz0/evidence/`。截图、测试项目和机器结果不进入 Git；可重复执行上述命令生成新的结果。

前一轮未完成的运行（复用示例地址造成空地址断言不适用）已由本轮独立临时项目完整运行替代。SDK 运行时替身无法替换已捕获的 RecorderManager，因此仅在测试副本的工厂边界注入合成输入；本地持久文件不能充当录音临时文件的问题通过真实下载产生临时文件解决。开发者工具的一次模拟器无响应由停止并重新编译测试模拟器恢复后，本轮全部步骤通过。E2E 覆盖当前体验包的本机演示闭环；合成录音不调用真实麦克风，故事是界面明确标注的示例，不代表真人录音、真实 ASR/AI、微信登录、资金、真机中断或实物验收。
