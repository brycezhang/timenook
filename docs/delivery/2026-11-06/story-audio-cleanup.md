# 故事查看与原声回听被失效临时文件缓存阻断

2026-11-06 用户报告：支付创建项目后，故事页显示「原声临时文件尚未清理，请重试」；随后同一篇故事整理完成，37 秒原声点击播放仍显示同一提示。

## 原因与修复

故事页进入与开始回听均先调用 `clearStoryAudio()`。旧实现仅在 `error.errCode === 1300002` 时认可文件已经不存在；微信实际可以仅返回 `errMsg`，也有通用 `errno` 字段。缓存路径失效后被误判为清理失败，引用一直保留，后续重复进入或播放继续失败。进入页的异常分支还直接返回，使录音/故事查询与自动整理受到回听缓存影响。

官方开发者工具对一个明确不存在的本项目诊断路径，实际返回 `errMsg: "unlink:fail no such file or directory …"`，没有 `errCode`/`errno`。把此真实错误形状用于故事页面回归，修复前复现截图中的提示且故事请求数为 0。另复现通用 `errno` 报告的同类问题。未直接抓取用户 iPhone 的原始文件系统错误，因此不把开发者工具结果写成手机底层错误实录。

- 按 `errno`、`errCode` 和明确的文件不存在消息识别已失效文件，清除对应回听缓存引用。
- 真正的删除/权限失败仍保留待清理引用并阻止新回听；故事页继续按当前会话权限查询，清理错误仅显示在原声区域。
- 仅处理原有回听缓存；录音上传清单、原始录音、会话、订单与服务端内容未修改。下载鉴权、字节数和 SHA-256 核验继续执行。

微信参考：[unlink](https://developers.weixin.qq.com/miniprogram/dev/api/file/FileSystemManager.unlink.html)、[通用错误码](https://developers.weixin.qq.com/miniprogram/dev/framework/usability/PublicErrno.html)。
