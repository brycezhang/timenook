# B04 订单退款与质量售后工程记录

范围：[#154](https://github.com/brycezhang/timenook/issues/154)，消费 #151 订单/Vben、#152 用户服务、#153 人工生产及 #105 长期服务。本文记录本地工程，未部署，未新增真实资金或印厂/实物操作。

订单待处理筛选继续使用实际退款/质量申请关联。从订单详情的已有申请选择处理，当前共享 `caseId` 保存在 `/admin/orders/:PaymentOrderId?case=:caseId`；列表查询保存在 `from`。退款与质量组件按申请编号挂载，切换、离开或退出时卸载并清理临时资料；私人 PDF/证据仍按本人当下限时授权取得。生产单使用 `FirstCopyOrder.id`，往返保持原订单、原查询和同一申请。

退款复用既有批准、拒绝、原生产核验、执行和向微信查单；原金额来自购买政策与实际付款，标价、实收和成功退款分列，受控 1 分标记保留。批准/拒绝/原生产核验/实际执行使用标准确认弹层。未知资金仍保留预留及原退款单号，重试先查原单；没有手工金额或成功状态输入。原生产未知接单和取消仍须在生产详情核实，完成印制与发货继续消费 #153 独立事实。退款不删除资料，也不改写原付款事实。

质量复用领取、原政策核验、限时原 PDF/证据及原单新增制作尝试；原文件重印和改稿重新确认分别执行，重印还需 `fulfillment:write`。方案核验与创建重印使用确认弹层。受保护的内部 books profile 现在装配相同 QualityCare 控制器/服务，继续要求显式 internal acceptance；未无条件开放其他能力。核验证据接受 `internal:` 和隔离合成 `synthetic:`；本人授权告知版本由当前原单/服务端返回，小程序不再写死合成告知。缺少原 D06 处理责任/时限或 D07 救济政策时明确不可领取或批准，不补造商业政策、身份核验规则或实物资格；候选 PDF、受控 `physicalProduction:false` 和当前生产条件仍独立执行。

退款及质量 HTTP 入口在成功取得客服权限后查到原 PaymentOrder，再把 `adminResourceType=order`、`adminResourceId=PaymentOrder.id` 交给既有管理命令。订单详情历史因此显示本单售后动作、操作人、结果和时间；动作与结果使用可读标签。未增加独立售后菜单、代客新申请、人工开单/改价/标记付款或通用售后平台。

## 本地验证

- TDD tracer：真实 PostgreSQL/Redis HTTP 的内部核验证据与本单历史用例先因 400 失败，再以 201 和正确订单历史通过。
- 定向退款/质量公开 HTTP 回归 33/33：含原窗口/人工时限、退款金额预留、并发与重启、未知接单/取消、原单重印不增权益、修订重新确认、本人专属授权与撤回。
- 公开内部 books 装配 HTTP 1/1：质量路由实际注册，匿名管理访问 401，合法内部产品会话不存在的原单/质量授权返回 404，内部告知版本通过输入校验。
- HTTPS 后台浏览器 6/6 分批通过：订单待处理发现、退款批准/执行/查单、未知结果重复操作不二次提交、拒绝未执行申请、1 分金额与标记、质量原单重印/生产往返、修订及质量退款组合、专属协助授权和切换申请清理。实际 HTTP、PostgreSQL/Redis、Secure Cookie/CSRF，只有外部供应商协议使用隔离替身。
- 既有质量组件/质量用户页/退款用户页定向测试 16/16；contracts/API test TypeScript、Admin 类型检查和构建、前端类型检查通过。
- 已合入本地 integration `04f5423`（#152 用户服务、#153 最终履约及网页打包跟进）。桌面/390px 与限时 PDF 截图已检查，无页面横向溢出；列表宽表在表内滚动。

浏览器中的 1 分订单是随机隔离 schema 的合成显示夹具，不是新真实资金证据。本轮既有真实 1 分支付/退款只按[原运行记录](../fixed-package-runtime.md)复用，未追认普通售卖、质量赔付、其他订单或设备。真实飞书与权限分配、公开部署及迁移、完整组合 CI、真实质量政策、原单重印印厂/实物、双端设备继续由对应运行验收留证。
