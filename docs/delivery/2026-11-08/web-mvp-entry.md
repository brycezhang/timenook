# Vue 网页公开入口与同号短信登录

范围为 WV01–WV02：公开首页/样书/条款 → 手机号验证码 → 真实项目列表，与小程序同号账号统一。后续故事、录音、邀请页面、书稿、支付及印刷仍按原计划实施；没有发布执行票或部署。

## 当前能力

- 用独立 Vue 3 视图替换旧产品网页运行器，手机底栏与电脑侧栏沿用已审阅设计和小程序 token。公开样书为明确标注的独立示例，私人项目只从成员接口读取。
- `POST /api/v1/web/sms-codes` 接收手机号与当前条款版本，返回挑战 ID、有效期和重发等待，不创建账号或订单，不返回验证码。
- `POST /api/v1/web/session` 校验挑战 ID、六位码及条款，成功后签发 Secure/HttpOnly/SameSite Cookie。恢复与退出沿用现有 Cookie/CSRF 边界，恢复请求不重写 Cookie，避免迟到响应覆盖另一端正在更换的会话。
- 阿里云 SDK 发送真实模板短信，HTTP 成功但业务拒绝仍按失败处理；错误不包含手机号、验证码或 SDK 原始详情。未配置发送能力时返回失败，不提供假短信或假登录。
- Redis 原子处理 5 分钟有效期、60 秒重发等待、单次消费、最多 5 次输错及手机号/IP 发送限额；持久记录保存验证码 HMAC，发送失败不留下可登录挑战。
- 网页短信证明与微信服务端手机号证明进入同一个账号解析事务。手机号规范化后唯一，首次并发登录收敛为同一 User；保留昵称，微信身份已归属冲突时拒绝，不搬移账号或项目。
- 网页读取现行 `/participations` 成员列表，展示本人购买及受邀项目；退出、换号、失效或跨标签页退出时清除页面项目，迟到请求不能重新填回。
- 条款更新为 `shiguang-story-2026-11-08`，网页与小程序说明短信/微信手机号验证及双端项目邀请。

## 开发阶段直接更新

新增手机号规范化及唯一索引迁移，不自动合并重复手机号用户；只在隔离测试 schema 执行，未对云端用户或项目做清理。公开 HTTP 内测票据登录、模拟登录/购买以及手动微信配对入口已撤下。原模拟购买/配对测试按新规则退役，支付和媒体测试通过受限的内部夹具准备会话；新登录验收经过实际 HTTP 验证码接口。

设计原型仍在 `designs/` 作为资料，产品源码及构建依赖不引用它；`状态预览`、`accountPreview`、`loginOutcome`、演示账户种子、模拟支付、WXML/WXSS 运行器均未进入新网页发布包。

## 验证

已完成：

- 真实 PostgreSQL/Redis 下 38 项相关 API 回归通过，包含网页先登录、小程序先登录、并发首次登录、昵称保留、购买/受邀项目一致、异号隔离、错误码/重发/供应商失败与 Cookie/CSRF 退出。
- 阿里云 SDK 的外部 HTTP 边界验证实际模板、手机号、验证码参数；供应商 HTTP 200 业务拒绝正确失败。未发送真实短信。
- 构建后 HTTPS 浏览器路径通过：公开首页与样书、未勾选协议不发码、真实验证码 HTTP 登录、与小程序同 User/项目、刷新恢复、跨标签页退出、供应商失败不提示已发送，以及 320/390/768/1440px 无横向溢出。
- 全量 API 执行 453 项，其中 452 项直接通过；一项跨用例累计的条款计数断言已改为只核对本场景账号，相关两项定向复测通过。没有再次重跑未受影响的 API 全量。
- Vue 类型检查、API 生产构建、小程序前端类型检查与 29 页 release 构建通过；小程序登录相关 31 项回归通过。
- 规格审查无实质问题；规范审查发现一项退出期间恢复响应迟到的竞态，已在 Cookie 锁内补齐最终失效及失败清理，修复经定向复核。构建后 HTTPS 浏览器追加真实响应延迟验证：跨标签换号后旧响应不会清掉新账号，退出期间的旧恢复响应在退出完成后送达也不能恢复身份。

可复现入口：`apps/api/test/web-account.test.ts`、`apps/api/test/sms-adapter.test.ts`、`pnpm test:web-mvp`；后者仅替换外部短信/微信传输，API、数据库、Redis、Cookie 与页面均真实运行。
